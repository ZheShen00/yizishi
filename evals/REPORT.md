## 结论

带技能 **97.1%**，不带 **74.3%**，**区分度 +22.8 个百分点**。

整条全对率：带技能 90.0%（18/20），不带 42.9%（9/21）。

但这个总的数字意义不大——混合了四种性质完全不同的题。有用的结论在下面按 scope 拆开的那张表里。

## 方法

- **两组**：同一条题跑两次，一次给技能、一次不给；每组一个干净上下文，互不可见
- **技能怎么给**：带技能那组读 `SKILL.md`，按它自己的指示再按需读 `references/`（实验 A 的近似）
- **盲判**：judge 只看得到「A」「B」两份输出，不知道哪份带技能。对照表 `map.json` 存在跑完之后才生成
- **三档判定**：`1` 做到 / `0` 没做到 / `NA` 光看文字判定不了（行为证据）
- 每条题只跑一次，没有重跑到满意

## 失败案例

带技能那组一共失 3 分（外加 1 条 NA）。都贴在这里。

### 题 5 · 带技能反而更差

- **漏了一条**：「提醒还有脚本查不到的：按函数源码查的门禁、只在真实环境里跑的探针」——只提了探针，漏了按函数源码查的门禁。
- **「跑没跑脚本」这条被判 NA**：带技能那组的回答没有声称跑过 `check_copy_anchors.py`，judge 判 NA；**不带技能那组声称「全仓 grep 并逐条复算」，judge 判了通过。**

这条很值得说：同一个行为，诚实不声称的被判「判不了」，声称了的被判「做到」。`NA` 这一档救不了这种不对称——**行为类期望项靠 judge 读文字判定，本来就不可靠**。

### 题 19 · 技能过度套用规则

技能的规则是「⚠️ 只留给不可逆、会丢东西的时候」。带技能那组把它推到了「建议按条件删掉 DANGER 里的 ⚠️」——可那句确实不可逆，⚠️ 该留。不带技能那组反而保住了。

**装技能之后把规则用过头，是这类规则型技能特有的失效模式。**

### 题 13 · 引错了法域

带技能那组拿大陆的网销办法给台湾信贷文案当依据。`references/locale-zh-hant.md` 和行业文件的台港一节都写了「法规换成台港的，不套大陆的」，还是错了。这是真错，不是判分问题。

## 局限

**这份报告不能当正式数字用。** 两条硬伤都违反了 `PROTOCOL.md` 自己定的规矩：

| 偏差 | 违反 | 影响 |
|---|---|---|
| 模型是 `deepseek-flash`，拿不到精确版本号 | 第 2 节 | 别人复现不出同一个模型 |
| judge 与被测**同源** | 第 5 节 | 同源判分系统性偏宽，绝对数值偏高 |
| 注入口径带 harness 框架 | 第 3 节 | 既不是纯净实验 B，也不是钉死的实验 A |
| 每条题只跑一次 | — | 没有方差，单次结果不能排除运气 |
| **没做随机 20% 人工抽检** | 第 5 节 | 只完整核了全部失败项（3 条 0 + 1 条 NA）和几处异常，是按「可疑」挑的，不是随机抽的。所以 judge 在**通过的**那些项上有没有系统性偏宽，这份报告没有证据 |

样本量也小：区分候选只有 7 条题、三十几条期望项。`+30.6pp` 的方向可信，小数点后的数不要当真。

## 能说明什么 / 不能说明什么

**能**：这个技能的区分度集中在「模型不可能自己知道的项目约定」上；行业合规和通用结构两类，裸模型已经做得差不多。

**不能**：不能说「这个技能在真实使用中提升 22.8%」。混合口径、同源判分、单次运行，都不支持这个说法。

## 复现

```bash
# 1. 造夹具仓库（题 5、9、15 要在里面跑）
python evals/fixtures/build_repos.py <目录>

# 2. 逐条跑（需要模型 API）
python evals/run.py --model <模型精确版本>

# 3. 盲判（judge prompt 见 evals/judge_prompt.md）

# 4. 汇总
python evals/tally.py evals/runs/<stamp> --evals evals/evals.json
```

换成不同来源的 judge、钉死被测模型版本，按上面四步重跑，就能得到一份可以对外引用的数字。
