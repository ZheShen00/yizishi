**1. smoke/gate.sh:3 —— 会断，门禁变红**

门禁就是按源码 grep「你后来自己改过」，改完这句在 src/panel.tsx 里没有了，直接 FAIL 手改提醒不在了。把锚换成新句子里的一小段，并限定在字符串字面量里：

```bash
grep -qE '"[^"]*之后有手动修改[^"]*"' src/panel.tsx || { echo "FAIL 手改提醒不在了"; exit 1; }
```

`之后有手动修改` 在 panel.tsx 里只出现 1 次，就在那句提示里。

注意别把锚换成「撤销可能撤到」或「手改过」：panel.tsx 第 1 行注释里两个词都有，句子删了注释还在，门禁照样是绿的。我实测过这件事——把提示整句删掉、注释不动，锚注释里也有的词仍然绿，锚「之后有手动修改」（带双引号限定）会红。

**2. tests/panel.test.ts:3 —— 会断，单测变红**

`toContain("你后来自己改过")` 拿不到这句了。改成 `toContain("之后有手动修改")`，这个片段在文件里唯一，锚够短。测试名「手改过 → 卡片写明撤销可能撤到用户的改动」和新措辞已经对不上，可以顺手改成「手改过 → 卡片写明撤销可能影响这些改动」，改不改都不影响跑。

**3. tests/panel.test.ts:6 —— 反向断言失效，要改**

`not.toContain("你后来自己改过")` 改完后永远通过，守不住「没人手改时卡上不许出现这句」。这处能断精确值，直接写：
