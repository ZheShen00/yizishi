# 同步横幅改文案：门禁和单测都要跟着改，共 3 处

`python scripts/check_copy_anchors.py --base HEAD` 在 e9 上跑出来：

```
BREAK    smoke/gate.sh:3          「关闭页面会中断」
BREAK    tests/banner.test.ts:3   「关闭页面会中断」
VACUOUS  tests/banner.test.ts:6   「仍在同步」
```

2 处会断、1 处会静默失效，都是这次改文案引出来的。不跟着改就提交：门禁和第一条单测红，第二条看着绿、其实已经不测任何东西了。我一行没改，下面逐条给判断和改法。

依据：仓库里没有 `docs/copy-glossary.md`，`detect_industry.py` 也没识别出行业信号，按通用界面规则处理；这句是纯文本横幅，不涉及 markdown。文案本身（14 字 → 10 字）符合规范：单行提示不加句号、只有一个「请」、「同步中」状态在前。

## 1. 门禁：必须改，而且不能照抄「请勿关闭页面」

`smoke/gate.sh:3` 现在是 `grep -qF '关闭页面会中断' src/banner.ts`。新句子没有这几个字，跑起来直接 `FAIL 关页提醒不在了`（我按同样的匹配核过，0 命中）。

```diff
-grep -qF '关闭页面会中断' src/banner.ts || { echo "FAIL 关页提醒不在了"; exit 1; }
+grep -qE '"[^"]*请勿关闭页面[^"]*"' src/banner.ts || { echo "FAIL 关页提醒不在了"; exit 1; }
```

不能写成 `grep -qF '请勿关闭页面'`，因为 `src/banner.ts:1` 的注释里已经有这几个字：

```ts
// 同步横幅：没同步完时提醒「请勿关闭页面」，关了会中断同步
```

裸锚在文件里命中 2 处（注释 + 字符串）。拿一份「句子删掉、注释留着」的文件试过：裸锚命中 1，门禁绿（错）；限定在引号里的锚命中 0，门禁红（对）。旧锚没这个毛病，`关闭页面会中断` 只在字符串里出现，注释里写的是「关了会中断同步」。引号版还有个好处：注释以后怎么改都不影响门禁。整句 `同步中，请勿关闭页面` 现在也只命中第 3 行，但注释哪天更新成整句就又串了，不如引号版稳。

## 2. 正向断言：BREAK，跟着换片段

`tests/banner.test.ts:3` 断言的是旧句子里的「关闭页面会中断」，新文案没有它，这条会失败。

```diff
-  expect(syncBanner(false)).toContain("关闭页面会中断");
+  expect(syncBanner(false)).toContain("请勿关闭页面");
```

测试名是「没同步完 → 提醒别关页面」，锚「请勿关闭页面」意思对得上，够短也唯一。想更紧可以写 `toBe("同步中，请勿关闭页面")`，但整句钉进测试，改一个标点就要动测试，不建议。

## 3. 反向断言：VACUOUS，改成断言精确值

`tests/banner.test.ts:6`：

```diff
-  expect(syncBanner(true)).not.toContain("仍在同步");
+  expect(syncBanner(true)).toBe("");
```

「仍在同步」在新句子里已经不存在，这条现在永远通过。它守的是「同步完，横幅消失」。我把 `syncBanner` 改成同步完也返回横幅试了一下，这条断言还是绿的，等于没测。改成 `toBe("")` 钉住「这时什么都不显示」，以后文案怎么改都不会再失效。只换成 `not.toContain("请勿关闭页面")` 能修好这一次，下次改文案又失效。

## 4. 不用动的

- 两条测试的名字、门禁里的 `FAIL 关页提醒不在了`：意思还对。
- `src/banner.ts:1` 的注释：内容仍然准确。别为了躲开它去改注释，把锚限定在字符串字面量里更稳。
- 换行和编码：三个文件都是 UTF-8 无 BOM、LF，改的时候保持，别整份重存。

## 5. 验证

- 我在仓库的临时副本上按上面 3 处改了一遍，再跑 `check_copy_anchors.py --base HEAD`：输出「0 条锚会断，0 条反向断言会失效」，退出码 0。原仓库没动。
- 门禁：这台机器没有可用的 bash（只有 WSL 桩），`bash smoke/gate.sh` 跑不了。用等效正则核了两种状态：改后命中 1（ok），把句子删掉命中 0（FAIL）。有 bash 的环境提交前跑一次 `bash smoke/gate.sh` 确认。
- 单测：仓库里没有 `package.json`，也没有 jest，跑不了 jest。我用 node 按这两条断言跑了函数逻辑：改前第 1 条失败、第 2 条通过（把函数改坏后仍然通过）；改后两条都通过，把函数改坏第 2 条会红。
