# 界面文案修改方案（4 条）

## 前提：规范原文没随任务给出

任务只说"按规范"，但没附规范正文。我先按国内通用的两层依据改：

- **国标**：GB/T 15834—2011《标点符号用法》、GB/T 15835—2011《出版物上数字用法》
- **界面通行规则**：短语型提示不加句末标点；一条提示只给一个动作；同组选项的句式、单位、连接号必须一致；操作词随端变化（"点击"不用于触屏）

如果你们有自己的文案规范（中英文间是否加空格、连接号用"～"还是"–"、提示语是否统一加句号），发我，我按它再对齐一遍。

---

## 逐条修改

### ① 筛选项：`1万以下 / 1–10万 / 10万以上`

**问题：**

1. **单位不统一**。只有第二项两端不重复单位，"1–10万"很容易读成"1 元到 10 万元"。按 GB/T 15835，数值范围两端都要带单位，应写"1万～10万"。
2. **连接号用错**。原文用的是西文短横（en dash）"–"，中文数值范围按 GB/T 15834 用浪纹线"～"（或按你们设计系统统一的一字线"—"），不能中英混用。
3. **区间重叠、不互斥**。1万既在"1万以下"又在"1–10万"里；10万既在"1–10万"又在"10万以上"里。筛选器必须互斥且穷尽，否则用户点哪一档都可能漏数据。
4. **句式不平行**。三项里两项是"……以下/以上"，中间项是光秃秃的区间，一排看过去不齐。

**改后（主推）：**

```
1万以下
1万～10万
10万以上
```

并在组件说明或文档里定死一条边界规则：**含下限、不含上限** —— 1万归第二档，10万归第三档。

**改后（要求零歧义、不依赖说明时）：**

```
1万以下
1万（含）～10万（不含）
10万及以上
```

这一版啰嗦，只建议在导出报表、财务/法务口径这类必须无歧义的场景用；普通筛选器用主推版加一行说明即可。

---

### ② 保存提示：`保存成功。`

**问题：**

1. **句末句号是多余的**。句号用于陈述句末尾；"保存成功"是短语型轻提示（Toast），按通行界面规范不加句末标点。这也是四条里标点不一致的根源：②③带句号，①④不带。
2. **也别改成"保存成功！"**。感叹号表强烈感情，成功提示属中性反馈，滥用反而削弱语气。
3. **提示语要短、结果导向**：动词 + 结果，不加主语、不加客套。

**改后：**

```
保存成功
```

更省字、更贴合"已发生"语义的写法是 `已保存`。二者取一，全站统一，别两处混用。

---

### ③ 加载失败：`加载失败——请稍后重试，请检查网络，请点击刷新。`

**问题：**

1. **破折号误用**。GB/T 15834 里破折号用于注释、转折、中断或延长；这里只是"结论 + 建议"，用逗号或直接拆行就够了。界面文案基本不需要破折号。
2. **一句话塞了三个指令**：稍后重试、检查网络、点击刷新。三个动作互相打架 ——"稍后重试"是等待，"点击刷新"是立刻操作，用户不知道听哪句。
3. **违反"一条提示一个动作"**。要么让用户重试，要么让用户刷新，别同时要求。
4. **"请点击刷新"把操作说明写进了文案**。按钮本身就是操作，文案里再写"点击"是重复；而且"点击"只适用于鼠标，触屏端得说"轻点"。跨端文案应直接引用按钮名，把动作交给按钮。
5. **句末句号**：同②，短语提示不加。

**改后（推荐：标题 + 一句说明 + 一个按钮）：**

```
加载失败
请检查网络后重试
[刷新]
```

如果只能保留一行文案，二选一，别叠加：

```
加载失败，请检查网络后重试
```

或（原因不在用户侧、不该让他排查网络时）：

```
加载失败，请稍后重试
```

---

### ④ 上传限制：`最多可选3个文件`

**问题：**

1. **动词和实际操作对不上**。上传组件的动作是"选择/上传"，"可选"是站在系统视角说的。用户视角应写"最多可上传3个文件"（或"最多选择3个文件"，看组件按钮叫什么，跟按钮保持一致）。
2. **只给了数量，没给格式和大小**。上传限制通常是三件事：数量、格式、单个大小。只说数量，用户会在选完文件之后才被拦。
3. **数字用法是对的，格式要统一**。GB/T 15835 规定计量用阿拉伯数字，"3"没错；但"3"与"个"之间留不留空格要按设计系统统一，别一处"3个"、一处"3 个"。
4. **短语型说明不加句末句号**（同②）。

**改后：**

```
最多可上传3个文件
```

如果这条提示旁边还有格式/大小要求，合并成一句，别拆成三行小字：

```
最多可上传3个文件，支持 JPG、PNG，单个文件不超过 5MB
```

（格式、大小按实际能力填；没有限制就别写，写了就必须真能拦住。）

## 汇总（可直接替换）

| # | 原文 | 改后 |
|---|---|---|
| ① | 1万以下 / 1–10万 / 10万以上 | 1万以下 / 1万～10万 / 10万以上（含下限、不含上限） |
| ② | 保存成功。 | 保存成功 |
| ③ | 加载失败——请稍后重试，请检查网络，请点击刷新。 | 加载失败 ＋ 请检查网络后重试 ＋ ［刷新］按钮 |

再补一条统管四条的规则，建议直接写进规范：**同类提示的句末标点、数字单位、连接号三项必须全站一致**。现在这四条里，②③带句号、①④不带；①的单位只在中间一项缺失；③把三个动作塞进一句 —— 单看每条都"能懂"，摆在一起就不像一个人写的。

## 需要你定的 3 件事（会直接影响最终措辞）

1. **① 的边界归属**：1万、10万这两个值到底归哪一档？我按"含下限、不含上限"写的（1万进第二档，10万进第三档）。如果业务口径是"含上限"，文案和说明要跟着调。
2. **③ 给"重试"还是"刷新"**：这决定按钮文字，也决定文案里那一句写什么。别两个都留。
3. **④ 除数量外还有没有格式、大小限制**：有就并进去，没有就别写。
