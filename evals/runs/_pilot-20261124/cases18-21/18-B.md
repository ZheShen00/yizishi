# 设置页文案问题清单

## 逐条问题

**1. 剩余空间不足 200 字节**

- 语义双关：「不足」既能读成「少于 200 字节」（描述剩余量），也能读成「不够用、还差 200 字节」（描述缺口），一句话两种读法。
- 量级可疑：200 字节连一条日志都存不下，与「剩余空间」这种通常按 MB/GB 计的指标严重不匹配，疑似单位写错（MB？）或内部阈值/错误码直接漏到了界面上。
- 作用域缺失：是哪个空间的余量（快照、缓存、账户配额、某个挂载点？）没有交代；与第 2 条「快照」的占用关系也没说清，用户无法判断快照是否吃掉了这块空间。
- 只报状态，不给后果和出路：跌破该值会发生什么（停止写入、自动删旧快照、同步中断？）、用户能做什么（清理、扩容、导出？），都没有。
- 阈值写死：200 若是可配置或按套餐变化，硬编码在文案里，阈值一调就失真。
- 位置错配：这是运行期告警语气，不是设置项说明，放在设置页里读起来像系统报错。

**2. 快照保留 7 天**

- 起算点缺失：从创建时算、从最后一次访问算，还是按自然日滚动？三种算法结论完全不同。
- 到期行为缺失：「保留」之后是自动删除、转归档，还是只是不能再恢复？「保留 7 天」不等于「7 天后删除」，用户极易误判。
- 边界未定义：是否含创建当天、跨时区/夏令时怎么计、到期当天是零点还是同一时刻、能否手动延长或锁定。
- 与设置页身份不符：看不出这是固定策略还是可调项；若是固定策略，放在设置页会被当成可改的选项。
- 没有失败/例外说明：容量不足时是提前淘汰还是暂停快照，未提及（与第 1 条直接相关）。

**3. 沙箱环境仅供测试**

- 「仅供测试」是结论不是信息：没说清测试环境的具体限制——数据是否可能被清空、是否保证持久化、有无 SLA、能否与生产互通，用户无法据此评估风险。
- 责任边界含糊：没有明确禁止事项（如禁止存放生产数据、个人信息、密钥），也没有说明数据丢失时的责任归属。
- 术语未落地：「沙箱」与常见的「测试环境」「预发环境」是不是同一层、有何差别，没有定义。
- 缺可操作信息：如何切到正式环境、测试数据能否导出、环境配额多少，都没有。
- 无视觉/语气层级：这是一条风险告知，却与其他说明性短句同权重，容易被扫读跳过。

**4. 引擎版本 v2.3**

- 精度不足：只到次版本号，区分不了 v2.3.1 与 v2.3.7 这类补丁差异；反馈问题、对照日志时这条信息基本不可用。
- 表意重复：「版本」与「v」同一含义出现两次，且中英混排风格与全篇不统一。
- 指代不明：是哪个「引擎」（渲染、计算、同步、推理、规则引擎）？多引擎产品里无法定位。
- 缺状态与出口：是否最新、有无可用更新、更新渠道（稳定版/内测版）、能否手动检查更新，全无。
- 无构建信息：缺 build 号、commit、构建日期，无法与后台日志对账。
- 无兼容性提示：该版本对应的能力/限制（例如旧版本不支持哪些功能）没有说明。

**5. 操作留痕可在后台查看**

- 「留痕」是内部行话，用户通常理解为「操作日志/审计记录」，用词没有翻译成用户语言。
- 「后台」指代不明：管理控制台、运维后台还是第三方系统？入口在哪、要不要额外权限，都没说。
- 主体缺失：谁能看（仅管理员 / 仅本人 / 全体成员）、看谁的记录、能否筛选导出，均未交代；这直接涉及隐私告知是否充分。
- 保留期缺失：记录保存多久、到期是否清除、能否按合规要求导出，没有说明，且与第 2 条的「7 天」口径不统一，用户会以为是同一套保留策略。
- 「可查看」只是能力描述，不是承诺：该功能默认开还是关、能否关闭、关闭后是否仍被记录（尤其涉及员工侧），都未说明。
- 权限与告知不匹配：如果记录包含成员操作且成员本人看不到，文案没有提示这一不对称。

**6. 同步失败后会先回落本地缓存，再补传**

- 术语错位：「回落」是金融/行情用语（价格回落），技术语境表达 fallback 一般说「回退」「降级」「改为读写本地缓存」，此处属用词误用。
- 句子成分残缺：「回落本地缓存」缺少方向或动作（回落到本地缓存？改为读本地缓存？），读者要自己补全。
- 「先…再…」的时序含混：是自动串行执行，还是先给本地兜底、等条件满足才补传？由谁触发也没说。
- 失败判定未定义：什么算失败（断网、超时、服务端 5xx、鉴权失效、版本冲突）、多久判定、重试几次，均缺失。
- 补传触发条件缺失：恢复联网时、下次启动时、还是定时任务？退避策略如何？关机或强退后未补传的数据还在不在？
- 一致性风险未提：本地缓存与远端冲突时以谁为准、补传是否幂等、会不会重复提交或覆盖他人修改、失败多次后是否降级为人工处理。
- 用户侧不可见：失败期间界面有没有「未同步」标识、能否手动重试、缓存会不会过期被清，全无说明；句中的「会」是承诺语气，却没有任何前提条件约束。
- 对象不明：「同步」的是哪些数据、范围多大（全部还是增量）、有无大小上限，均未交代。

## 跨条目共性问题

- **场景错位**：六条里只有第 3、4、5 条勉强属于「环境/版本/隐私」类说明，第 1、2、6 条是带条件分支的运行状态与机制描述。设置页真正需要的是「这一项是什么、当前值/默认值是什么、改动后有什么影响」，六条中没有任何一条给出可调项、默认值或影响范围。
- **句式与语域不统一**：第 1、6 条是完整句，第 2、3、4、5 条是名词短语；同一列表里混着告警、策略、免责声明、版本号、功能说明，读起来不像一套文案体系。
- **未定义术语扎堆**：「后台」「留痕」「回落」「沙箱」「引擎」都是内部词或跨域词，且没有一处给出解释，同页共存会叠加歧义。
- **数字与单位不规范**：数字与中文之间的空格、单位写法（字节 / MB / GB）、版本号「v」前缀，全篇没有统一规则；「200 字节」与「7 天」这类数值也都没标注来源或是否可变。
- **只描述、不兜底**：涉及限制和失败的三条（1、2、6）都没写失败后的用户可见状态与补救路径；涉及合规的一条（5）没写权限范围和保留期。
- **状态层级缺失**：这类页面通常要区分正常 / 警告 / 异常 / 不可用，文案本身没有状态区分，也没考虑颜色之外的表征方式。
- **本地化隐患**：「字节」「天」以及「先…再…」的语序在翻译和复数变化上都会出问题，第 1 条的阈值表述还依赖中文语序才能勉强读懂。
- **缺少时间/时区基准**：第 2 条的「7 天」和第 5 条的「可查看」都涉及时间窗口，但全篇没有一处说明以哪个时区、哪个时间点为准。
