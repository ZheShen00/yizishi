## 问题清单

1. **纯文本面上有 markdown 记号（硬伤，两条）**
   原文：`LOADING = "**正在加载**，请稍候"`、`EMPTY = "**暂无结果**"`（位置：任务里这段文案常量，未给文件路径）
   改法：删掉两组 `**`。纯文本渲染时星号会原样显示，用户看到的是四个星号。

2. **等待文案：`请`用错了地方，也没说等多久**
   原文：`LOADING` 的「，请稍候」
   改法：删「请稍候」，留「正在加载…」。要写时长就写真实值：「正在加载，通常需要 X 秒」，X 和代码里的超时、平均耗时对一遍。

3. **空状态只有现状，没有下一步**
   原文：`EMPTY = "暂无结果"`
   改法：补一句下一步，三种空分开写：筛选没结果 → 「没有找到结果，换个条件试试」；确实没有数据 → 「还没有 X，[填：怎么创建]」；第一次进来别和被清空共用一个句子。

4. **确认框没说要删的是什么**
   原文：`DANGER`「删除后不可恢复，确定要删除吗？」
   改法：把对象名写进后果里：「删除「X」后不可恢复」，名字用调用方手里的显示名，不用路径。一次删多条时写真实条数。

5. **「不可恢复」是替产品下的断言，和 `HINT` 的「随时取消」互相矛盾**
   原文：`DANGER`「删除后不可恢复」+ `HINT`「你可以随时取消」
   改法：先确认到底能不能撤销。能撤销，就写清时限「可在 X 分钟内撤销」，并改成带「撤销」的 toast；确实不能撤销，保留「不可恢复」，删掉「随时可以取消」。

6. **`⚠️` 用在了不丢东西的地方，前面还挂了个引子**
   原文：`HINT = "⚠️ 提示：你可以随时取消"`
   改法：删 `⚠️` 和「提示：」。`⚠️` 只留给不可逆、会丢东西的时候（`DANGER` 那条该留）。

7. **`HINT` 整句可以删**
   原文：同上
   改法：确认框里的「取消」按钮已经说明能取消，这句没有新信息；「随时」还是个没出处的承诺。整句删；要留就写成可核对的事实「取消后不会删除」。
