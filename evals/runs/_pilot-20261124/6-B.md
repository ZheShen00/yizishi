## 文案问题

1. **提示与实现数字对不上**：「最多显示最近 100 条订单。」与实际 `PAGE_SIZE = 50`、只发一次 `limit=50` 请求、没有任何加载更多/分页相矛盾，文案承诺了组件给不出来的 100 条。

2. **「共 N 条」把"已加载数"说成了"总数"**：`orders.length` 只是本次拉到的条数，不是订单总量，标题用「共」等于对全量下断言；被 `limit` 截断时用户会以为这就是全部（50 条时既看不出被截断，也没有"还有更多"的任何提示）。

3. **加载中就已经显示「共 0 条」**：初始 `loading = true` 时 `orders` 为空，标题先断言"共 0 条"，「最多显示最近 100 条订单。」也照常展示，与正在转圈的 Spinner 自相矛盾。

4. **失败态同时出现「加载失败」和「暂无订单」**：请求失败后 `loading` 置 false、`orders` 仍为 `[]`，页面既弹错误 toast 又渲染「暂无订单」，等于把"加载失败"表述成"没有订单"。

5. **错误文案直接拼接原始技术信息**：`加载失败：${r.error}` 会把 `HTTP 500`、`Failed to fetch`、JSON 解析异常原文、以及服务端 `body.error` 的开发者措辞原样抛给用户，中英混杂；`(e as Error).message` 在非 Error 抛出时还可能渲染成"加载失败：undefined"或空消息。

6. **错误文案没有出路**：只说明"失败"，没说影响范围（是全部订单还是部分），也没有重试/刷新的可操作文案；toast 消失后不留任何提示，用户回到的界面看起来就是"没有订单"。

7. **加载态完全没有文案**：只有 `<Spinner />`，没有"正在加载订单…"之类文字，也没有给读屏的加载状态说明（Spinner 无 aria-label / 无 live region），弱网时界面只有计数「共 0 条」。

8. **空态文案过于笼统且无引导**：「暂无订单」不区分"确实没有订单"和"加载失败/无权限/被截断"，也不告诉用户接下来能做什么。

9. **「最近」是没有依据的排序承诺**：请求里没有任何排序参数，组件无法保证拿到的是"最近"的订单，文案却把时间顺序当成事实。

10. **量词不自然**：订单通常按"笔"或"个"计，「100 条订单」「共 N 条」读感生硬；组件内部虽然统一用"条"，但与后台系统里订单的惯用说法不一致。

11. **同级文案格式不统一**：标题「订单 · 共 N 条」用间隔号且无句末标点，提示句末带「。」，错误前缀用全角冒号，三种风格混在一屏；数字也未做千分位/本地化（如 1,000 条）。
