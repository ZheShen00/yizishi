# 结论：会挂——两红两绿，但两个绿都是假绿

改动本身只是文案：`staleNote(true)` 还是返回一句提醒，`staleNote(false)` 还是返回 `""`，行为没变。所以没有要改的产品逻辑，出问题的全是**把旧文案钉死**的检查。

这份仓库里 `git ls-tree HEAD` 只有 4 个文件，`git diff` 确认改动只落在 `src/panel.tsx`。旧句 `你后来自己改过` 被 3 个文件、4 条断言/检查引用（另有一处注释也过期），结果是：

| 位置 | 依赖 | 改文案后 |
|---|---|---|
| `tests/panel.test.ts:3` 正断言 `toContain("你后来自己改过")` | 旧文案 | **红（硬失败）**：`staleNote(true)` 现在返回「（之后有手动修改，撤销可能影响这些修改）」，不含旧句，第一条用例必挂 |
| `smoke/gate.sh:3` `grep -qF '你后来自己改过' src/panel.tsx` | 旧文案 | **红**：exit 1，打印「FAIL 手改提醒不在了」，提交/CI 会被挡 |
| `smoke/probes/panel_e2e.cjs:3` `!cardText.includes('你后来自己改过')` | 旧文案 | **绿（假绿）**：改文案后任何卡片都判 `no_false_manual_warning: true`，这条探针**再也不可能失败** |
| `tests/panel.test.ts:6` 反断言 `not.toContain("你后来自己改过")` | 旧文案 | **绿，但是空过**：改前改后都绿——它只查这一句具体文案，压根没守住用例名里写的"卡片上不许出现那句提醒"（既有薄弱点，不是这次弄红的，但这次让它更没意义） |
| `src/panel.tsx:1` 注释仍写「撤销可能撤到那些改动」 | 旧文案 | 不影响门禁，但过期了 |

最该警惕的是第 3 条探针：它不是变红，是**变瞎**。改完重跑，看到"2 红 → 改完 → 全绿"，很容易以为收工；实际上"没手改的轮次不许出现手改提醒"这条防线从此永真（它开头还有 `!cardText ||` 放过空卡片，本来就不严）。反断言 T2 也一样，本来就只钉那一句，现在更是彻底的恒真。这两处不会给你任何红信号，是这次真正的坑。

# 我实际做了什么、没做什么

- **没跑成真正的 test runner**：仓库里没有 `package.json`、没有 jest/vitest 配置、没有 `node_modules`，测试文件也没 import 测试全局。这台机器有 node，但没有 jest。
- **`smoke/gate.sh` 也没能直接执行**：本机没有 bash + grep（`C:\Windows\system32\bash.exe` 是 WSL 且没装发行版，Git Bash 也没装）。
- 所以我做的是**等价复算，不是"跑过了"**：用 node 从 `src/panel.tsx` 取出三元表达式两个分支的字符串，按四条检查各自的原始谓词逐条算：

```
note(true)  = "（之后有手动修改，撤销可能影响这些修改）"
note(false) = ""
T1 toContain(旧句)     => false  FAIL
T2 not.toContain(旧句) => true   PASS（空过）
GATE grep -qF(旧句)    => false  FAIL 手改提醒不在了 (exit 1)
PROBE 手改卡片          => true
PROBE 不手改卡片        => true   ← 两种情况同结果，探针已失去区分力
```

- 顺带排除了编码这个假原因：文件 UTF-8 无 BOM、CRLF、251 字节，`grep -F` 匹配中文不受影响；`git show HEAD:src/panel.tsx` 里旧句确实在，说明 base 提交里门禁的匹配目标还在（base 上应该是绿的，这点同样是静态判断，没实跑）。
- 也确认本地没装 pre-commit 钩子（`.git/hooks` 只剩 `.sample`），所以本地提交大概率不拦，红会落在手动跑门禁或 CI 那一步。

# 怎么处理

**一、这 4 处必须一起改（3 个文件）。** 只把 gate 的 grep 换掉最省事，但探针会继续保持假绿。

**二、别把新文案再抄四遍。** 这次的问题就是"改一句文案、四处引用全红"；原样再抄一遍，下次改文案照旧全红，探针也继续钉着中文。建议把文案抽成单一事实源，让检查钉语义而不是钉整句：

```tsx
// src/panel.tsx
export const MANUAL_EDIT_NOTE = "（之后有手动修改，撤销可能影响这些修改）";
export function staleNote(manualEdit: boolean): string {
  return manualEdit ? MANUAL_EDIT_NOTE : "";
}
```

```ts
// tests/panel.test.ts
import { staleNote, MANUAL_EDIT_NOTE } from "../src/panel";

test("手改过 → 卡片要说明撤销会影响用户的手动修改", () => {
  const note = staleNote(true);
  expect(note).toBe(MANUAL_EDIT_NOTE);
  expect(note).toContain("撤销");      // 语义核心：撤销风险必须说
  expect(note).toContain("手动修改");
});

test("没人手改 → 卡片上不许出现任何提醒", () => {
  expect(staleNote(false)).toBe("");   // 比 not.toContain(旧句) 强，这才真能守住"不误报"
});
```

```js
// smoke/probes/panel_e2e.cjs —— 按稳定标记判定，不要再按中文文案
// 卡片上加 data-note="manual-edit"（有提醒时才有），探针查属性：
async function check(card) {
  return { no_false_manual_warning: !card.noteKey || card.noteKey !== "manual-edit" };
}
```

如果探针只能拿到纯文本、加不了属性，那至少让它从 `MANUAL_EDIT_NOTE` 那一个常量取值（共享模块或构建时注入），别再在探针里抄第四份中文——抄一份就多一个会烂的地方。

```bash
# smoke/gate.sh —— 门禁守"这个提示还在"，不守"一个字都没变"
grep -qF '撤销' src/panel.tsx || { echo "FAIL 手改提醒的撤销风险说明不在了"; exit 1; }
```

想更硬就让 gate 改成跑测试套件看退出码，语义交给测试，gate 不另存一份文案副本；如果团队确实要求这句文案一字不能变（有文案评审），那就让 gate 指向 `MANUAL_EDIT_NOTE` 的定义处，一处改、处处跟。

**三、退一步的最小方案（如果这轮不想动结构）：** 就把那 4 处字面量换成新文案、顺手改 `panel.tsx:1` 的注释和两条用例标题，同一个提交里一起改。能过，但门禁从此退化成"文案快照"，探针继续钉中文——这次的代价已经证明了这种钉法迟早再痛一次。

**别做的：** 为了让 CI 变绿，只把 gate 那行字面量替换掉、其他不管。那样 gate 绿了、探针仍瞎，等于把唯一能抓"手改提醒误报"的检查关掉了。

# 提交前

```bash
git grep -nF '你后来自己改过'   # 老文案有没有漏在 i18n / 快照 / 其他测试里
git grep -nF '撤销可能撤到'
bash smoke/gate.sh             # 本机没有 bash/grep，需在有 runner 的环境跑
npx jest tests/panel.test.ts   # 假定 runner 是 jest；这个切片里没有 jest 配置，跑不了
```

另外一句产品侧的确认：新文案把「撤销可能撤到你的改动」换成「撤销可能影响这些修改」，从"撤销会回退到你手改之前"弱化成"会影响"，也不再点名"你"。如果这句提示本意是警告"撤销会把手改一起回退掉"，建议跟设计确认语义还准不准；功能上没影响。
