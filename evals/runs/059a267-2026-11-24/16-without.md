# 这次没法「按规范改」，因为规范没给

任务文件里只有四条待改文案，没有给出：

- 要遵循的**规范本身**（名称、版本、条文，或内部文案规范文档/链接）；
- **被审仓库**的路径，以及这四句文案所在的页面/组件、是否走 i18n 词条、是否由服务端下发。

「按规范改」的产出完全取决于规范怎么规定标点、数字、区间写法、提示语结构，而这些细则各家并不一致，甚至互相冲突（比如「短提示不加句末句号」是常见内部规范，但 GB/T 15834 并没有这一条）。规范缺位时直接甩一版「改好的文案」，等于我自己编一套规范再声称符合它——你没法验证，也没法合并。

所以下面分两块：**A. 不依赖具体规范也成立的客观问题**（自相矛盾、可读错、功能缺陷）；**B. 必须由规范拍板的取舍**（我列选项，给规范后定稿）。

---

## A. 四条文案的客观问题

### ① 筛选项：1万以下 / 1–10万 / 10万以上

1. **区间边界重叠，用户判断不了 1万 和 10万 落在哪一档。** 汉语「以上/以下」含本数（《民法典》第一千二百五十九条：「以上、以下、以内」包括本数，「不满、超过、以外」不包括）。于是 1万 同时属于「1万以下」和「1–10万」，10万 同时属于「1–10万」和「10万以上」。这不是文案风格问题：如果后端用同一套边界，就会出现「选哪一档都能筛出 1万 的记录」，或者两边都筛不到（取决于实现写的是 `<` 还是 `≤`）。
2. **数字写法不一致。** 上限写「1万」，下限却写「1」。同一组选项里同一个量两种写法，用户要先换算才知道是连续区间。
3. **连接号用错。** 标示数值范围的起止，GB/T 15834—2011 规定用**浪纹线「～」**；「–」是西文排版习惯，在中文正文里不合规。
4. **缺单位。** 三档都没写「元」。字段若以元计，`1万` = 10000 元；若以万元计，`1万` = 10000 万元，量级差一万倍。至少要在筛选标题处标「单位：元」。
5. **三档字数不齐。** 分段控件里宽度不一致、视觉不齐。

**暂定改法**（左闭右开，须与后端区间定义一起确认）：

```
1万以下  |  1万～10万  |  10万以上
```

对应 `1万以下` = `<1万`；`1万～10万` = `≥1万 且 <10万`；`10万以上` = `≥10万`。若规范不接受用注释解释，改成显式写法：

```
＜1万  |  1万～10万  |  ≥10万
```

**这条不建议只改文案就交付。** 必须先确认三档在筛选逻辑里的运算符，否则文案不重叠了、代码还重叠，问题只是从界面挪到了数据里。

### ② 保存成功后的提示：保存成功。

1. **句末句号。** toast/轻提示是短语而非完整句，常见规范是不加句末标点；但**这恰恰是要看规范的地方**——也有规范要求完整句一律加句号。两种都常见，必须按你那本。
2. **缺对象。** 多模块页面（基本信息、配置、成员各有一块）里，「保存成功」不说明保存了什么。
3. **「成功」vs「已保存」。** 完成态用「已+动词」还是「动词+成功」，各家二选一；同一产品混用会显得很脏。

**暂定：** 单对象页 → `保存成功`（去句号）；多对象页 → `基本信息已保存`。

### ③ 加载失败的提示：加载失败——请稍后重试，请检查网络，请点击刷新。

1. **破折号后面挂一串并列祈使句。** 破折号的功能是解释说明，不是当冒号用来分层主副信息。
2. **三个「请」连用、一逗到底。** 一条提示塞三个动作，用户不知先做哪个；且「稍后重试」与「点击刷新」是同一件事的两种说法，语义重复。
3. **「请检查网络」归因错误。** 加载失败可能是服务端 5xx、超时、鉴权失效，不一定是用户网络——把自己的故障推给用户。
4. **「请点击刷新」把操作写进了文案。** 刷新/重试应该是一个按钮，文案不该教用户点哪里。
5. **标点。** 三个分句用逗号连成一串，即便保留并列也该用分号或拆句。

**暂定：**

```
加载失败
请检查网络后重试            [刷新]
```

需要区分原因时（依赖后端错误码）：

```
加载失败
网络异常，请检查网络后重试   [刷新]      ← 网络类
加载失败
服务暂时不可用，请稍后重试   [刷新]      ← 5xx / 超时
```

### ④ 上传限制提示：最多可选3个文件

1. **「可选」歧义。** 「最多可选」既能读成「上限 3 个」，也能被读成「至少可以选 3 个」。建议「最多选择 3 个文件」或「最多只能上传 3 个文件」。
2. **缺触发语境。** 这句是上传前的限制说明，还是用户选了第 4 个文件时的报错？报错场景要带现状：「最多选择 3 个文件，当前已选 4 个」。
3. **数字与量词间距。** 「3个」还是「3 个」是 house style，需规范定；数字本身用阿拉伯数字是对的（GB/T 15835—2011：数值用阿拉伯数字）。
4. **限额硬编码。** 若限额会调整，做成占位符（`最多可选 {n} 个文件`），别把 3 写死在文案里。

## B. 需要你补的三样东西

1. **规范**：文档/链接/条文；至少说明它管到哪几类（标点、数字、术语、提示语结构、语气）。上面每个「暂定」都要拿它复核，尤其 ② 的句号和 ④ 的数字间距，正反两种规范都存在。
2. **被审仓库**：路径 + 这四句文案的位置（页面/组件/i18n key）。没有仓库，我判断不了是硬编码、词条表还是服务端下发，而这直接决定改法（改一个 key，还是改 N 个语言包，还是改后端）。
3. **① 的边界定义**：三档的运算符（`<` / `≤` / `≥`）和金额单位。
