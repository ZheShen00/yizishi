# 三句报错的改稿

**用的行业风格**：`ai`（AI 产品 / AI 文档助手）。依据：用户没说行业，这次也没有仓库和项目术语表，只能从句子本身判断：「改动已经生成好了」「我改完会被编辑器的下一次保存覆盖掉」是模型生成改动再写回文件的场景，技能的 `references/examples.md` 也把这批句子标为「AI 文档助手类产品」。文件名、保存、编辑器这一层和 SaaS 重叠，按通用写法和 SKILL 的固定句式处理。

## 改后（可直接用）

1. 读取文件失败，请重试；多次失败请联系管理员。
2. 保存失败，请重试；多次失败请联系管理员。
3. 文件在保存后又被改过，请关闭编辑器后重试。

## 改前 → 改后

| # | 改前 | 改后 | 问题 |
|---|---|---|---|
| 1 | 读不到这个文件：[Errno 2] No such file or directory: '/srv/files/x.docx' | 读取文件失败，请重试；多次失败请联系管理员。 | 「读不到」口语；异常原文、错误码、服务器路径进了界面（异常只进日志） |
| 2 | 改动已经生成好了，但保存时出错了。请重试一次；一直失败请联系管理员。 | 保存失败，请重试；多次失败请联系管理员。 | 冗长；前半句是过程信息；「请重试一次」「一直失败」和固定句式不一致 |
| 3 | 这份文件在你保存之后又被改过了 —— 请先关掉编辑器再试一次（否则我改完会被编辑器的下一次保存覆盖掉）。 | 文件在保存后又被改过，请关闭编辑器后重试。 | 破折号当连接词；括号里解释机制，还带第一人称「我」 |

## 改了多少处

3 句、7 处具体改动：

- 第 1 句 2 处：删掉异常原文和服务器路径；「读不到这个文件」→「读取文件失败」，套固定句式。
- 第 2 句 3 处：删「改动已经生成好了，但」；「保存时出错了」→「保存失败」；「请重试一次；一直失败」→「请重试；多次失败」。
- 第 3 句 2 处：删破折号和括号；「这份文件在你保存之后又被改过了 / 请先关掉编辑器再试一次」→「文件在保存后又被改过 / 请关闭编辑器后重试」。

字数（含标点）：150 → 63，少 58%。逐句：64 → 22、34 → 20、52 → 21。

## 新增事实及出处

| 改后的说法 | 出处 |
|---|---|
| 读取文件失败 | 原稿「读不到这个文件」；「读取…失败」的句式来自 SKILL 固定句式 |
| 请重试；多次失败请联系管理员 | 原稿「请重试一次；一直失败请联系管理员」；句式对齐 SKILL 固定句式（重试可能好的报错） |
| 保存失败 | 原稿「保存时出错了」 |
| 文件在保存后又被改过 | 原稿「这份文件在你保存之后又被改过了」 |
| 关闭编辑器后重试 | 原稿「请先关掉编辑器再试一次」 |

结论：没有新增事实。数字、时效、承诺、能不能撤销、改动会不会丢，一处都没加，所以没有 `[填：…]`。

## 刻意没改的

1. 「请重试」留着：读取和保存这两处失败重试可能好，固定句式就是「…失败，请重试；多次失败请联系管理员」；没换成「再试一次」（口语，术语里「重试」专指报错后的操作，和「重新生成」分开）。
2. 「联系管理员」留着：原句就是「联系管理员」，只把「一直失败」换成固定句式的「多次失败」，没改成「联系客服」（原稿没说是谁负责）。
3. 「文件」没换成「文档」：按原句用词，也没有术语表可对，最小改动。如果产品统一叫「文档」，第 1、3 句一起换。
4. 「编辑器」留着：下一步就是关它，不换别的说法。
5. 没加「请重新上传」「请重新选择文件」这类下一步：不知道产品支不支持这个动作，不替产品编。

## 需要确认的 3 处（猜的）

1. **第 1 句不再带文件名**：按 `references/examples.md` 的同类案例，这条报错出现时面板上已经显示文件名，句子里不再重复。如果界面上看不到文件名，改成：读取「x.docx」失败，请重试；多次失败请联系管理员。
2. **第 1 句按可重试处理**：文件不存在严格说重试没用。如果这句的真实成因是文件被删或移走，应该写成：找不到「x.docx」，请重新上传。下一步取决于产品支持什么，我没有编；先确认成因再定用哪句。
3. **第 2 句删掉了「改动已经生成好了」**：改动卡片上已经能看到这条改动，报错只交代保存失败。如果保存失败会让已生成的改动丢掉、要用户重新生成，就得加回半句：改动已生成，保存失败，请重试；多次失败请联系管理员。会不会丢要产品确认。

## 验证结果

- 逐句核对：对象（文件、编辑器）、动作（读取、保存、重试）、状态都没动；没有改数字、日期、否定和完成状态；删掉的两处是过程信息和机制解释，不是条件或承诺。
- 格式：三句都是纯文本报错，没有 `**`、没有破折号、没有括号补充；「请」每句只出现一次；全角标点。
- 字数：150 → 63（含标点，少 58%），逐句见上。
- 审的 0–8 步：能做的做了（定行业、按纯文本渲染面处理、清点叫法「文件 / 编辑器」、逐句对固定句式）；找全（`extract_ui_strings.py`）、项目术语表、逐状态渲染、核数字、查锚这几步这次没有仓库和页面，没有对象可查。
- 代码侧没法验证：这次只有三句文案，没有仓库、没有改代码、没有 `docs/copy-glossary.md`，`check_copy_anchors.py`、单测、门禁、构建产物都无从跑。这三句如果落在代码或测试里被锚着，落地时在同一提交里改锚点，再跑 `python scripts/check_copy_anchors.py --base HEAD`。
- 只有中文原稿，没有英文版本要一起对；英文界面需要的话，按同一句式补三句即可。
