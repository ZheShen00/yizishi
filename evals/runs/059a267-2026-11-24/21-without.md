## 2. 更要紧的是：这不是改文案能解决的事

「用户应该先做一次风险测评再买」是流程要求，不是措辞问题。

把「立即购买」改成「先做风险测评」，如果点下去还是直接进下单，按钮就在骗人：原来文案和结果至少是一致的，改完反而不一致。做风险测评的产品（理财、保险、基金这类）通常测评本身是适当性管理的一环，只改文案、不真的拦，比不改更糟，也容易在合规上被认定成流程缺失。

正确的拆法是让文案跟着状态走，三处对齐——文案、跳转、真正的拦截：

- 未测评 / 测评过期：按钮写「先做风险测评」，点击进测评页，做完回到原页面继续买
- 已通过且在有效期内：保持「立即购买」，点击直接下单
- 测评不通过或不匹配：不显示购买按钮，或按钮置灰并说明原因（这类拦截一般不能只靠前端隐藏）

示意代码（前端拿不到测评状态的话，得先有这个接口）：

```tsx
// 文案由测评状态决定；文案说去测评，点击就必须真去测评
const { status, expired } = useRiskAssessment(userId);

if (status === "not_started" || expired) {
  return <Button onClick={goToAssessment}>先做风险测评</Button>;
}
if (status === "rejected") {
  return <Button disabled>暂不可购买</Button>;
}
return <Button onClick={buy}>立即购买</Button>;
```

只改按钮的 `children`、不动点击逻辑，是最差的一种改法。

## 3. 如果你现在只想要文案

那就先别动按钮，在它旁边加一行说明，比如「首次购买需先完成风险测评」。这句话是真的，也不会让人以为点按钮就会去测评。等流程接上了，再按上面的状态分工。

## 4. 需要你确认三件事

1. 风险测评是硬性拦截，还是只做提示？（这决定要不要动流程，还是纯文案）
2. 测评有有效期吗？过期后按钮显示成什么？
3. 界面上「风险测评」固定用哪个说法？有些合规口径要求写「风险承受能力评估」，定了我照抄，不自创术语。

把按钮的位置和这三条给我，我一次改到位：按钮文案、背后的跳转和拦截、以及跟着改的测试。另外提醒一句，这份产品有一份界面文案规范（用「您」不用「你」、用「材料」不用「文件」、用「会话」不用「对话」、用「历史记录」不用「历史版本」），新文案我会照它写；如果那句话正好被测试或门禁锚着，我会把测试和门禁一起更新，不留红灯。
