# 结论

要改，一共 3 处断言级的东西：**`smoke/gate.sh` 和 `tests/banner.test.ts` 的第一条现在是红的，第二条现在是绿的但已经是废的**。

但改法不是把新文案抄进去。这次代码只动了文案、没动行为（没同步完 → 非空提示；同步完 → 空串），所以要改的是「断言盯什么」，不是「断言里的字符串换成哪一句」。否则下次再改一次文案，同样这三处再红一遍。

先确认过：`git status` 只有 `src/banner.ts` 一个改动，`git diff` 也只有那一行字符串，逻辑没动。全仓就 `src/banner.ts`、`tests/banner.test.ts`、`smoke/gate.sh` 三个文件，没有别的引用点，也没有 CI 配置要跟着同步。

# 三条断言的现状

| 位置 | 现在断言什么 | 现在的结果 | 问题 |
| --- | --- | --- | --- |
| `tests/banner.test.ts:3` | `toContain("关闭页面会中断")` | ❌ 红 | 钉的是旧文案里「后果」那半句，新文案没有 |
| `tests/banner.test.ts:6` | `not.toContain("仍在同步")` | ✅ 绿（但这已经不是断言了） | `syncBanner(true)` 返回 `""`，空串当然不含 `仍在同步`；它对「横幅永不消失」这类回归已经不敏感 |
| `smoke/gate.sh:3` | `grep -qF '关闭页面会中断' src/banner.ts` | ❌ `FAIL 关页提醒不在了`，exit 1 | 同上，而且门禁红了会直接拦提交流 |

门禁是实跑的：

```
$ bash smoke/gate.sh
FAIL 关页提醒不在了
exit=1
```

（本机没装 WSL 发行版，`bash` 那层是 Git 自带的 bash；脚本本身在 CI 的 Linux 上行为一致。）

第二条为什么说「废了」，按三种实现推一遍就清楚：

| 实现 | `toContain("关闭页面会中断")` | `not.toContain("仍在同步")` |
| --- | --- | --- |
| 当前代码 | 失败 | 通过（空串） |
| 回归：忽略 `done`，永远返回横幅 | 失败（这里其实文案是对的，属于误报） | **通过 → 漏掉回归** |
| 回归：文案退化成「同步中」，提醒丢了 | 失败 | **通过 → 漏掉回归** |

也就是说，改完之后如果只把第一条的字符串换掉，第二条会一直绿着，而它本该守的那个「同步完横幅消失」已经没人守了。

# 怎么改

## 1. `tests/banner.test.ts`

```diff
 import { syncBanner } from "../src/banner";
+
+// 断言的是「要求」不是「文案」：没同步完必须提示别关页面，同步完必须没有横幅。
+// 文案以后还会改，改到哪一版这两条都得成立。
 test("没同步完 → 提醒别关页面", () => {
-  expect(syncBanner(false)).toContain("关闭页面会中断");
+  const banner = syncBanner(false);
+  expect(banner).not.toBe("");
+  expect(banner).toMatch(/请勿关闭|不要关闭/);
 });
 test("同步完 → 横幅消失", () => {
-  expect(syncBanner(true)).not.toContain("仍在同步");
+  expect(syncBanner(true)).toBe("");
 });
```

两个点：

- 第一条必须保留「含请勿关闭/不要关闭」这一层。只断言 `not.toBe("")` 的话，退化成 `"同步中"` 这种丢了提醒的文案也能过——那正是这条测试存在的理由。
- 第二条从「不含某个词」换成 `toBe("")`，是严格加强，而且彻底和文案无关。

## 2. `smoke/gate.sh`

```diff
 #!/usr/bin/env bash
 # 门禁：没同步完时必须提醒别关页面
-grep -qF '关闭页面会中断' src/banner.ts || { echo "FAIL 关页提醒不在了"; exit 1; }
+# 只认「必须提醒别关页面」这条要求，不认整句文案；先剥 // 注释，
+# 免得注释里的字把门禁骗过去（这个文件第 1 行的注释里就有这句话）。
+sed 's://.*::' src/banner.ts | grep -qE '请勿关闭|不要关闭' || { echo "FAIL 关页提醒不在了"; exit 1; }
 echo ok
```

门禁和测试分工要说清楚：门禁是源码文本级的烟雾检查（拦「提示被整段删掉」），行为回归靠测试守。所以别指望这行 grep 能发现逻辑写反，那是第二条测试的活。

# 一个真实的坑：这句 grep 会被注释骗

`src/banner.ts:1` 的注释是：

```
// 同步横幅：没同步完时提醒「请勿关闭页面」，关了会中断同步
```

只要把 needle 放宽成 `请勿关闭` 而不剥注释，**哪怕函数体里的提示被删光、只剩注释，门禁照样 PASS**。我对现在这版文件确认过，`请勿关闭页面` 同时命中第 1 行和第 3 行：

```
关闭页面会中断   -> NO MATCH
请勿关闭页面     -> MATCH line 1,3
同步中           -> MATCH line 3
仍在同步         -> NO MATCH
```

剥掉注释后 `请勿关闭` 只剩函数体里那一处，门禁才真的在查「有没有这句提示」。这个 `sed` 只处理 `//` 行注释，够用是因为本仓没有 `/* */`、也没有含 `//` 的字符串字面量；以后要是出现，得换正经解析（或者干脆把文案提成一个具名常量，门禁查「常量非空且被 return」——但那是另一次重构，不值得为这行文案捎带做）。

# 需要你拍板的一点

旧文案是「状态 + 后果」：`仍在同步，关闭页面会中断同步`；新文案只有「状态 + 命令」：`同步中，请勿关闭页面`。**「关了会中断同步」这个理由没了。**

- 如果要求只是 `smoke/gate.sh:2` 注释写的「没同步完时必须提醒别关页面」——新文案满足，按上面改测试和门禁即可，这就是一次纯粹的去耦合。
- 如果「要让用户知道关页会中断同步」也是要求——那这次不是改测试的事，是把后果补回文案（或加一句副标题），测试/门禁该同时钉「别关页面」和「提后果」两件事。

我按第一种理解，因为门禁注释写的就是「提醒别关页面」，没提后果。

# 改完怎么验

1. `bash smoke/gate.sh` → 期望 `ok`，exit 0。
2. 补三个反例（我这边没有 test runner，只能推演，建议你在真工程里跑一遍）：
   - 函数体改成 `return "同步中";` → 门禁应 FAIL；
   - 忽略 `done`、恒返回横幅 → 第二条测试应失败；
   - `done` 分支返回 `" "` → 第二条测试应失败。
3. 仓库里没有 `package.json` / `tsconfig.json` / jest 配置，`test` / `expect` 是外部注入的全局，所以这两条测试断言我没法在这个仓库里跑绿给你看——只能按字符串包含关系推出结论；门禁那条是真跑过的。

# 不用动的地方

- `src/banner.ts:1` 的注释已经写的是「请勿关闭页面」，跟新文案一致，没漂移。
- 除上面三段之外，没有别的地方引用旧文案或依赖它的字面值。
