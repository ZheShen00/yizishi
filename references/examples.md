# 改前 → 改后（案例）

来源：AI 文档助手类产品的常见问题，句子已改写成通用示例。
每条后面注的是它犯的那一类。

## 卡片、简介、注意事项

| 改前 | 改后 | 类别 |
|---|---|---|
| 支持 Word / Excel / PDF：上传，或从文件库、最近对话里选一份。Word / Excel 可以在线编辑，保存后覆盖原文件，旧版本可以在历史版本里找回；PDF 只能预览。也可以下载或存进文件库。 | 在线编辑 Word / Excel，预览 PDF。文件可以上传，或从文件库、最近对话中选取。 | 卡片简介写成了说明书；细节放到它出现的地方 |
| 这个功能在对话里也能用，所以没放在首页 | （删掉） | 讲设计理由 |
| 导出任务存在内存队列里，服务重启就没了 | 服务重启后列表会清空，已导出的文件不受影响。 | 讲实现 → 讲用户看得见的后果 |
| 每次导出都会新建一个对话来放结果。删掉对话，导出的文件也会一起删掉；存进文件库的副本不受影响。 | 导出的文件保存在对应的对话中，删除对话会一并删除文件；已存入文件库的副本不受影响。 | 冗长 |
| 导出只转换格式，不改写内容。50 页以上的文档可能要十几秒，带图片会更慢。 | 只转换格式，不改写内容。50 页以上的文档需要十几秒，带图片更慢。 | 冗词 |
| 名称（会写进元数据和文件名） | 文件名称 | 标签里塞了实现 |

## 空状态、toast、提示

| 改前 | 改后 | 类别 |
|---|---|---|
| 文件库里还没有文档。可以先上传一份，或在对话里把文件存进文件库。 | 文件库中还没有文档。上传一份，或在对话中存入文件库。 | 冗词 |
| 已存进文件库（文件库里是新的一条，原文件不受影响） | 已存入文件库 | toast 里讲机制 |
| 这份文件预览不出来，可以下载后看。 | 无法预览这份文件，请下载后查看。 | 口语 → 问题 + 下一步 |
| 改动会**立刻**写进文档，每条改动一张卡，随时可以撤销。 | 改动即时生效，每条一张卡片，可随时撤销。 | 纯文本面上的 `**`（星号原样显示）+ 冗长 |
| 这段对话不保存（关掉面板就没了，刷新还在），文档里的改动会保留。 | 关闭面板后对话不保留，文档里的改动会保留。 | 括号里的细节 |
| 停下这一轮，智能体也会一起停下。已经写进文件的改动不会自动回滚，可以在历史版本里找回旧版本。 | 停止本轮处理。已写入文件的改动不会回滚，可在历史版本中找回旧版 | 悬停提示：冗长、带句号 |

## 进度、状态

| 改前 | 改后 | 类别 |
|---|---|---|
| 已交给智能体。它会先读这份文件再修改，通常要二三十秒，复杂的更久。 | 已交给智能体处理，通常需要 20–30 秒。 | 讲机制；数字写成汉字 |
| 好，这一轮我没有改动文档。 | 文档没有改动。 | 助手腔 |
| 确认中 / 已生效 / 没生效 / 没法确认 | 确认中 / 已生效 / 未生效 / 无法确认 | 状态词统一 |
| 这一条到底改没改我确认不了 | 无法确认是否生效。 | 套话、第一人称 |
| 文档一个字都没变：这一条没落上（编辑器没执行或被撤回了）。 | 文档没有变化，这一条未生效。 | 冒号揭晓 + 开发者用词「落上」 |
| 文件的字节没有变化 —— 它可能只是回答了你，并没有改动这份文件。 | 文件没有变化，智能体可能只回答了问题，没有修改文件。 | 「字节」+ 破折号 |

## 报错

| 改前 | 改后 | 类别 |
|---|---|---|
| 读不到这个文件：[Errno 2] No such file or directory: '/srv/files/…/x.docx' | 读取文件失败，请重试；多次失败请联系管理员。 | 异常原文 / 服务器路径外泄（面板上已经显示着文件名，句子里就不再带） |
| 这个文件不是一份能读的 xlsx（File is not a zip file） | 表格无法打开，可能已加密或损坏。 | 窄 except 里的英文原文 |
| 改动已经生成好了，但保存时出错了。请重试一次；一直失败请联系管理员。 | 保存失败，请重试；多次失败请联系管理员。 | 冗长 |
| 这份文档在你保存之后又被改过了 —— 请先关掉编辑器再试一次（否则我改完会被编辑器的下一次保存覆盖掉）。 | 文档在保存后又被改过，请关闭编辑器后重试。 | 括号里解释机制 + 破折号 |
| 这一条需要编辑器在线才能执行，但当前没有打开的编辑器，没有执行。 | 编辑器没有打开，这一条未执行。 | 讲机制 |
| 配置里的模型 ID 'x' 找不到，这次降级用 fallback_model。 | 配置的模型不存在，已改用默认模型。（模型 ID 只进日志） | 开发者用词 |
| 这个表格里有我们**写回时会丢**的东西（…）—— 在这里改单元格会把它抹掉，所以拒绝了。 | 表格含保存时会丢失的内容（…），在这里编辑单元格会把它们抹掉，因此无法编辑。 | `**` + 破折号 + 「我们」 |
| 第 2 段的italic变了（它是切换：再说一次会变回去） | 第 2 段已切换斜体（再说一次会恢复） | 内部值（英文键名）直接拼进句子 |

## 超限、看不见的范围

| 改前 | 改后 | 类别 |
|---|---|---|
| 这份文档约 N 字，超出一次能处理的上界（M 字）—— 这一轮我只看了**目录 + 最相关的 K 段**。要改的地方不在里面：**选中那一段**再说一句，或者说「重新看一遍第 X 节」。 | 这份文档约 N 字，超出单次处理上限（M 字）。本轮只读了目录和最相关的 K 段（约 L 字）。要改其他地方，请先选中那一段再说，或说「重新看一遍第 X 节」。 | `**`、破折号、冒号揭晓、「上界」 |

## 列表与筛选页

| 改前 | 改后 | 类别 |
|---|---|---|
| 筛选条件只用列表行里真有的字段；作者 / 标签 / 引用次数是详情字段，点条目在详情里看。 | 作者、标签、引用次数在详情里看。 | 讲设计理由 |
| 表头随数据源变化（各源字段不同），由接口下发。排名来自第三方统计，与官方数据可能不一致。 | 前半句删掉。后半句**需要裁决**：它和之前按用户裁决删掉的那条说明是同一句，先问留不留；要留的话写「排名来自第三方统计，可能与官方数据不一致。」 | 讲实现；和裁决过的内容重合（例子里曾直接给了改写，评测时模型照着改写后留下了，漏标裁决） |
| 搜索标题 / 编号（列表内即时过滤，回车搜全库） | 搜索标题或编号 | 占位符写成说明书（回车后出现的按钮已经说明了） |
| 今日暂无数据。 | 这一天暂无数据。 | 不准确：用户可能在看往日数据 |
| 不限状态 / 类型：全部 / 负责人：全部 | 状态：全部 / 类型：全部 / 负责人：全部 | 筛选项「全部」写法不一 |
| 要你补 / 待你补全 / 需要你补全 / 待填 | 待填 | 同名异称 |

## 状态、数字、对象名

| 改前 | 改后 | 类别 |
|---|---|---|
| 文件库加载失败时，页面显示「文件库中还没有文档。」 | 失败时显示「文件库加载失败，请刷新重试」；空状态只在加载成功、结果为空时出现 | 失败显示成空 |
| 最近对话 · 共 30 个（接口只取最近 30 个） | 最近 30 个对话 | 截断写成总数 |
| 最多上传 20 个文件（代码里 `MAX_FILES = 10`） | 最多上传 10 个文件 | 数字和代码对不上：以代码为准，拿不准就问 |
| 读取附件失败：FileNotFoundError: '/data/uploads/9f1c/季度报告.pdf' | 找不到季度报告.pdf，可能已被移动或删除，请重新上传。 | 上下文里看不出是哪份文件：留用户认得的文件名，去掉路径和异常 |
| 上传失败：不支持的格式，请重试。 | 只能上传 docx / xlsx / pdf，请换成这几种格式后重新上传。 | 重试好不了的错误不写「请重试」，写能解决它的那一步 |
| 邮件已发送给 3 位联系人 ✓ | 邮件已写好，请在邮箱中检查后发送。 | 交给别的应用去做的事：页面不知道邮箱打开没有、信发出去没有，只写页面做到的；去掉 ✓ 和成功样式 |

查锚也补了一招：门禁 `grep -qF '片段' 源文件` 时，如果注释里也写着这个片段，句子删了门禁照样绿。把锚限定在字符串字面量里：`grep -qE '"[^"]*片段[^"]*"' 源文件`，注释怎么改都不影响。

## 反例：改错了的（都是测试或门禁当场拦下的）

1. **「已撤销 3 步」**：撤销没有回执，这么写等于宣称已经完成。门禁要求只说「已发出」。
   正确：「已发出 3 步撤销，请确认文档是否已恢复。」只删掉原来括号里的「编辑器没有回执，请看一眼……」。
2. **「文字改动和格式改动不能一起执行」**：意思没错，但门禁靠「不要混用」这四个字确认函数会拒绝混用。
   正确：「文字改动和格式改动不要混用，请分两次：…」。门禁锚着的短词本身就够短时，保留它。
3. **前后端各写一份兜底句**：前端改成了「没识别出要改什么，文档没有动」，但后端在这条路上每次都先补一句自己的旧话，前端那句从来显示不出来；前端单测喂的是「回复为空」，一直是绿的。
   正确：后端只发 `parse_failed`，句子只在前端一份；测试喂后端真的会发的形状。
4. **反向断言悄悄失效**：`not.toContain("你后来自己改过")`，句子改成「之后有手动修改」之后，它永远通过。
   正确：断言精确值 `expect(staleNote(false)).toBe("")`，钉住「这时卡片上什么都不显示」，以后怎么改文案都不会再失效。
   只换成 `not.toContain("之后有手动修改")` 也能修好这一次，但下次改文案又会失效。
5. **把裁决过的名字当行话改掉**：「智能整理」看着像营销腔，但它是功能名，门禁按用户裁决锚着。
   正确：审的时候标成「需要裁决」，不在提案里直接换掉；卡片简介里裁决过的口径词同理保留。
6. **发给客户的邮件草稿按界面腔压短**：草稿是用户要发给别人的信，压短会丢掉礼貌和语气。
   正确：草稿按改文章的规则处理，只改它外面那层按钮和提示（「复制草稿」「N 处待填」）。
