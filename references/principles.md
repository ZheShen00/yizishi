# 通用写法：原则、按元素写、去 AI 腔

各家规范都认的通用规则，模型本来大多就会。项目自己定下的叫法、固定句式和用户裁决过的名字在 SKILL.md 的「项目约定」里；两边冲突时，以项目约定为准。出处见 `sources.md`。

## 动笔前先定三件事

1. **谁在看、在什么时候看**：刚点了按钮在等结果？出错了？第一次进来什么都没有？
2. **它渲染在哪**：纯文本（`whitespace-pre-wrap`、toast、`title`、`placeholder`）还是 markdown；空间多大。纯文本面上 `**` 会连星号一起显示。
3. **看完要用户做什么**：说不出下一步、也不是在报结果的句子，多半可以删。

## 核心原则

1. **以用户为主体**：说用户能做什么、得到什么，不讲系统怎么实现。
2. **精简**：删冗词，不重复用户已知的事，不必交代全部细节。
3. **关键信息放前面**：结果或问题先说，原因后说。
4. **一句一件事**：一句里别叠三层括号和分号。
5. **具体**：写用户用得上的数字、对象和动作；用不上的（字节数、内部上限）不写。
6. **一致**：同一个东西全站一个叫法，同一类提示一个句式，以术语表为准。
7. **诚实**：只说确认了的事（见 SKILL.md「踩过的坑」）。
8. **不责怪、不卖萌、不滥用道歉**：「抱歉」只留给真给用户造成了损失的时候。

## 按元素写

| 元素 | 写法 | 例 |
|---|---|---|
| 按钮 | 动词开头，一般 2–4 个字，说清点了会发生什么；危险操作写动作本身，不写「确定」。字数是默认值：术语表或行业文件定下的固定词（「立即购买」）、功能名照用，不为凑字数删信息；「立即」这类词同一稿里同类按钮只用一种写法，一屏只给主要动作用 | 保存 / 删除 / 打开对话 / 仍要导出 |
| 标签、标题 | 名词短语，不加句号 | 工作表名称 |
| 下拉选项、筛选项 | 名词短语；「全部」项的写法见 SKILL.md 固定句式 | 状态：全部 |
| 无障碍标签、图标按钮的 `title` | 写控件是什么、点了做什么，和可见文字（包括下拉占位）一致；不加句号，不写「按钮」「图标」 | 清空搜索 / 上一页 / 已认证 |
| 占位符 | 给例子，不写说明书；不加句号。不能代替标签：去掉占位符后输入框就没名字了，那是缺陷 | 想怎么改？例如：把开头那段写短一半 |
| 输入框下的提示、悬停提示 | 一句补充，不加句号，不重复标签 | 也可上传 md / csv / json / tsv 文件 |
| 空状态 | 现状 + 下一步（可以带一个主操作）。只在加载成功、结果确实为空时显示；失败要显示报错。第一次用、被清空、筛选没结果是三种情况，各写各的 | 文件库中还没有文档。上传一份，或在对话中存入文件库。 |
| 报错 | 问题 + 对症的下一步；具体句式见 SKILL.md 固定句式。不露异常原文、服务器路径、库名、类名、错误码 | 保存失败，请重试；多次失败请联系管理员。 |
| toast | 只说结果，越短越好 | 已存入文件库 |
| 确认框 | 说删掉什么、多少、能不能撤回，不写光秃秃的「确定吗？」；按钮写动作 | 将删除「X」（第一处），只能靠撤销找回 |
| 状态标签 | 一套固定词，几种状态分开 | 确认中 / 已生效 / 未生效 / 无法确认 |
| 进度、等待 | 在做什么 + 大概多久 | 已交给智能体处理，通常需要 20–30 秒。 |
| 注意事项、长说明 | 最多两三句，只写用户要做的事和要等多久 | 只转换格式，不改写内容。50 页以上的文档需要十几秒，带图片更慢。 |

括号里常藏着机制解释，能删就删；只留用户用得上的补充（大小、页数、原因类别）。

## 去 AI 腔（no-ai-slop 在界面上的样子）

| 写法 | 例子 | 改法 |
|---|---|---|
| 讲设计理由 / 实现 | 「这个功能在对话里也能用，所以没放在首页」「导出任务存在内存队列里，服务重启就没了」 | 删；或换成用户看得见的后果：「服务重启后列表会清空」 |
| 描述机制 | 「它会读这份文件后直接修改」「编辑器没有回执」「文件的字节没有变化」 | 删，或只留结果：「文件没有变化」 |
| 助手腔、自说自话 | 「好，这一轮我没有改动文档」「（它没说什么）」 | 「文档没有改动。」「（智能体没有回复文字）」 |
| 冒号揭晓 | 「要改它：**选中那一段**再说一句」 | 「要改它，先选中那一段再说。」 |
| 破折号当连接词 | 「找不到这一段 —— 插入没有执行」 | 逗号或句号 |
| 装饰性强调 | `**立刻**`、到处放的 ⚠️ | 删；⚠️ 只留给不可逆、会丢东西的时候 |
| 同名异称 | 网页端编辑 / 在线编辑；会话 / 对话；产物 / 文件 | 全站只留一个，写进术语表 |
| 套话重复 | 「通常二三十秒」出现在三个地方 | 只留最需要的那一处 |
| 可选动作一长串 | 「可以……也可以……还可以……」 | 只留主路径 |
| 二元对比 | 「这不是 X，是 Y」 | 直接说 Y；只有真能消除误会时保留 |
| 营销腔 | 赋能、助力、一站式、全方位、极致、无缝、轻松、智能地；leverage、seamless、robust、empower、streamline | 删，写具体做什么 |
| 口语冗词 | 上下文已经明确时的「这一轮 / 这一条 / 这一批」，以及一下、进行、就、一点、直接、其实、然后 | 删 |
| 新一代口头禅 | 说白了、讲真、说到底、本质上、核心在于、真正的… | 删；去 AI 腔改完的句子要再扫一遍，常常是旧腔换成了这些 |
| 讲义腔冒号 | 「原因很简单：」「一句话总结：」 | 删掉引子，直接说内容 |
| 被动、空主语 | 「会被自动处理」「可以看到」「经过检测发现」 | 写出谁做的：「系统已自动处理」「你可以…」 |
| 抽象动词 | 体现了、意味着、标志着、旨在、聚焦、实现了、涉及 | 换成具体动作，或删 |
| 和稀泥 | 各有优缺点、因人而异、在一定程度上、通常来说 | 给结论；真不确定就说缺什么信息 |
| 对话面板开头结尾 | 「您好！感谢您的提问」「希望对你有帮助」「综上所述」；短回答硬拆成 1. 2. 3.；Certainly! / Great question / Feel free to… / Here are 3 ways… | 开头直接给结果，结尾不寒暄；两三句能说完的不列表 |
| 引号当强调 | 到处加「」或 "" 强调普通词；中文里夹 ASCII 引号 | 引号只给界面元素名、文件名、专有名词和原话 |
| 把系统拟人 | 「AI 认为」「智能体决定」 | 写系统实际做了什么：「已按 X 排序」 |
| 工具残留 | `citeturn0search0`、`utm_source=chatgpt.com`、没填的 `[占位符]` | 模型输出显示到界面前必须清掉，这是 bug 不是文风 |
| 可移植的套话 | 「让工作更高效」「开启智能新体验」「一切尽在掌握」 | 能原样搬到别的产品里的句子就是空话：换成这个功能具体做什么，或删 |
| 吹重要性 | 全新升级、重磅上线、里程碑式、革命性 | 写改了什么：「支持批量导出」 |
| 无源背书 | 「深受用户信赖」「业界领先」「专家推荐」 | 有出处就写出处和数字，没有就删；拿不准问用户，别编 |
| 解读型引子 | 「值得一提的是」「请注意」「重要提示：」后面跟的是普通信息 | 删引子；真要用户注意的，用组件层级（警告条、确认框）表达 |
| 推销式续话 | 「如果你愿意，我还可以帮你…」「有需要随时告诉我」 | 删；有后续操作就做成按钮，或一句「可以继续…」 |
| 罐头同理心 | 「我完全理解你的困扰」「别担心」 | 删，直接给解决办法 |
| 知识截止声明 | 「截至我的知识截止日期…」 | 界面上写数据时间：「数据更新于 2026-10-01」 |

开发者用词的清单在 SKILL.md「项目约定」里。

这些是文风提示，不是「AI 写的」的判决：单句命中不说明什么，同一段里扎堆才要改；平实的技术用语不算。

**按作用判断，不按词表命中**：一个词能不能删，看它在这句里做什么。交代对象、条件、范围、程度、下一步、谁负责的，不删；只是包装的才删。不主动换同义词，也不把几样具体的东西压成一个概括词（「更快、更省内存」不能并成「性能更好」）。哪一处改了拿不准意思是否等价，就撤销那一处。

**繁体界面**（zh-TW / zh-HK）：用词和标点另有一套，读 `locale-zh-hant.md`。

## 和 no-ai-slop 的分工

去 AI 腔的规则照用。但界面文案没有个人声音要保，要的是全站一致，所以同类句子统一成一个说法，优先于最小改动。发给第三方的文字（外联邮件、分享文案）例外，按 no-ai-slop 改文章的规则来：保住语气、最小改动。
