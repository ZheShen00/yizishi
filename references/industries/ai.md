## 1. 什么时候用这份

信号（命中任意两条就用；只命中一条时，结合用户的话判断）：

- 代码 / 依赖：`openai`、`@anthropic-ai/sdk`、`anthropic`、`@google/generative-ai`、`google-generativeai`、`langchain`、`langchain-core`、`llama-index`、`ai`（Vercel AI SDK）、`@ai-sdk/*`、`ollama`、`litellm`、`autogen`、`crewai`、`transformers`、`vllm`、`@modelcontextprotocol/sdk`（MCP）
- 目录 / 文件名：`agents/`、`prompts/`、`chat/`、`conversations/`、`completions/`、`rag/`、`tools/`、`mcp/`、`copilot/`、`model-router/`
- 界面里的词：对话、新对话、停止生成、重新生成、重试、引用来源、工具调用、正在搜索、正在思考、推理过程、思维链、token、额度、配额、速率限制、上下文长度、系统提示词、知识库、联网搜索、插件、技能、智能体、模型选择器、temperature / 采样、API Key、用量、账单、幻觉、水印标识
- 用户的话：「做个 AI 助手」「接 GPT / Claude / 通义的 API」「聊天机器人」「智能体产品」「大模型应用」「RAG 系统」「模型广场」「Copilot 功能」

和别的行业重叠时：

- **AI + 金融 / 医疗 / 教育 / 政务**：先按那个行业的合规硬约束（风险提示、处方禁区、广告法禁语、未成年人保护等级）走，再叠这份文件里和「这是不是 AI 生成 / 判断对不对」有关的规则（标识、幻觉提示、拒答）。两边都要求的「不许说的话」取并集，都不能违反。
- **AI + 企业 SaaS / 效率工具**：把这份文件当作「AI 功能」这一层的补充规则，SaaS 本身的按钮、空状态、报错仍按通用写法；只有涉及生成内容、工具调用、模型局限的部分套这份文件。
- **纯规则引擎 / 无大模型参与的"智能"功能**（比如传统推荐算法、规则匹配）：不适用这份文件，不要为了"看起来高级"而加幻觉提示或模型免责声明——那是误导。

## 2. 语气和人格

一句话定调：**克制地暴露不确定性，把判断权交还给用户；像工具该有的平实，不是来讨好你的人格。**

- **人称**：对用户默认用"你"；企业 / 政务场景跟随项目约定改"您"，全站只用一种。系统自称避免「我」替代客观陈述——「我觉得这样写更好」要改成「这个答案的把握不高，建议核对」，让陈述可以被验证，而不是变成人在表态。
- **正式程度**：比企业软件随意，比社交 App 克制。可以用省略号表示"生成中"，不滥用感叹号渲染自信，尤其是不确定性和报错场景里感叹号等于撒谎。emoji 默认不用，除非产品本身走人格化路线（虚拟角色、陪伴类）且已经在项目约定里裁决过。
- **确定性词要分级，不能两极化**：「可能」「通常」「目前看起来」「已核实」「无法确认」是不同把握程度，不能混用或省略；禁止「肯定」「保证」「100% 准确」这类绝对化用语出现在模型输出相关的任何提示里，哪怕是广告语境。
- **系统自称统一**：产品里"系统 / 模型 / 智能体"分别指什么要固定下来，不要在报错里叫"系统"、在聊天里叫"我"、在日志里叫"引擎"，指的是同一件事就用同一个词。
- **覆盖 `principles.md` 的地方**：
  - 「诚实」规则在这里从文案习惯升级成强制 UI 元素：免责声明、引用来源、生成内容标识不是可选的文风优化，是本节第 6 节的硬约束，删了算合规问题，不只是文案问题。
  - 「进度、等待」规则里"大概多久"的写法不适用于模型生成本身：生成耗时不可预测，不写"通常 20–30 秒"这类精确数字；用流式输出本身展示进度（文字逐渐出现），需要文字提示时写"生成中"而不编造时长；只有确定性强的外围步骤（如文件解析、联网检索）才可以给大致时长。
  - 「按钮：危险操作写动作本身」在智能体产品里要加对象和范围：不是"删除"，是"删除 orders.csv 中的 3 行"；智能体做的是用户没有亲眼看到完整过程的操作，确认文案必须比人工点击的按钮更具体（见第 7 节）。

## 4. 术语和叫法

| 用 | 不用 | 说明 |
|---|---|---|
| 对话 | 会话、线程、thread | 跟项目默认约定一致，全站一个词 |
| 智能体 | Agent、代理 | 「代理」在中文里和「中介/代理人」撞义，容易误读 |
| 提示词 | Prompt、指令（不一定对） | 用户写的那段输入；系统内置的固定文案叫「系统提示词」 |
| 幻觉 / 编造信息 | 瞎编（口语）、误差（轻描淡写） | 面向普通用户可以直接说「可能编造了不存在的信息」，不用「幻觉」这种行话（除非是开发者文档） |
| 可能不准确 | 存在误差、有一定局限性 | 后者是和稀泥套话，不说清楚风险有多大 |
| 联网搜索 | 网页浏览、上网查、Browse | 功能名以产品实际开关文案为准，这里给中文默认叫法 |
| 工具调用 | 函数调用、Function calling | 面向用户的状态文案不暴露「函数」这种开发者词 |
| 知识库 | 向量库、RAG 库、Embeddings | 后三个是实现细节，用户看不懂也用不上 |
| 上下文长度 / 对话长度 | Context window、上下文窗口（英文夹杂） | 中文界面统一用「上下文长度」或「可处理的对话长度」 |
| 额度 / 用量 | Credits（英文直接用）、点数 | 计费单位要和账单页一致，不要一个页面两种叫法 |
| 速率限制 | Rate limit（英文直接用） | 面向用户的报错统一用中文，开发者文档 / API 响应体里保留英文字段名 |
| 令牌 / token | Token（仅在开发者向文档里可以直接用英文） | 面向最终用户的计费说明优先用「字数」「用量」等用户能理解的单位，只有开发者 API 文档才用「token」 |
| 停止生成 | 中断、取消（易和"取消发送"混淆） | 这个按钮专指打断正在流式输出的回答 |
| 重新生成 | 换一个答案、Regenerate（英文直接用） | 和「重试」区分：重新生成是对正常回答不满意；重试是因为报错失败了 |
| 重试 | 刷新、再试一次 | 专指报错后的操作，和「重新生成」分开 |
| 引用来源 / 来源 | 参考资料、References（英文直接用） | 列在回答下方的可点击来源 |
| 显式标识 | 水印（不准确，水印只是显式标识的一种实现） | 按标识办法的官方用词走，不要用「水印」泛指所有标识方式 |
| 隐式标识 | 元数据标记（装饰性直译） | 同上，官方定义已经够用 |
| 思维链 / 推理过程 | Chain of thought（英文直接用）、草稿 | 面向用户展示模型中间推理步骤时的统一叫法 |
| 安全拦截 / 无法回答这类请求 | 河蟹、被墙、审核不通过 | 不用网络黑话描述安全策略触发 |
| 拒答 | 拒绝回答（偏法律腔）、驳回 | 开发者 / 审查语境用「拒答」，面向用户的文案本身不需要出现这个词，直接给替代方案 |
| 多轮对话 | 连续对话、Multi-turn（英文直接用） | 和「单轮」对应，用于说明功能范围时统一 |
| 模型 | 大模型、LLM（面向最终用户时） | 面向开发者的技术文档可以用「大模型」「LLM」，面向最终用户的界面统一简化成「模型」 |
| 技能 / 插件 | Skill、Plugin（英文直接用） | 两者在不同产品里指代不完全一样的能力扩展方式，按产品实际命名统一，不要同一产品里混用 |
| 多模态 | 全模态、跨模态（装饰性替换） | 指同时处理文字、图片、音频、视频中的多种；面向用户时优先直接说能处理什么（"可以识别图片"）而不是抛术语 |
| 流式输出 | 打字机效果（口语化但不准确）、Streaming（英文直接用） | 指回答逐字出现的传输方式；用户看到的是效果，解释功能时统一用「流式输出」 |
| 长期记忆 / 记忆 | Memory（英文直接用） | 跨对话保留的用户信息；和「上下文」区分：上下文只在当前对话有效，记忆跨对话 |
| 提示词注入 | Prompt injection（面向用户时直接用英文） | 面向用户的安全提示不需要这个术语，直接说「检测到异常指令，已忽略」；仅开发者文档里使用英文术语 |
| 置信度 / 把握程度 | Confidence score（面向用户时直接用英文） | 面向用户展示模型对答案的把握时用中文描述分级（见第 2 节），不直接暴露内部的数值分数 |
| 项目 / 工作区 | Project、Space（英文直接用） | 多个产品用这个概念归档一组对话和文件；中文叫法跟产品实际命名统一，不要「项目」「空间」「工作区」同一产品里混用 |
| 诱导模型违反安全策略的行为 | 越狱、Jailbreak（面向用户时直接用英文黑话） | 面向用户的安全提示写清楚发生了什么，不抛黑话：「检测到绕过安全限制的尝试，已拒绝」 |
| 已切换到备用模型 | 降级、Fallback（面向用户时直接用英文） | 原模型不可用时自动切换，要明确告知用户换了模型，不能悄悄切换让用户以为还在用原来的模型 |

## 5. 按元素写

只写和通用写法不同的部分，其余按 `principles.md`。

**按钮（停止 / 重新生成 / 重试 / 反馈）**

- 「停止生成」在流式输出过程中必须随时可点，不能因为还在"思考"就禁用；点击后已经生成的内容保留，不删除。
- 中：停止生成 / 重新生成 / 重试。英：Stop generating / Regenerate / Retry（三个按钮文字互不替代，用途见第 4 节术语表）。
- 反馈按钮（赞 / 踩）点击后只给一个轻量确认，不弹表单打断阅读：中「已记录反馈」，英「Feedback submitted」；需要进一步说明时才展开输入框，不强制。

**表单标签和校验（API Key、系统提示词、模型选择）**

- API Key 输入框：placeholder 给格式示例而不是说明书，中「sk-... 开头的密钥」，英「Starts with sk-...」；校验失败写清楚是格式错误还是验证失败：「密钥格式不正确」≠「密钥无效，请检查是否已过期或被吊销」，两种报错对应的下一步不同。
- 模型选择器里每个模型的副标题只写用户用得上的差异（速度、成本、是否支持联网/图片），不写参数量、架构这类内部信息。

**报错（速率限制 / 配额 / 上下文超限 / 安全拦截 / 工具调用失败）**

- 重试可能好的：速率限制、模型繁忙。中「请求过于频繁，请稍后重试」，英「You're sending requests too quickly. Please try again shortly.」
- 重试好不了的：配额用尽、余额不足。中「本月额度已用完，请升级套餐或等待额度重置」，英「You've used all your quota for this period. Upgrade or wait for it to reset.」不写「请重试」。
- 上下文超限：说清楚超在哪、能做什么。中「这段对话过长，已处理不了更多内容；可以开始新对话，或说明要保留的部分」，英「This conversation is too long to continue. Start a new one, or say which parts to keep.」
- 安全拦截：见第 7 节「安全拒答」。
- 工具调用失败：说工具本身，不说函数名。中「联网搜索暂时不可用，已基于已有信息回答」，英「Web search is unavailable right now. This answer uses existing information only.」

**空状态（新对话 / 无可用模型 / 知识库为空）**

- 新对话：不需要寒暄开场白，输入框占位符给可执行的例子，不是「我能帮你做什么？」这种空泛问题。
- 无可用模型 / 未配置 API Key：现状 + 下一步，点名具体缺什么。中「还没有配置模型，添加一个 API Key 后即可开始对话」。

**确认框（智能体动作确认）**

- 不可逆或有外部影响的动作，确认框必须写清楚：要做什么、影响范围多大、能不能撤销；按钮写动作本身，不写「确定」。详细模板见第 7 节「智能体不可逆操作」。

**输入框下的提示、悬停提示（字数 / token 计数、模型能力提示）**

- 字数 / token 计数器只在接近上限时才需要强调（变色、加粗），平时是一句补充，不加句号：「还可以输入 1,200 字」。不要把精确的 token 数暴露给普通消费者产品的用户，字数对用户更直观；开发者向产品（API 控制台）才展示精确 token 数。
- 模型选择器的悬停提示写能力差异，不写参数：「适合复杂推理，速度较慢」而不是「320 亿参数，32K 上下文」。

**生成结果标注（图片 / 语音 / 视频）**

- 图片、语音、视频类的生成结果，显式标识要放在结果本身可见的位置（角标、水印、片头/片尾提示音），不能只写在页面说明文字里；下载后的文件要带着标识一起走（对应标识办法的隐式标识要求）。
- 中：生成的图片角标统一写「AI 生成」；语音类在播放开始前用简短提示音或文字条「以下内容由 AI 合成」。英：「AI-generated」标签统一放在同一位置，不要每次生成换一种措辞或位置。

**状态标签（生成中 / 思考中 / 工具调用中 / 已停止 / 已完成 / 出错）**

- 一套固定词，不要「生成中」「加载中」「处理中」混用表示同一个状态；展示模型推理过程时用「正在思考」或「推理中」（和「正在生成回答」区分开，前者是看不见最终文字的中间步骤）。
- 工具调用状态写用户能懂的动作，不写函数签名：「正在联网搜索」而不是「Calling search_web(query=...)」；「正在读取文档」而不是「Invoking read_file」。

**通知 / 推送（用量预警 / 任务完成）**

- 用量接近上限：提前量和下一步一起给。中「本月额度已用 90%，预计 3 天后用完，可提前升级」。不要只发「额度告急」制造焦虑却不给动作。
- 智能体长任务离开页面后完成：说清楚做了什么、要不要看结果，不写「任务完成」这种空泛的话。

**进度（智能体多步任务）**

- 展示当前在做第几步、一共几步（如果提前知道总步数），不编造剩余时间；步骤名写用户能懂的动作，不写内部状态机的节点名。

**引导 / 首次使用（模型能力说明）**

- 对应 HAX 准则第 1、2 条：开场要讲清楚「这个东西能做什么」和「做得有多好、在什么场景下不可靠」，不是功能列表式的自夸；局限性和能力放在同一处说，不要只强调能做什么、回避做不好的部分。

**帮助说明（幻觉 / 引用来源解释）**

- 引用来源：行内标记用可点击的角标或来源名（如「[1] 来源：xxx.com」），不要裸 URL 堆在一起；每条来源要能点开核对，不是摆设。
- 幻觉说明只出现一次（比如页面底部固定一行），不要在每条回答下面都重复一遍免责声明造成视觉噪音。

## 6. 合规和硬约束

必须出现的话：

- 生成内容在合理位置有显式标识，用语遵循官方定义的「显式标识」「隐式标识」，不要自造说法（如用「水印」代替「标识」）。标识办法要求导出、下载、复制、转发等场景保留标识，产品的导出 / 分享功能文案和实现都要覆盖这点。
- 对话式界面在用户首次使用时让其明确知道在和 AI 交互，除非上下文已经非常明显（EU AI Act 第 50(1) 条的原则；国内同样要求以显式标识落实类似效果）。
- 涉及模型训练数据使用用户内容的，开关 / 说明文案要讲清楚默认状态（默认开启还是默认关闭）、关闭后影响的范围（新对话 / 历史记录 / 多久生效），不能用一句「改进我们的服务」糊弄过去。
- 生成或编辑他人人脸、声纹的功能，上传素材前要有同意确认，不能默认用户已经获得授权（《互联网信息服务深度合成管理规定》）。

不许出现的话：

- 「绝对准确」「100% 正确」「保证无错」等绝对化用语，不管是营销文案还是功能说明，只要和模型输出的可靠性有关就不能用。
- 让用户误以为在和真人客服对话的话术（刻意隐瞒 AI 身份），除非产品场景已经被监管豁免（如内部技术支持工具的明显上下文）。
- 「恶意删除、篡改、伪造、隐匿」生成内容标识的功能或引导（标识办法明令禁止，产品设计本身也不能提供这类选项）。

必须的格式：

- 标识的呈现方式（文字 / 图形 / 声音）要让用户「明显感知」，字体不能刻意缩小或模糊、位置不能藏在角落只有放大才能看清。
- 计费相关文案：额度 / token / 金额三者换算关系要在用户能查到的地方说清楚，不能只显示一个抽象的「额度」数字而不说明等于多少次调用或多少钱。
- 速率限制报错要带上限值和重置时间（如果产品已知具体数值），不要只写「太频繁了」而不给用户预期。

对应法规 / 标准出处：

- 《生成式人工智能服务管理暂行办法》第 4 条（内容底线）、第 9 条（服务协议与用户权利义务）、第 12 条（生成内容标识）、第 15 条（投诉举报入口）。<https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm>
- 《人工智能生成合成内容标识办法》（显式 / 隐式标识定义、禁止删除篡改条款）。<https://www.cac.gov.cn/2025-03/14/c_1743654685896173.htm>
- GB 45438-2025《网络安全技术 人工智能生成合成内容标识方法》（技术实现要求）。<https://www.cac.gov.cn/2025-09/05/c_1758792061408012.htm>
- 《互联网信息服务深度合成管理规定》（人脸 / 声纹等深度合成的同意与显著提示义务）。<http://www.cac.gov.cn/2022-12/11/c_1672221949354811.htm>
- EU AI Act 第 50 条（交互透明义务、合成内容标记义务）：随第 113 条通用日期 2026-08-02 生效；Digital Omnibus on AI（Regulation (EU) 2026/1744，2026-07-27 生效）给 2026-08-02 前已上市的生成式 AI 系统一个过渡期，第 50(2) 条标记义务的合规期限延到 2026-12-02，第 50 条其余义务不受影响。<https://eur-lex.europa.eu/eli/reg/2024/1689/2026-07-27/eng>、<https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A32026R1744>

## 7. 高风险场景

**智能体不可逆操作（发邮件、删文件、下单支付、执行命令、写操作 API 调用）**

必写要素：动作对象（具体到文件名 / 收件人 / 金额）、影响范围（删几行还是删整个文件）、能不能撤销。按钮写动作本身。

> 中：「这将删除「2026年报.xlsx」中的 3 个工作表，且无法撤销。」按钮：删除 / 取消。
> 英：「This will permanently delete 3 sheets in "2026 Annual Report.xlsx." This can't be undone.」Buttons: Delete / Cancel.

**高风险问答的不确定性披露（医疗、法律、金融类追问）**

不堆叠免责声明，但在给出具体建议的那一条回答里，如果涉及需要专业判断的领域，要明确提示"仅供参考，需要核实"，不写成好像在教条地免责。

> 中：「以下信息可能不完整，具体用药请以医生或药品说明书为准。」
> 英：「This may not be complete—check with a doctor or the medication's label before acting on it.」

**安全拒答（违法、自伤、未成年人保护相关请求）**

拒答简短、不说教，不堆砌"我们鼓励""请遵守"这类教导式语言；能给替代路径时给（比如换个问法、相关求助资源），不能给时就停在简短陈述，不硬加一段说教收尾。

> 中：「这个请求我无法处理。」（如适用，另起一行给资源或替代方向，不混在同一句话里）
> 英：「I can't help with that request.」

**生成内容标识被去除或导出丢失**

导出 / 下载 / 复制功能必须保留标识，产品说明里不能暗示"导出后就是你自己的内容，可以去掉标识"。

> 中：「导出的文件仍会保留「AI 生成」标识，这是平台规则要求。」
> 英：「Exported files keep the "AI-generated" label — this is required by platform policy.」

**配额 / 余额耗尽导致服务中断**

必须说清楚是否扣费、历史记录是否还能看、什么时候恢复，不能让用户误以为数据丢失。

> 中：「额度已用完，无法生成新回答；已有的对话记录仍可查看，额度将于 11 月 1 日重置。」
> 英：「You're out of quota for new responses. Existing conversations are still available. Your quota resets on Nov 1.」

**训练数据使用授权 / opt-out 开关**

开关本身的标签要讲清楚默认值和作用范围，不能埋在"隐私设置"深处只给一句笼统描述。

> 中：「允许将对话内容用于改进模型（默认开启，可随时关闭；关闭后仅影响后续新对话）」
> 英：「Allow your conversations to help improve the model (on by default; turning it off only affects new conversations going forward).」

**深度合成人脸 / 声音（数字人、换声、换脸类功能）**

生成或编辑他人人脸、声纹的功能，提示文案要明确告知"这是编辑/合成"，并确认已取得被编辑对象的同意；不能把"一键换脸""声音克隆"包装成纯娱乐效果而隐去同意和标识要求。

> 中：「生成的视频将合成你上传的人脸，且会带有「AI 合成」标识；请确保你有权使用这张照片。」
> 英：「This video will use the face from your uploaded photo and will carry an "AI-synthesized" label. Make sure you have the right to use this photo.」

**拒答疑似误判时的申诉入口**

安全拦截不是终点，产品要给出申诉或反馈路径，不能让用户卡在一句拒答里无路可走；入口文案要具体，不是泛泛的"联系客服"。「人工复核」只在确实有人复核时写，没有就只写「可以点击反馈」。

> 中：「如果你认为这是误判，可以点击反馈，我们会人工复核。」
> 英：「If you think this was a mistake, send feedback — we'll have someone review it.」

## 8. 这个行业的 AI 腔和坏写法

| 坏写法 | 例子 | 改法 |
|---|---|---|
| 拟人化系统内部状态 | 「我正在思考」「我觉得这个答案不太好」 | 写实际状态：「推理中」「这个答案把握不高，建议核实」 |
| 过度抱歉式拒答 | 「非常抱歉，作为一个 AI 语言模型，我不能帮助您完成这个请求」 | 「这个请求我无法处理。」——一句话，不自我介绍 |
| 免责套话在每条回答下堆叠 | 每条回答后面都跟一句「以上内容由 AI 生成，仅供参考，请谨慎核实」 | 固定在页面一处（如底部）出现一次，不逐条重复 |
| 不确定性写成营销感叹号 | 「放心大胆用！AI 全程智能守护~」 | 删掉感叹号和营销词，平实陈述能力边界 |
| 工具调用状态暴露开发者细节 | 「Calling function: search_web(query="...")」 | 「正在联网搜索」 |
| 引用来源裸链接堆砌 | 参考资料：https://a.com https://b.com https://c.com | 「[1] 来源：A 网站标题」可点击，带来源名 |
| 停止后加拟人化收尾 | 「好的，这一轮先到这里～」 | 「已停止生成。」 |
| 滥用"大模型""智能"做定语营销 | 「大模型加持的智能摘要，体验飞跃」 | 「自动生成摘要」，功能名不堆形容词 |
| 把配额错误显示成技术异常 | 「Error 429: Too Many Requests」直接露给用户 | 「请求过于频繁，请稍后重试」 |
| 安全拦截写成说教 | 「我们鼓励健康、积极、向上的交流方式，请您遵守社区准则后重新尝试」 | 「这个请求我无法处理，换个问法试试。」 |
| 确定性语气两极化 | 同一产品里有的地方「一定是」，有的地方「也许大概可能」 | 统一分级词表：可能 / 通常 / 已核实 / 无法确认，不额外发明新说法 |
| 标识文案每次变着花样写 | 有的页面写「AI生成」，有的写「由人工智能创作」，有的写「机器人作答」 | 全站一种标准措辞，写进术语表 |

## 9. 改前 → 改后

| 改前 | 改后 | 问题 |
|---|---|---|
| 非常抱歉，作为一个 AI 语言模型，我无法满足您的这个请求，请您谅解。 | 这个请求我无法处理。 | 拒答套话、自我介绍、多余道歉 |
| Error: insufficient_quota | 本月额度已用完，请升级套餐或等待额度重置。 | 把内部错误码直接显示给用户 |
| Rate limit reached for requests | 请求过于频繁，请稍后重试。 | 开发者向错误信息面向用户展示 |
| 本回答由 AI 智能生成，内容仅供参考，可能存在不准确之处，请以实际情况为准，感谢您的理解与支持！ | AI 生成内容，可能不准确。 | 冗长、感叹号、营销式收尾、每条重复 |
| Calling tool: get_weather(city="Beijing") | 正在查询北京天气 | 暴露函数签名 |
| 参考资料：[1] https://a.com [2] https://b.com | [1] 来源：A 网站 · [2] 来源：B 网站（可点击） | 裸链接、不可读 |
| 确定要继续吗？ | 这将删除「2026年报.xlsx」中的 3 个工作表，且无法撤销。删除 / 取消 | 确认框没说清楚删什么、能不能撤销 |
| Are you sure? | This will permanently delete 3 sheets in "2026 Annual Report.xlsx." This can't be undone. Delete / Cancel | 同上，英文版 |
| 好的，这一轮先聊到这里，有其他问题随时找我哦~ | 已停止生成。 | 拟人化收尾、卖萌 |
| 额度告急！再不升级就用不了啦！ | 本月额度已用 90%，预计 3 天后用完，可提前升级。 | 制造焦虑、没给具体数字和下一步 |
| Your usage is running low! Upgrade now! | You've used 90% of this month's quota — it'll run out in about 3 days. Upgrade anytime. | 同上，英文版 |
| 是否允许改进我们的产品和服务？ | 允许将对话内容用于改进模型（默认开启，可随时关闭；关闭后仅影响后续新对话）。 | 笼统不说默认值和生效范围 |
| 我们鼓励健康、积极、向上的交流方式，请您遵守社区准则后重新尝试提问。 | 这个请求我无法处理，换个问法试试。 | 说教式拒答 |
| 这段对话内容太多了，系统处理不了。 | 这段对话过长，已处理不了更多内容；可以开始新对话，或说明要保留的部分。 | 只说问题，没给下一步 |
| 本次回答耗时约 20-30 秒，请耐心等待。 | （不显示固定时长，用流式输出本身展示进度） | 给模型生成编造精确时长，经常不准 |
| 一键换脸，想换谁换谁，开启你的奇趣之旅！ | 生成的视频将合成你上传的人脸，且会带有「AI 合成」标识；请确保你有权使用这张照片。 | 隐去深度合成的同意和标识要求，包装成纯娱乐 |
| Face swap, have fun with it! | This video will use the face from your uploaded photo and will carry an "AI-synthesized" label. Make sure you have the right to use this photo. | 同上，英文版 |
| 很抱歉无法处理你的请求，如有疑问请联系客服。 | 如果你认为这是误判，可以点击反馈，我们会人工复核。 | 拒答后没有可操作的申诉入口，「联系客服」太泛 |
| 当前模型：GPT-4-turbo-2024-04-09，32K 上下文，温度 0.7 | 当前模型：擅长复杂推理，速度较慢 | 把内部参数当成用户可读的能力说明 |
| （原模型过载时悄悄切到备用模型，不提示） | 已切换到备用模型以保持响应，结果可能略有差异。 | 悄悄降级，用户以为还在用原来的模型 |

## 10. 审查时加查的项

- [ ] 生成内容是否按标识办法 / EU AI Act 要求做了显式标识，导出 / 分享 / 下载路径是否保留标识
- [ ] 不确定性 / 幻觉提示是否只在合适位置出现一次，没有在每条回答下重复套话
- [ ] 智能体执行不可逆操作前的确认文案是否具体到对象、范围、可否撤销，确认按钮是否写了动作本身而不是"确定"
- [ ] 拒答文案是否简短、不说教，需要时给出了可操作的替代方向，不是空泛的"请遵守规定"
- [ ] 速率限制 / 配额 / 余额不足三种报错是否分清楚了"重试能不能解决"，各自给了对应的下一步
- [ ] token / 额度 / 计费相关文案的数字是否和实际计费口径一致，不是把估算值当成精确值显示
- [ ] 训练数据使用 / opt-out 开关文案是否说清楚了默认状态和生效范围（新对话 / 历史记录）
- [ ] 工具调用状态文案是否写成了用户能懂的动作，而不是函数名、参数或内部状态机节点名

## 11. 台港市场差异

- 台湾：《人工智慧基本法》已于 115 年（2026 年）1 月 14 日公布施行，主管机关是国科会。它是原则法，没有逐字规定标识用语：
  - 第 4 条第 5 款要求「人工智慧之產出應做適當資訊揭露或標記」。
  - 第 5 条规定，被认定为高风险应用的产品或系统，「應明確標示注意事項或警語」。
  - 具体子法还在制定中。<https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=H0160093>
- 台湾广告：网路广告平台刊登或推播的广告，如果使用深度伪造技术或人工智慧生成的个人影像，必须在广告中揭露（《詐欺犯罪危害防制條例》第 31 条第 1 项第 4 款）。<https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=D0080226&flno=31>
- 香港：没有 AI 专门立法。数字政策办公室的《香港生成式人工智能技術及應用指引》（1.1 版，2025 年 12 月）不具法律约束力，是建议性质。指引没有规定全站统一的标识文字或图标样式；媒体报道的理解是，针对深伪影像、财务资料等高风险内容，建议开发者预设浮水印标识以便追溯和明确责任，不是对所有 AI 生成内容都要求固定用语。<https://www.digitalpolicy.gov.hk/tc/our_work/data_governance/policies_standards/ethical_ai_framework/doc/HK_Generative_AI_Technical_and_Application_Guideline_tc.pdf>（原文为扫描版 PDF，中文内文未能逐字提取核对，以上转述自 <https://unwire.hk/2025/04/17/aiguidelines-hong-kong/ai/> 等媒体报道，建议正式引用前核对指引原文对应段落）
- 第 6 节说的「显式标识／隐式标识」是大陆《人工智能生成合成内容标识办法》的法定用语，台港不适用。繁体界面写「AI 生成」「由 AI 產生」即可，全站一种。
- 个资：台湾适用《個人資料保護法》（蒐集时依第 8 条告知），香港适用《個人資料（私隱）條例》（Cap. 486，保障資料第 1 原則），不是大陆《个人信息保护法》。用对话内容训练模型时，要按这两部法告知用途。
