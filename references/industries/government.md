## 1. 什么时候用这份

信号（命中任意两条就用；只命中一条时，结合用户的话判断）：

- 代码 / 依赖：`govuk-frontend`、`@uswds/uswds`、国密 SDK（`sm-crypto`、`gmssl`）、实名认证 / 人脸核身 SDK（支付宝 / 腾讯云 `faceid`、`webank-facelivenessid`）、电子证照 SDK、字段或变量名里出现 `shixiang`（事项）、`banjian`（办件）、`shouli`（受理）、`banjie`（办结）、`zhengwu`（政务）
- 目录 / 文件名：`government/`、`gov-portal/`、`egov/`、`zhengwu/`、`shenpi/`（审批）、`xuke/`（许可）、`shenbao/`（申报）、`yiwangtongban/`（一网通办）、`shiyixiang/`（事项）
- 界面里的词：受理、审核中、已办结、不予受理、补正、退件、材料清单、办事指南、承诺时限、法定时限、容缺受理、告知承诺、实名认证、人脸识别 / 人脸核身、电子证照、网号 / 网证、长辈版、适老化、无障碍、异地可办、全国通办、一次性告知、好差评
- 用户的话：「政务服务平台」「政务 App」「政府网站」「小程序办事」「审批系统」「12345 热线」「适老化改造」「一网通办」

和别的行业重叠时：

- **政府 + 金融**（政务缴费、社保公积金）：先按本节的受理 / 时限 / 救济路径硬约束走，再叠金融行业的金额、账户、流水格式规则。
- **政府 + 医疗**（医保服务平台）：状态词（受理 / 审核中 / 办结）按本节；涉及病种、诊断、用药的措辞按医疗行业规则（不下诊断类判断、不替代医嘱）。
- **政府 + AI**（政务智能客服、政务大模型问答）：先满足本节「不许模糊法定义务」「不许替公民下结论」的硬约束，AI 产品的免责提示规则作为补充，不能用「仅供参考」冲淡法定告知内容。

## 2. 语气和人格

一句话定调：像政务服务窗口工作人员口头告诉你下一步要做什么，而不是把文件抬头念给你听——权威、准确，但不打官腔。

- **人称统一用「您」**，覆盖 `principles.md` 「你 / 您全站统一、不规定选哪个」的默认规则：政务场景面向不特定公民，没有产品那种熟客关系，全站只用「您」，包括按钮、空状态、报错。
- **正式程度高于一般产品、低于公文**：不出现「兹」「特此通知」「现将有关事项通知如下」「望周知」这类公文虚词（这是 GB/T 9704 规定的公文体式，不是给界面用的）；但也不能松到网络用语的程度。
- **不用感叹号、不用 emoji、不开玩笑**：公共服务场景的严肃性要求，适老化 / 无障碍改造规范也要求「避免采用专业词语或网络新词语作为访问目标和结果表达」（工信部《关于进一步抓好互联网应用适老化及无障碍改造专项行动实施工作的通知》），装饰性符号同样不读给语音播报用户听。
- **不怀疑、不预设用户有问题**：对材料、身份的任何负面判断必须有明确依据再写，不能写「您的材料涉嫌造假」这类未经认定的指控性措辞；查实前只能客观描述不一致之处。
- **「抱歉」只留给系统 / 机构方的责任**：平台故障、系统维护导致的延误可以说「抱歉，系统维护中」；公民材料不全、证件过期这类不是平台的错，不道歉，直接说清楚缺什么、怎么补。
- **权威但不推诿**：报错和驳回要说清楚谁审核的、依据什么、下一步找谁，不用「系统繁忙」「请稍后再试」打发本该给出法律依据的场景。
- **区分「收到」和「受理」**：提交成功只是收到，材料齐全并进入审查才叫受理；界面在这两个时间点之间不能都显示同一句「处理中」，否则用户不知道自己卡在哪一步。

## 4. 术语和叫法

| 用 | 不用 | 说明 |
|---|---|---|
| 受理 | 已提交、已收到 | 法定状态：材料齐全、符合法定形式，正式进入审查 |
| 已收到 / 已提交 | 已受理 | 用户点击提交后、系统还没核验材料是否齐全时的状态，不能提前用「受理」 |
| 审核中 | 处理中、办理中 | 和「受理」「已收到」是不同阶段，不要合并成一个笼统的「处理中」 |
| 已办结 | 已完成、已处理 | 法定终态，办结不等于通过——结果可能是准予、不予、退回，办结只表示流程走完 |
| 不予受理 | 申请失败、提交失败 | 对应可复议 / 可诉的法律状态，必须带理由和救济路径，不能写成一般性的「失败」 |
| 补正 | 修改材料、重新提交 | 《中华人民共和国行政许可法》第三十二条规定的「一次性告知补正」概念，不是普通的「改一下重传」 |
| 退件 | 打回、驳回 | 指退回要求补正，不是终局决定；「驳回」用于最终不予批准的场景，两者不能混用 |
| 材料清单 | 所需文件、资料列表 | 政务场景固定叫法，按「名称 / 类型 / 份数 / 是否需电子件」结构化列出 |
| 办事指南 | 使用说明、帮助文档 | 政务服务标准化规定的法定文种，有固定要素结构 |
| 承诺（办结）时限 | 处理时间、预计时间 | 机构自我承诺的时限，通常短于法定时限，不能和法定时限混着说 |
| 法定时限 | 最长时间、截止时间 | 来自法律法规的上限，是硬约束，不随机构效率变化 |
| 实名认证 | 身份验证、登录验证 | 特指与公民身份信息库比对的认证，比普通账号登录验证更严格 |
| 人脸识别 / 人脸核身 | 刷脸 | 「刷脸」可以留在按钮等口语化场景，说明性文字一律用「人脸识别」 |
| 容缺受理 | 先收下材料 | 法定概念：允许次要材料暂缺、承诺补交的情形下先予受理，不是普通「宽松处理」 |
| 告知承诺（制） | 自行保证、自证 | 固定法律制度名称，不能自造说法 |
| 申诉 | 投诉 | 对认定事实有异议走申诉；对服务态度 / 效率不满走投诉，两条路径不同。平台有正式入口名的跟随入口名，如交管 12123 的「申请陈述和申辩」（见第 3 节） |
| 行政复议 | 上诉、申请复核 | 《中华人民共和国行政复议法》规定的行政系统内救济途径，和司法程序（诉讼）是两回事 |
| 行政诉讼 | 打官司、起诉政府 | 正式法律程序名称，界面提示用全称或「向人民法院提起诉讼」 |
| 事项 | 业务、服务、功能 | 政务服务编码体系（GB/T 39554）里的法定单位；界面可写「该事项」「办理该事项」，不要和产品「功能」混用 |
| 一次性告知 | 多次补充材料的说明 | 《行政许可法》要求的服务承诺：材料不全要一次说清全部缺项，不能办一次说一次 |
| 适老化 | 老年版、老人模式 | 官方规范固定用词「适老化」；具体入口名称（长辈版 / 长者版 / 关怀模式）跟随各平台已有命名，不要自造新词 |
| 无障碍 | 残障版、盲人模式 | 《信息无障碍》标准固定用词，不用带歧视色彩的指代 |
| 电子证照 | 电子版证件、证件照片 | 政务服务标准概念，与实体证照具有同等法律效力，不是普通的证件扫描件 |
| 网号 / 网证 | 统一身份账号 | 国家网络身份认证公共服务的法定名称，用于减少反复人脸核验 |
| 异地可办 | 外地也能办 | 指特定事项允许在非户籍地办理，范围通常小于「全国通办」，两者不能互换 |
| 全国通办 | 到处都能办 | 范围覆盖全国的事项，比「异地可办」范围更大，写之前要核对该事项的实际覆盖范围 |
| 窗口 / 综合窗口 | 柜台、服务台 | 政务服务中心的标准叫法，线上线下要一致 |
| 好差评 | 满意度调查、评分 | 政务服务「一次办好」配套的评价机制的固定叫法 |
| 办件 | 工单、任务、单据 | 政务系统内部对一次申请的统称，是开发者 / 后台用词，不进用户界面——用户看到的是「您的申请」「您的 XX 事项」 |
| 统一社会信用代码 | 营业执照号、企业代码 | 企业身份的法定标识，固定 18 位，界面校验提示要用全称 |
| 电子印章 | 盖章扫描件、公章图片 | 具有法律效力的电子签章，和普通图片扫描件不是一回事 |
| 联审联办 | 合并办理、一起审 | 多部门协同审批的固定叫法，涉及「一件事一次办」类场景 |
| 首违不罚 | 第一次不罚款、警告一下 | 《行政处罚法》规定的轻微违法免罚情形的固定说法，不能随意替换成口语 |
| 失信惩戒 | 拉黑、上黑名单 | 社会信用体系的正式用语，和内部「黑名单」的随意说法不同，涉及信用修复路径时要用这个词 |
| 信用修复 | 洗白、恢复信誉 | 失信惩戒解除的法定程序名称，有固定申请条件和流程，不是口语化的「洗白」 |

## 5. 按元素写

**按钮**：政务场景危险操作少，但「提交申请」一旦点击通常进入不可逆流程，要写动作本身而不是「确定」。

- 用：「提交申请」/「确认提交，进入审核」；不用：「确定」/「Submit」（裸词）。
- 不用网络用语包装严肃操作：「一键搞定」「冲」。

**表单标签和校验**：长表单按 GOV.UK 一问一页的思路拆分步骤，减少一页信息量；必填标注遵循中文政务行业既有惯例——用红色星号 `*` 并配文字「（必填）」双重提示（不能只靠颜色，适老化 / 无障碍要求文字和颜色同时存在）。这里是和 GOV.UK「不用星号」相反的行业惯例，跟随中文政务产品已有约定，不要套用英文设计系统的做法。

- 中：姓名 *（必填）／ 身份证号 *（必填，18 位）
- 英：Full name (required) / National Insurance number — Enter it in the correct format

**资格问题（您是否……）**：资格认定类问题要用法规里的认定条件原文提问，不能简化成模糊的是非判断；用户答不上来时要给出「不确定」或指向资格自测工具的路径，不能强迫二选一，涉及残障、低保等敏感资格的问题尤其要给「不便透露」选项（参照 GOV.UK equality-information 模式，原文给出 *"Prefer not to say"*）。

- 中：您是否属于《社会保险法》规定的灵活就业人员？不确定可先使用「资格自测」。
- 英：Are you self-employed under the Social Insurance Law? If you're not sure, use the eligibility checker first.
- 不用：您是不是灵活就业的？（口语化、没有法规依据，答案无法支撑后续判定）

**下拉选项 / 证件类型**：证件类型、婚姻状况这类枚举项要用法律 / 户籍系统里的正式名称，不能简写或口语化，全站同一个证件在不同表单里用词必须一致。

- 用：证件类型：居民身份证 / 港澳居民来往内地通行证 / 护照
- 不用：证件：身份证 / 回乡证 / 护照（俗称混进正式表单）

**报错**：结构是「问题 + 法定或可执行的下一步」，比普通产品更严格——重试解决不了的，必须说明具体依据和办理渠道，不能用「请重试」打发。

- 中：身份证号格式不对，请输入 18 位身份证号。
- 英：Enter a National Insurance number in the correct format（GOV.UK 原文示例）
- 中：材料需要补充。缺少：房产证明复印件（原件已核验）。请在 15 个工作日内通过「补充材料」上传，逾期未补将视为撤回申请。

**空状态**：现状 + 下一步，不用拟人化或营销语气。

- 中：您还没有办理记录。前往「办事大厅」选择事项开始办理。
- 英：You have not submitted any applications yet. Start a new application from the service directory.

**确认框**：说清提交后能不能改、审核期间状态如何。

- 中：提交后材料将进入审核，审核期间无法修改；如需变更，请先撤回本次申请。
- 英：Once submitted, you cannot change your answers. To make changes, withdraw this application first.

**状态标签**：固定四态，不自造同义词——受理 / 审核中 / 已办结 / 不予受理。「已办结」下还要带结果（准予 / 不予 / 退回），不能让办结看起来等于通过；需要更细颗粒度的行业（如医保，见第 3 节）可以在四态基础上拆分子状态，但子状态要能映射回这四态中的一个，不能另起一套。

**通知 / 推送**：格式固定为「结果 + 下一步 + 时限」。

- 中：您的灵活就业社保缴费申请已通过审核，请于 10 月 25 日前完成首次缴费，逾期需重新申请。
- 英：Your application has been approved. Complete your first payment by 25 October or you will need to reapply.

**进度**：区分法定时限和承诺时限，给出当前进度，不用「马上好」「快了」这类无法验证的表述。

- 中：法定办结时限 20 个工作日，承诺时限 10 个工作日，当前第 3 个工作日。
- 英：Legal deadline: 20 working days. Service commitment: 10 working days. Day 3 of 10.

**引导 / 首次使用**（实名认证 / 人脸识别授权）：必须说明用途、是否留存、能否拒绝，不能用营销话术包装；同意勾选不能默认勾上。

- 中：需要进行人脸识别以核实您的身份，识别结果仅用于本次认证，不会用于其他用途。
- 英：We need to verify your identity using facial recognition. This is only used to confirm it's you, and is not used for any other purpose.
- 不用：「一键认证，畅享便捷服务」。

**保存进度（中途保存 / 草稿）**：长表单要能中途保存，提示要说明保留多久、超期会怎样，不能只说「已保存」。

- 中：草稿已保存，为您保留 30 天；超过 30 天未提交将自动清除，需要重新填写。
- 英：Your answers have been saved. They will be available for 30 days, after which you will need to start again.

**服务中断 / 系统维护**：这是少数可以用「抱歉」的场景（系统方责任），要给出具体恢复时间，并说明中断前的数据是否保留。

- 中：抱歉，系统维护中，预计 10 月 17 日 9:00 恢复。维护期间您已填写的内容已保存，恢复后可继续填写。
- 英：Sorry, the service is unavailable. You will be able to use the service from 9am on 17 October. Anything you had already entered has been saved.

**语言切换 / 适老化入口**：入口文字用该平台已有的命名（长辈版 / 长者版 / 关怀模式 / 无障碍版 / 英文版），不要为了统一风格自造一个新词；入口位置要固定、全站一致，不要有的页面在首页右上角、有的页面藏在个人中心三级菜单里。

- 中：长辈版 ／ 无障碍 ／ English
- 不用：温暖模式 ／ 简易版（和平台实际入口名称不一致时会让用户找不到自己用过的模式）

**帮助说明（办事指南）**：按法定要素结构化呈现，不要写成一段连续说明文字——事项名称、受理条件、申请材料、办理流程、办理时限、收费标准、咨询电话分开列。

## 6. 合规和硬约束

**必须出现：**

- 不予受理 / 驳回必须写明理由 + 法律依据 + 救济途径（复议 / 诉讼）及起算时间点。
- 材料不全必须一次性列出全部缺项（《中华人民共和国行政许可法》第三十二条「一次性告知」原则），不能分批退件。
- 收集人脸、指纹等生物识别信息前必须单独说明用途、是否留存，并取得单独同意（《中华人民共和国个人信息保护法》第二十八条将生物识别信息列为敏感个人信息，第二十九条要求单独同意，不能和其他授权打包勾选）。
- 涉及收费的事项必须写明收费依据或明确「不收费」，不能只写金额不写依据。
- 适老化 / 无障碍版本正文字号不小于 18dp/pt（工信部《关于进一步抓好互联网应用适老化及无障碍改造专项行动实施工作的通知》），且不得出现广告内容及插件、不得出现随机广告弹窗。
- 重大处罚类事项（如吊销证照）要提示公民享有陈述、申辩的权利，达到听证条件的要提示可以申请听证（《中华人民共和国行政处罚法》相关规定）。
- 线上办理渠道之外必须保留人工 / 线下办理入口的指引，不能把线上作为唯一渠道——这是无障碍 / 适老化整改的底线要求，不是锦上添花的选项。

**不许出现：**

- 任何暗示加急付费、走关系能加快流程的措辞。
- 未经认定的指控性表述（「涉嫌造假」「恶意申请」），这类判断只能在有明确调查结论后使用。
- 用「建议」「最好」替代法定义务的措辞——法定该交的材料、该缴的费不能写成可选项。
- 绝对化承诺：「彻底解决」「永久有效」「马上办好」，政务服务不能对无法控制的审批结果打包票。
- 适老化版面里出现专业术语或网络新词（工信部通知原文：「避免采用专业词语或网络新词语作为访问目标和结果表达」）。

**必须的格式：**

- 日期用阿拉伯数字「2026年10月16日」，不用「二〇二六年十月十六日」这种更正式场合（领导批示、合同用印落款）的写法——这点常被误解：GB/T 9704《党政机关公文格式》对正文成文日期本身规定的就是阿拉伯数字、年份写全、月日不编虚位，全汉字写法是另一套落款 / 用印惯例，不是界面该模仿的对象。
- 时限要写清单位是「工作日」还是「自然日」，两者不能混用、不能省略。
- 身份证号、统一社会信用代码等证件号出现校验提示时要给出标准位数（18 位身份证号、统一社会信用代码 18 位）。
- 金额用「元」加阿拉伯数字，正式凭证里的大写金额不进入界面提示文案。

## 7. 高风险场景

**身份核验失败（实名认证 / 人脸识别不通过）**：必须给出失败原因类别（光线 / 角度 / 信息不一致）和人工核验 / 线下办理渠道，不能只说「验证失败，请重试」。

- 中：人脸识别未通过，可能原因：光线不足或未正对摄像头。请重试，或携带身份证前往属地政务服务中心人工核验。

**不予受理 / 驳回**：法律依据 + 救济途径 + 期限起算点三者缺一不可。

- 中：您的《个体工商户设立登记》申请不予受理。原因：经营场所证明材料与登记地址不一致。如对本决定有异议，可自收到本通知之日起 60 日内向属地市场监督管理局申请行政复议，或 6 个月内向有管辖权的人民法院提起行政诉讼（复议期限依据修改后的《中华人民共和国行政复议法》，具体条号以生效文本为准）。

**罚款 / 缴费类（交通违法、滞纳金）**：金额、截止日期、逾期后果必须精确，不能用约数。

- 中：罚款 200 元，请于 15 日内缴纳；逾期每日按罚款数额 3% 加处罚款，加处罚款不超过罚款数额。

**纳税申报截止日期（个人所得税汇算清缴）**：窗口期、分段规则（是否需要预约）、逾期的法律后果要分开写清楚，不能只给一个笼统日期。

- 中：个人所得税综合所得年度汇算办理期为 3 月 1 日至 6 月 30 日；3 月 1 日至 20 日需预约办理，3 月 21 日起无需预约。逾期未申报的，可能产生滞纳金并影响纳税信用记录。（日期按当年国家税务总局公告填写，不要沿用往年。）

**材料补正 / 容缺受理**：告知截止时间和逾期后果。

- 中：以下材料允许容缺后补：房产证明。请在 10 个工作日内补交，逾期未补将按原申请材料重新审查，可能影响办理结果。

**老年人 / 无障碍用户**：关键信息不能仅靠颜色或图标传达，必须配文字；长辈版要简化流程、避免行话，不是只放大字号。

- 中（反例）：红色圆点表示未通过 → 改为：未通过（配红色圆点作为辅助视觉）。

**多语言 / 少数民族语言**：译文和中文版不一致时以中文为准，界面要声明这一点，不能让译文单独承担法律效力。

- 中：本页面藏文译文仅供参考，与中文内容不一致时以中文为准。
- 依据：《中华人民共和国民族区域自治法》关于民族自治地方国家机关执行职务时依照本民族自治地方通用的一种或者几种语言文字的相关规定。

**个人信息 / 生物特征数据使用提示**：必须说明收集目的、留存时长、可否拒绝及拒绝的后果。

- 中：本次人脸识别结果不会留存，仅用于本次身份核验；如您拒绝，可改为携带身份证到现场办理，但无法使用线上通道。

**失信惩戒 / 信用修复**：列入失信名单要写明依据、影响范围（限制哪些事项）和修复路径，不能只说「已被列入黑名单」却不给出路。

- 中：您已被列入税收严重失信主体名单，将在办理贷款、招投标等事项时受到限制。满足信用修复条件（已缴清税款、滞纳金和罚款满 1 年）后，可申请信用修复。

## 8. 这个行业的 AI 腔和坏写法

| 坏写法 | 例子 | 改法 |
|---|---|---|
| 把公文开头套进提示 | 「为进一步做好相关工作，现将有关事项通知如下」 | 直接说内容：「您的申请已通过审核」 |
| 公文虚词混进 App | 「兹证明」「特此告知」「望周知」 | 删，用日常书面语说结果 |
| 法定时限和承诺时限说混 | 「一般 3 天左右能办完」 | 分开写：「法定时限 20 个工作日，承诺时限 10 个工作日」 |
| 把不予受理美化成失败 | 「很遗憾，您的申请未能通过」 | 「不予受理。原因：……如有异议，可申请行政复议」 |
| 混淆「收到」与「受理」 | 提交成功和材料齐全进入审查显示同一句「处理中」 | 提交成功显示「已提交，正在核验材料」，材料齐全后再显示「已受理」 |
| 无依据的指控 | 「您提交的材料涉嫌造假」 | 「您提交的《房产证明》与登记信息不一致，请核实后重新提交」 |
| 感叹号 / emoji 营造亲切感 | 「恭喜您！审核通过啦🎉」 | 「审核已通过」 |
| 把实名认证包装成营销话术 | 「一键认证，畅享便捷服务」 | 「需要进行人脸识别以核实您的身份，结果仅用于本次认证」 |
| 把法定权利包装成功能卖点 | 「尊享专属申诉通道」 | 「对处理结果有异议，可在此申请复核」——申诉 / 复议是法定权利，不是增值功能 |
| 绝对化承诺 | 「彻底解决您的诉求」「马上办、永久有效」 | 给出具体时限和责任部门，不做无法兑现的承诺 |
| 回避责任的被动句 | 「您的申请未能通过」 | 「XX 部门审核后未予批准，原因：……」 |
| 适老化只改字号不改措辞 | 长辈版字体放大但正文仍是「依据相关规定，经审核，予以办理」 | 同时简化句式：「审核已通过，材料齐全」 |
| 网络热词套进政务场景 | 「冲就完事了」「绝绝子」 | 删，用平实陈述 |
| 多语言机器直译丢失法律含义 | 「行政复议」被直译成不对应法律程序的日常词 | 法律术语的多语言版本需专业核对，不能用通用翻译引擎直出 |
| 资格问题强迫二选一 | 「您是不是灵活就业的？」只给「是 / 否」 | 加「不确定，先测一下」的第三选项，敏感资格问题再加「不便透露」 |

| 红色圆点：未通过 | 未通过（配红色圆点辅助标识） | 仅靠颜色传达状态，无障碍用户和色盲用户看不出来 |

| 罚款请尽快缴纳。 | 罚款 200 元，请于 15 日内缴纳；逾期每日加处罚款数额 3%，上限为罚款数额。 | 金额、期限、逾期后果都缺失 |
| 为进一步做好便民服务工作，现将有关事项通知如下：您的申请已受理。 | 您的申请已受理。 | 公文开头套进通知 |
| 本页面藏文内容由系统翻译生成。 | 本页面藏文译文仅供参考，与中文内容不一致时以中文为准。 | 没有声明译文和中文版的法律效力关系 |
| 您的申请正在处理中。（提交后 5 秒和材料审核通过后显示同一句） | 已提交，正在核验材料是否齐全 → 材料齐全，已受理，审核中 | 「收到」和「受理」是两个法律阶段，不能用同一句模糊带过 |
| 您是不是灵活就业的？ | 您是否属于《社会保险法》规定的灵活就业人员？不确定可先使用「资格自测」。 | 口语化判断没有法规依据，且没给「不确定」的出路 |
| 已保存。 | 草稿已保存，为您保留 30 天；超过 30 天未提交将自动清除。 | 没说明保留多久、超期会怎样 |
| 系统繁忙，请稍后再试。（系统维护期间，用户已填内容全部丢失） | 抱歉，系统维护中，预计 10 月 17 日 9:00 恢复，您已填写的内容已保存。 | 没给恢复时间，也没说明数据是否保留 |

## 10. 审查时加查的项

- [ ] 状态词是否用了固定四态（受理 / 审核中 / 已办结 / 不予受理），「已办结」是否带了具体结果（准予 / 不予 / 退回），「已收到 / 已提交」和「受理」是否分开、没有提前显示「已受理」？
- [ ] 不予受理 / 驳回是否同时带了理由、法律依据、救济途径（复议 / 诉讼）和期限起算点？
- [ ] 承诺时限和法定时限是否分开写、单位（工作日 / 自然日）是否明确，没有混用？
- [ ] 材料不全的提示是否一次性列出了全部缺项，而不是一条一条分批退件？
- [ ] 人脸识别 / 实名认证前是否说明了用途、是否留存、能否拒绝及拒绝的后果，是否做成了默认勾选？资格认定类问题是否给了「不确定」或「不便透露」的出路，没有强迫二选一？
- [ ] 必填项是否同时有颜色和文字两种提示，没有只靠红色星号或红色圆点传达状态？
- [ ] 人称是否全篇统一用「您」，是否避免了公文虚词（兹、特此、望周知）、网络热词和营销腔（一键、畅享、绝绝子）？
- [ ] 适老化 / 长辈版正文字号是否不小于 18dp/pt，是否没有广告或插件，语言是否真正简化而不是只放大字号？线上渠道之外是否保留了人工 / 线下办理入口的明确指引？
- [ ] 多语言版本是否声明了与中文版的效力关系（以中文为准）？中途保存 / 草稿提示是否说明了保留多久、超期后果？系统中断提示是否给了具体恢复时间、说明了数据是否保留？
- [ ] 费用、时限、证件位数等数字是否和法规原文或后端实际值核对过？

## 11. 台港市场差异

适用场景：给台湾（zh-TW）或香港（zh-HK）的政府网站、电子化政府服务、公共服务 App 写文案。上面第 6、7 节引用的是大陆法规，到台港全部换成当地依据。通用换词见 `locale-zh-hant.md`，这里只列政府场景特有的差异。

个资：台湾适用《個人資料保護法》（蒐集时依第 8 条告知），香港适用《個人資料（私隱）條例》（Cap. 486），都不是大陆《个人信息保护法》。

### 台湾

**必须出现的话：**

- 蒐集个资时，告知六项内容：机关名称、蒐集目的、个资类别、利用的期间／地区／对象／方式、当事人依第 3 条可行使的权利和方式，以及当事人可以选择不提供时，不提供对其权益有什么影响（《個人資料保護法》第 8 条第 1 项）。公务机关执行法定职务所必要的情形可以免告知（同条第 2 项），但界面上照样建议写明用途。<https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=I0050021&flno=8>
- 驳回、不予核准这类书面行政处分，要写明主旨、事实、理由、法令依据，并说明「救濟方法、期間及其受理機關」（《行政程序法》第 96 条第 1 项第 2、6 款）。<https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=A0030055&flno=96>
- 救济期间写清楚起算点：诉愿「應自行政處分達到或公告期滿之次日起三十日內」提起（《訴願法》第 14 条）。不要照搬大陆的「60 日内申请行政复议」。<https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=A0030020&flno=14>
- 网站要放无障碍标章。各级政府及附属机关（构）、学校的网站，「應通過第一優先等級以上之無障礙檢測，並取得認證標章」（《身心障礙者權益保障法》第 52-2 条）。法律条文本身只要求「第一優先等級以上」（即 A 级）；具体检测依据的《網站無障礙規範》把 AA 级（须通过第一、二优先等级共 68 项检测码）定为政府网站标章实务的主流要求，新建或改版网站通常直接按 AA 级设计。<https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=D0050046&flno=52-2>
- 检测依据是数位发展部《網站無障礙規範》，配套的是《各級機關機構學校網站無障礙檢測及認證標章核發辦法》。新版规范对齐 WCAG 2.2，115 年 5 月 29 日修正、115 年 11 月 30 日生效，新增如「2.5.8 目標尺寸（最小）」等 AA 级成功准则（官网有 Cloudflare 拦截无法直接取得正文，日期与对齐 WCAG 2.2 的说法经多个独立技术讨论来源交叉确认，未逐字核对规范原文）。服务网：<https://accessibility.moda.gov.tw/>；规范原文：<https://law.moda.gov.tw/LawContent.aspx?id=GL000006>
- 网站营运参考数位发展部《政府網站服務管理規範》，共 11 条原则、32 项参考指引，含个资保护（確認符合資通安全管理法、個人資料保護法等規定）、无障碍（遵循網站無障礙規範及聯合國身心障礙者權利公約）、资料开放（以開放源碼工具與系統為優先）等。<https://moda.gov.tw/digital-affairs/digital-service/guide/380>

**不许出现的话：**

- 大陆政务词，必须换成台湾制度名：
  - 身份证 → 國民身分證（「分」不是「份」）
  - 户口本 → 戶口名簿
  - 社保 → 勞保／健保，按险种分开写
  - 医保卡 → 健保卡
  - 公积金：台湾没有对应制度，退休金写「勞工退休金（勞退）」
  - 个税 → 綜合所得稅
  - 行政复议 → 訴願
  - 政务服务中心 → 戶政事務所／區公所／各機關服務台，写具体机关
  - 实名认证 → 身分驗證，或写具体方式，如「自然人憑證」
- 「一网通办」「最多跑一次」这类大陆政务口号，台湾用户看不懂，直接删掉或改写成具体做法。

**格式要求：**

- 身分證統一編號是 10 码：1 个英文字母加 9 个数字。校验提示写「請輸入 10 碼身分證統一編號（第 1 碼為英文字母）」，不要写「18 位」。
- 政府机关惯用民国纪年（「115 年 10 月 16 日」）。同一站内要么全用民国，要么全用西元，不能混用；表单可以标「民國年」提示（惯例，未见成文规定）。
- 时限写「工作天」或「日」，单位同样不能省。
- 人称统一用「您」；公文虚词「台端」「爰」「希照辦」不要进界面。

### 香港

**必须出现的话：**

- 直接收集个人资料时，在收集当时或之前告知：收集目的、资料可能转移给哪类人、提供资料是必须还是自愿，以及不提供会有什么后果；还要告知资料当事人有权要求查阅及改正，以及向谁提出（Cap. 486 附表 1 保障資料第 1 原則第 (3) 款）。这些内容通常写成「收集個人資料聲明」。<https://www.elegislation.gov.hk/hk/cap486!zh-Hant-HK>；私隐公署指引：<https://www.pcpd.org.hk/chinese/publications/files/GN_picspps_c.pdf>
- 无障碍：政府网站（存档资料除外）自 2013 年 1 月 1 日起须符合 W3C WCAG 2.0 或以上 AA 级；政府流动应用程式须在 2019 年 7 月前具备无障碍功能（数字政策办公室 FAQ）。WCAG 2.2 目前不是强制要求：FAQ 原文是「鼓励」机构酌情采纳 WCAG 2.1／2.2 的新成功标准，改版沿用 WCAG 2.0 AA 这条法定底线即已合规，采用 2.2 属于加分而非义务——此前「改版须用 WCAG 2.2 AA」的说法不准确，已更正。<https://www.digitalpolicy.gov.hk/en/our_work/digital_infrastructure/digital_inclusion/accessibility/faq/>
- 政府服务要有中英文两个版本（中文和英文都是法定语文），两版内容要对应，不能中文写了的条件英文漏掉。

**不许出现的话：**

- 大陆和台湾的制度词都不要用，换成香港的叫法：
  - 身份证 → 香港身份證
  - 社保 → 強積金（MPF）。强积金是退休保障，不等于社保，不要硬对译
  - 个税 → 薪俸稅
  - 户籍：香港没有对应制度
  - 实名认证 → 「智方便」或「身份認證」，写具体方式
- 不要写「邮编」「请输入邮政编码」：香港没有邮政编码，地址栏不应要求填写。

**格式要求：**

- 香港身份證號碼的格式是 1 至 2 个英文字母、6 个数字，再加括号内 1 位检查码，例如 A123456(3)。校验提示照这个格式写。
- 机构名用现名：数字政策办公室（2024 年由政府资讯科技总监办公室等合并而成）。政府内容里的 digital 写「數字」（如「數字政府」），不写台湾的「數位」。
- 人称：港府网页和电子服务多用「你」，正式通知书多用「閣下」；产品内选一种全站统一，不要「您」「你」「閣下」混用（观察所得，未见成文规定）。
- 日期写「2026年10月16日」；英文版用日／月／年顺序。
