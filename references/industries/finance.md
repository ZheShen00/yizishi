- 用户的话：「银行 App」「支付页面」「钱包」「转账功能」「理财产品页」「信用卡账单」「炒股软件」「借款 / 放款流程」「理赔页面」「交易所 App」「企业报销系统」「对公财务工具」

和别的行业重叠时：金融 + AI（智能投顾、风控模型解释）先按本篇的硬约束（禁用语、风险提示、适当性），再叠 AI 产品的措辞规则，优先级：合规 > 诚实 > 简洁。金融 + 电商（分期付款、会员卡）按这份处理支付和利率部分，商品本身的文案按电商惯例。

## 2. 语气和人格

- 一句话定调：先把钱、风险、时间点说准，语气克制，不用情绪词替用户做决定。
- 人称：银行、保险类产品用「您」；支付宝、微信支付这类互联网系产品多用「你」，但涉及金额、合同、风险提示时即使全站用「你」也不转向俏皮。全站只定一种人称，参见 `principles.md`。
- 不能幽默、不能用感叹号和表情：报错、风险提示、确认框、验证码短信。可以克制地用在新手引导、功能介绍这类不涉及金额结果的场景，但不能出现在数字旁边。
- 和 `principles.md` 不同、要覆盖它的地方：
  - 货币数字必须精确到最小单位（分 / 美分），不写约数、不写「差不多」；`principles.md` 的「具体」原则在这里没有例外空间。
  - 金额、费率、到账时间这类决策性数字要比周围文字更醒目（字号、颜色、加粗任选），这是视觉层级要求，不只是用词——参照美国 Reg Z 要求 APR 的展示「比其他任何披露都更醒目」（见第 6 节）。
  - 「抱歉」不只是留给造成损失的报错：涉及资金损失、账户冻结、理赔拒赔时必须先说清楚损失范围和下一步，道歉放在后面且只说一次，不堆砌。
  - 报错要诚实但不能泄露风控规则细节：「因安全原因暂时无法完成」比捏造一个假原因更诚实，也不等于可以什么都不说——必须给出用户能做的下一步（见第 7 节「支付 / 转账失败」）。
  - 免责声明不能靠堆砌掩盖真正的风险提示：一页里出现五六条通用法律免责声明时，和这笔交易真正相关的那一条（比如「本产品不保本」）要排在最前面或单独加粗，不能和「本页面仅供参考」这类通用免责声明混在一起、被稀释掉。

## 4. 术语和叫法

| 用 | 不用 | 说明 |
|---|---|---|
| 到账 | 入账 | 「到账」给转账 / 收款方的资金状态；「入账」多用于对公会计凭证场景，界面给个人用户一律用「到账」 |
| 手续费 | 服务费、费用 | 转账 / 取现类成本统一叫「手续费」；基金交易成本按种类分别叫「申购费」「赎回费」「管理费」，不要用「费用」笼统带过 |
| 年化利率 | 利率、日息、月息 | 展示借款成本必须出现「年化利率」字样；单独写「利率」「日息」会让用户低估真实成本，须与年化利率同屏出现 |
| 风险等级 | 风险评级、风险标签 | 行业惯用 R1–R5 或 PR1–PR5 这类等级名，全站统一一套 |
| 持仓 | 仓位、持有 | 证券 / 基金类 App 统一用「持仓」做名词 |
| 可用余额 | 余额 | 「余额」在有冻结资金时会和「可用余额」混淆，需要分开展示并分别命名 |
| 实名认证 | 身份验证、KYC | 中文界面不用英文缩写 KYC；统一「实名认证」，流程里的分步骤可以叫「人脸核验」「身份证验证」 |
| 验证码 | 校验码、动态码 | 全站统一「验证码」 |
| 冻结 | 锁定 | 账户 / 资金的状态用「冻结」；密码连续输错导致的锁定用「锁定」，两者不混用 |
| 挂失 | 冻结卡 | 银行卡丢失场景的专有动作叫「挂失」，不要和账户「冻结」混成一个词 |
| 签约 | 绑定协议 | 代扣 / 自动扣款协议用「签约」；银行卡本身用「绑定」，两个动作分开说 |
| 撤回 | 取消 | 已经发起、进入处理流程的转账用「撤回」；还没提交或还没扣款的订单用「取消」 |
| 逾期 | 过期 | 还款没按时叫「逾期」；优惠券、证件、验证码失效叫「过期」 |
| 还款日 | 到期日 | 贷款 / 信用卡按期支付的日子叫「还款日」；理财产品 / 存款的到期兑付叫「到期日」 |
| 流水 | 账单、对账单 | 「流水」指交易记录列表；「账单」指信用卡 / 贷款的周期性汇总单；「对账单」指银行出具的正式凭证，三者不要互换 |
| 汇率 | 兑换率、牌价 | 统一「汇率」，牌价仅用于银行柜台语境的历史叫法，App 内不用 |
| 涨跌幅 | 涨幅、跌幅（分开用） | 展示正负变化统一叫「涨跌幅」，数值本身可正可负；境内产品红涨绿跌、境外产品可能反过来，颜色要跟着市场而不是跟着「涨跌幅」这三个字 |
| 持有人 | 用户、客户（混用） | 基金类产品的持有人在合规文件里叫「基金份额持有人」，界面可简化为「持有人」，不要和通用的「用户」混用在同一页 |
| 授信额度 | 额度、信用额度 | 贷款 / 信用卡类产品统一「授信额度」；「可用额度」指授信额度减去已用部分 |
| 本金 | 本金金额 | 直接用「本金」，不叠「金额」 |
| 理财 | 投资、理财产品（泛指） | 「理财」特指银行 / 理财公司发行的资管产品；基金、股票、保险各自用自己的产品名，不要用「理财」统称所有投资品类，容易让用户以为保本 |
| 买入 / 卖出 | 购买 / 出售 | 证券交易场景统一「买入」「卖出」；「购买」「出售」留给非交易类商品或理财产品申购场景 |
| 充值 | 存入、转入（混用） | 钱包 / 账户余额的注资动作统一叫「充值」；银行账户的资金转入叫「转入」或「存入」，依产品形态固定一个 |
| 适当性 | 风险匹配（非正式场合可用） | 正式合规文案（协议、风险揭示书）用「适当性管理」；用户可读的提示里可以说「风险匹配」，但不要在同一页混用两种说法 |
| 助记词 | 私钥（当成同一个词用） | 「助记词」（seed phrase）和「私钥」（private key）是两个不同的凭证，界面只在准确对应的地方各用各的词，不要用「密钥」笼统代替 |
| 自托管 | 托管（不分场景混用） | 「自托管」指用户自己保管私钥 / 助记词，平台拿不到；「托管」指平台代为保管。两种钱包模式对用户的权责完全不同，必须分开说明，不能都叫「钱包」而不注明托管方式 |
| 对公账户 | 对公户、企业账户（混用） | 全站统一「对公账户」，不要和「企业账户」「对公户」换着用 |
| 强制平仓线 | 爆仓线、止损线（混用） | 杠杆 / 保证金交易里触发强制平仓的价位统一叫「强制平仓线」；「爆仓线」是口语化说法，「止损线」是用户自己设置的止损点，三者含义不同，不能互换 |
| 报销单 | 费用单、报销申请 | 企业财务工具里固定叫「报销单」；「费用单」留给供应商开给企业的账单场景，不要混用 |
| 审批中 | 待处理、处理中（对公审批场景） | 对公支付 / 报销走多级审批时用「审批中」，并注明当前在哪一级；「处理中」留给系统自动处理、没有人工审批环节的场景 |
| 保费 | 保额（混用） | 「保费」是用户要交的钱，「保额」是出险后能赔多少，两个数字经常相邻出现，绝不能混用或只写其中一个却让用户以为是另一个 |
| 核保 | 核赔（混用） | 「核保」发生在投保时（审查是否承保、费率多少）；「核赔」发生在出险后（审查是否赔付、赔多少），流程和结果完全不同，不能用同一个词指代 |
| 临时退款 | 退款（争议处理中阶段） | chargeback / 交易争议处理期间先行返还的钱叫「临时退款」（provisional credit），争议未成立时会被扣回；最终处理完成后的钱才叫「退款」，两者法律效力不同，不能用同一个词 |
| 划转 | 转账（同机构内部账户间） | 同一机构内部账户之间（如活期转理财子账户）叫「划转」；跨银行 / 跨机构的资金转移叫「转账」，两者走的通道、到账时间、手续费都不同，不能混用 |
| 赎回 | 提现（基金 / 理财场景） | 基金、理财产品卖出变现叫「赎回」；钱包余额转到银行卡叫「提现」，两个动作对应不同的资金来源，不要用「提现」代替「赎回」 |
| 冻结金额 | 不可用余额（表述不一） | 账户里因司法冻结、担保占用等原因暂不能动用的部分统一叫「冻结金额」，和「可用余额」相加应等于「账户余额」，三个数字要对得上 |

## 5. 按元素写

只写和通用写法不同的部分。

**按钮**：涉及资金的操作按钮写清楚动作本身，不写「确定」「提交」——「确认转账」「确认支付」「提交赎回申请」。按钮本身不需要带金额，金额放在它上方的确认信息里。
中：「确认转账 ¥1,280.00」上方已显示完整确认信息时，按钮本身可以只写「确认转账」，避免同一数字出现两次造成视觉噪音。
EN: "Confirm transfer" — not "OK" or "Confirm", which don't say what's about to happen.

**表单标签和校验**：金额输入框要实时显示千分位和两位小数（用户输入 `1280` 实时转成 `1,280.00`）；校验信息给具体格式要求，不写「格式错误」——「卡号应为 16–19 位数字」「验证码为 6 位数字」。
EN: "Card number should be 16–19 digits" — not "Invalid format".

**报错**：支付 / 转账失败要分清「能重试」和「不能靠重试解决」两类（原则见 `principles.md`），金融场景额外要求：失败原因不能模糊到用户不知道该怎么办，也不能具体到暴露风控规则（见第 7 节）。

**空状态**：交易流水、持仓为空时只说现状，不用营销腔邀请消费——「暂无持仓」而不是「还没有任何持仓，去看看有什么好机会吧」。理财 / 基金类产品的「全部」「热门」这类列表为空时同样克制。

**确认框**：涉及资金的确认框是这个行业最高风险的元素，必须包含收款人（或交易对象）、金额、到账时间（或生效时间）、手续费、能否撤回这五项里用户用得上的几项，不能只写「确定要转账吗？」（展开示例见第 7 节）。

**状态标签**：固定一套，按阶段区分，不能用「已完成」模糊掉「审核通过」和「资金到账」的区别。
中：转账中 / 已到账 / 已退回 / 处理中 / 已失败；放款场景：审批中 / 已放款 / 已拒绝 / 已取消。
EN: Transferring / Delivered / Returned / Processing / Failed; lending: Under review / Disbursed / Declined / Cancelled.

**通知 / 推送**：大额变动通知要给出具体金额和账户尾号（「您尾号 1234 的账户发生一笔 ¥5,000.00 支出」），不能只说「您的账户有变动，点击查看」——那是诱导点击的做法，监管禁止的「虚假或引人误解的宣传」同样适用于推送文案。基金 / 股票类涨跌提醒不渲染情绪，不用「暴涨」「大赚」这类词。
EN: "A $5,000.00 charge posted to your account ending in 1234." — not "Something happened on your account. Tap to see."

**进度**：转账 / 放款处理中给预计到账 / 放款时间，不用百分比进度条模拟一个无法验证的进度（银行 / 支付类处理时间通常是节点制，不是连续进度）。

**引导 / 首次使用**：首次购买理财 / 基金前必须先走风险测评，不能把测评做成可跳过的引导页；实名认证引导要说明为什么需要（「为保障资金安全，交易前需完成实名认证」），不是单纯的「下一步」。

**帮助说明**：年化利率、费率、产品条款这类信息用「了解更多」链接到完整说明，不要把完整费率表压缩成一行提示语；但不能用链接代替第 6 节里要求「必须出现」的关键信息本身。

## 6. 合规和硬约束

以下硬约束主要引自《银行保险机构消费者权益保护管理办法》（国家金融监督管理总局 2022 年第 9 号令，2023 年 3 月 1 日起施行，全文：<https://www.gov.cn/gongbao/content/2023/content_5753317.htm>），条号已逐条核对原文：

**必须出现的话 / 必须做到的披露**：

- 第二十一条：信息披露要「使用通俗易懂的语言和有利于消费者接收、理解的方式」，专业术语要「解释说明」。界面文案里出现「净值」「久期」「回撤」这类术语，要么换成大白话，要么配一句解释。
- 第二十二条：「应当以显著方式向消费者披露产品和服务的性质、利息、收益、费用、费率、主要风险、违约责任、免责条款等可能影响消费者重大决策的关键信息。**贷款类产品应当明示年化利率。**」——任何借款、分期、信用卡产品的利率展示，年化利率必须出现，且不能被日利率 / 分期费率这类更小的数字抢了视觉重点。
- 第十一条：银行保险机构要建立「消费者适当性管理机制」，「开展消费者风险认知、风险偏好和风险承受能力测评，将合适的产品提供给合适的消费者」。界面上体现为：用户测评等级低于产品风险等级时，不能直接放行购买，要有拦截或二次确认（参照蚂蚁财富的劝退机制，第 3 节）。
- 第四十四条：线上授权个人信息时要「以醒目的方式、清晰易懂的语言明示与消费者存在重大利害关系的内容」。
- 行业惯例（非该办法逐字规定，但与第二十一 / 二十二条的风险揭示要求一致）：理财 / 资管产品销售页和风险揭示书固定出现「理财非存款、产品有风险、投资须谨慎」，购买前二次确认弹窗需要用户显式确认已读风险提示，不能默认勾选。
- 验证码短信固定要素：验证码本身、有效期、「请勿告诉他人」或等价表述、非本人操作的处理建议。不能在验证码短信里夹带营销内容（见第 8 节）。

**不许出现的话**：

- 第二十三条：「不得进行欺诈、隐瞒或者误导性的宣传，不得作夸大产品收益或者服务权益、掩饰产品风险等虚假或者引人误解的宣传。」——据此，「保本」「稳赚」「无风险」「100% 安全」「保证收益」「跑赢大盘」这类词不能出现在任何投资 / 理财产品的营销或引导文案里。
- 八部门《金融产品网络营销管理办法》（公告〔2026〕第 9 号，2026 年 9 月 30 日起施行）第十条进一步列出具体禁用诱导词：第（七）项「使用“低风险”“低门槛”“秒到账”“高收益”“低利率”“无成本”等诱导性用语」；第（三）项不得「明示或暗示资产管理产品、投资顾问或者咨询服务保本、承诺收益、限定损失金额或比例」；第（四）项不得「夸大保险责任或保险产品收益，将保险产品收益与存款、资产管理产品等金融产品简单类比」（条号已对原文核实：<http://www.whwx.gov.cn/zcfg/gfxwj/202608/t20260806_2830542.shtml>）。
- 第二十八条：不得「从贷款本金中预先扣除利息」，不得「以向第三方支付咨询费、佣金等名义变相向消费者额外收费」——费用展示要是最终会扣的全部费用，不能把实际费率藏进「咨询费」这类名目。
- 第四十四条：「银行保险机构通过线上渠道使用格式条款获取个人信息授权的，不得设置默认同意的选项。」——个人信息授权、隐私协议、营销短信订阅的复选框一律默认不勾选。
- 第四十一条：催收不得「冒用行政机关、司法机关等名义」，不得「采取暴力、恐吓、欺诈等不正当手段」。逾期提醒文案不能伪装成法院 / 公安通知的语气来制造恐慌。
- 美国场景（Reg Z 12 CFR §1026.17(a)(2)）：年化利率和 finance charge 的披露必须比其他任何披露都更醒目（「shall be more conspicuous than any other disclosure」），反过来说，不能用更大字号展示月费率、分期费率而把 APR 压成小字。

**必须的格式**：

- 金额：人民币用 `¥` 符号，千分位分隔，保留两位小数（`¥1,280.00`）；正式凭证（转账回单、合同）的大写金额用「壹贰叁肆伍陆柒捌玖拾佰仟万亿元角分零整（正）」书写；金额到「元」为止的，「元」后写「整」或「正」，到「角」的可以不写，有「分」的「分」后不写。依据：中国人民银行《支付结算办法》附件一《正确填写票据和结算凭证的基本规定》，全文：<https://www.cncc.cn/zcfg/200903/t20090323_286.html>。
- 敏感信息脱敏（《个人金融信息保护技术规范》JR/T 0171—2020 第 6.1.4.1 条、附录 A 表 A.1）：界面上的银行卡号、手机号、证件号要屏蔽展示，或由用户选择是否屏蔽；要完整展示，先做身份验证。格式：银行卡号显示前 6 位 + 星号（星号数等于被隐藏的位数）+ 后 4 位（如 `622575******1496`）；大陆手机号显示前 3 位 + `****` + 后 4 位（如 `137****9050`）；身份证号按缺省规则显示前 1/3 和后 1/3，中间用星号，隐藏出生日期那一段。标准全文（银行转载）：<https://static.ibank.bocd.com.cn/www/fileupload/20210407/16177854515902020%E4%B8%AA%E4%BA%BA%E9%87%91%E8%9E%8D%E4%BF%A1%E6%81%AF%E4%BF%9D%E6%8A%A4%E6%8A%80%E6%9C%AF%E8%A7%84%E8%8C%83.pdf>
- 利率：至少同屏展示年化利率；如果同时展示日利率，年化利率的字号 / 位置不能比日利率弱。
- 美国场景：APR 必须使用「annual percentage rate」这一术语本身，并配一句通俗说明（12 CFR §1026.18(d)(e)，如「the cost of your credit as a yearly rate」）。
- 单笔交易金额不用「万」「亿」这类缩写：转账、支付、账单这类单笔金额必须写全数字（`¥128,000.00`），不能写成「12.8 万」。「万」「亿」缩写只能用在仪表盘、统计概览这类看汇总趋势、不涉及具体一笔钱对不对的地方，和 `SKILL.md` 里「紧凑数值可以写『12.3万』」的通用项目约定不同——金融场景任何会被用户拿来核对「这笔钱对不对」的数字都不能缩写。
- 长期人身保险新型产品（投连、万能、分红）投保成功页要明示「犹豫期」：期内可解除合同、退还保费。天数写保险合同里约定的实际天数，不要写一个笼统区间。银行代理渠道卖的、保险期间超过一年的产品，犹豫期是 15 日，提示原文是「您在收到保险合同后 15 日内有全额退保（扣除不超过 10 元的工本费）的权利。超过 15 日退保有损失」（《商业银行代理保险业务管理办法》，银保监办发〔2019〕179 号，第三十六条、第六十七条：<https://www.gov.cn/zhengce/zhengceku/2019-12/03/content_5457853.htm>）。

**加密货币 / 数字资产的额外约束**：中国人民银行等十部门《关于进一步防范和处置虚拟货币交易炒作风险的通知》（银发〔2021〕237 号，<https://www.gov.cn/zhengce/zhengceku/2021-10/08/content_5641404.htm>）明确虚拟货币相关业务活动属于非法金融活动，境外虚拟货币交易所通过互联网向境内居民提供服务同样属于非法金融活动，因此面向中国大陆个人用户的产品不能出现加密货币交易、充值、提现一类界面。面向境外用户的产品如果涉及加密货币，要比照第 7 节「投资业绩展示」的约束，另外加两条：不能说「存款」「保本」，因为加密资产不受美国 FDIC 存款保险保障（<https://www.fdic.gov/news/fact-sheets/crypto-fact-sheet-7-28-22.html>），多数加密资产也不在 SIPC 保护范围内（<https://www.sipc.org/for-investors/what-sipc-protects>）；资产托管方式（自托管 / 平台托管）要明确说明，不能都叫「钱包」而不说清楚私钥在谁手里。示例写法（非引用某家交易所原文）：「加密资产不受 FDIC 或 SIPC 保险保障，价格波动剧烈，可能损失全部本金」。

**对公 / 企业财务工具的额外约束**：报销单、对公转账、工资发放这类多级审批场景，状态要显示到具体审批层级，不能只写「审批中」；涉及税费（增值税、个税代扣）的金额要分别列出税前金额、税费、税后金额，不能只给一个合计数。

## 7. 高风险场景

> 示例里的数字、时效和承诺（「25 分钟」「自动回滚」「近 7 日最低价」这类）是示意，只示范要素和句式。改真实文案时以产品给的事实为准，没有就写 [填：…]（见 SKILL.md 踩过的坑 7）。

**转账 / 支付确认**：必写收款人（姓名 + 机构 / 账户后四位）、金额、到账时间、手续费、能否撤回。
中：「向张三（工商银行 \*\*\*\* 1234）转账 ¥1,280.00，预计实时到账，手续费 ¥0，发起后无法撤回。」
EN: "Send $1,280.00 to John Smith (Chase •••• 1234). Arrives instantly. Fee: $0.00. This can't be undone once sent."

**支付 / 转账失败**：给分类原因 + 对症下一步，不编造模糊到没用的理由，也不泄露风控阈值。
中：「银行卡余额不足，请更换付款方式或存入资金后重试。」（钱包余额不足才写「充值」，见第 4 节）「单笔金额超过当日限额（¥50,000），请分笔转账或联系银行提升限额。」风控拦截时可以说「因安全原因暂时无法完成，请稍后重试或联系客服」，但不能编造一个假的具体原因。
EN: "Your card has insufficient funds. Add funds or use a different payment method."

**风险提示 / 理财与基金销售**：购买前二次确认页必须出现风险提示和业绩免责声明，不能被营销话术挤掉。
中：「理财非存款，产品有风险，投资须谨慎。本产品不保本，历史业绩不代表未来表现。」
EN: "This investment can lose value. Past performance is not a reliable indicator of future results."

**适当性 / 风险不匹配**：产品风险等级高于用户测评等级时，不能直接放行购买，要明确告知差距并要求用户主动确认。
中：「该产品风险等级（R4）高于您的风险测评等级（C2），继续购买即表示您已知悉并自愿承担超出承受能力的风险。」

**KYC / 实名认证**：说明为什么要验证，不要只给一个「下一步」。
中：「为保障您的资金安全，交易前需完成实名认证，预计 1 分钟。」

**开户 / 首次出金限制**：新开证券 / 加密货币账户常有首次入金后的出金观察期（反洗钱常见做法），要在入金前就说明，不能等用户出金被拦下时才解释。
中：「为符合反洗钱监管要求，首次入金后 T+1 个工作日内暂不支持出金，之后可随时申请。」
EN: "To comply with anti-money-laundering requirements, withdrawals are unavailable for 1 business day after your first deposit. After that, you can withdraw anytime."

**反诈提示**：大额或陌生账户转账要给延迟到账和核实渠道，不能只在事后补救。
中：「已提交，24 小时后到账，到账前可在「转账记录」里撤回。如对方自称公检法人员要求转账，请先拨打 96110 核实。」

**账户冻结**：委婉但不能含糊到用户不知道发生了什么，要给解冻 / 申诉路径。
中：「账户已冻结，暂不能转账或支付。如需解冻，请联系客服或前往网点办理。」不写「你的账户出问题了」这种没有对象、没有下一步的句子。

**贷款 / 信用产品**：年化利率必须和日利率 / 分期费率同屏出现，不能只展示让成本显得更低的那个数字。
中：「日利率 0.02%，折合年化利率 7.3%（单利），以实际放款为准。」
EN: "0.02% daily, equivalent to 7.3% APR (simple interest). Final rate subject to approval."

**投资业绩展示**：任何收益率展示（历史净值、业绩比较基准、模拟收益）都要配免责声明，不能让数字单独出现、暗示未来会重复。
中：「近一年收益率 8.2%（历史数据，不代表未来表现，不构成收益承诺）。」

**脱敏展示**：卡号、身份证号等敏感信息默认展示成掩码，需要用户主动操作（如输入密码）才能看到完整信息。
中：「储蓄卡 622202\*\*\*\*\*\*7890」，不直接显示完整 16 位卡号。

**验证码**：短信 / 界面弹出的验证码只含验证码本身、有效期、防泄露提示，不夹带任何营销内容。
中：「验证码：123456，5 分钟内有效，请勿告诉任何人，如非本人操作请忽略。」

**争议 / 退款**：给清楚的时间线和查询入口，拒绝退款要说明依据和申诉方式。
中：「退款申请已提交，预计 1–3 个工作日原路退回，可在「退款记录」中查看进度。」
EN: "Refund requested. Expect it back on your original payment method in 1–3 business days — track it under 'Refund history.'"

**交易争议 / chargeback**：必写争议受理状态、是否已收到临时退款（provisional credit）、最终结果前该笔款项的可用性，不能让用户误以为争议一提交钱就已经拿回来了。
中：「争议已受理，预计 10 个工作日内有结果。我们已为您做临时退款 ¥320.00，如争议未成立将从账户扣回。」
EN: "Dispute filed. We expect a result within 10 business days. We've issued a provisional credit of $320.00 — if the dispute isn't resolved in your favor, it will be reversed."

**保险理赔**：核赔通过和拒赔都要说清楚依据，拒赔不能只说「未通过」，要指出具体不符合哪一条责任范围，并给出申诉入口和期限。
中：「理赔未通过：提交的诊断证明不符合条款约定的责任范围（XX 条「既往症除外」），可在 30 日内申诉，入口见下方。」核赔通过时同样要给金额和到账时间：「理赔已通过，赔付金额 ¥8,000.00，预计 3 个工作日内到账。」
EN: "Claim denied: the diagnosis provided doesn't fall within the covered conditions in your policy (Section 4, pre-existing condition exclusion). You can appeal within 30 days — see the link below."

**跨境汇款 / 外汇**：必写汇率（以及汇率的锁定时点）、到账币种和金额、中间行或代理行可能另收的费用、预计到账时间，四项缺一都会让用户在到账后才发现金额对不上。
中：「按汇率 7.1523（实时汇率，到账前可能变动）换算，预计到账 USD 180.00，另有中间行手续费（具体以中间行实收为准），预计 1–3 个工作日到账。」
EN: "Converted at 7.1523 (live rate, may change before the transfer completes). You'll receive approximately USD 180.00. Intermediary banks may charge additional fees. Arrives in 1–3 business days."

**加密货币 / 数字资产交易**（仅适用于合规允许提供该服务的市场和用户）：必写价格波动风险、是否受存款保险保障、资产托管方式，不能用「理财」「存款」这类词包装。
EN: "Crypto asset prices are highly volatile and you could lose your entire investment. Crypto assets aren't covered by FDIC or SIPC insurance. This wallet is self-custodial — we can't recover your funds if you lose your recovery phrase."

**对公财务工具审批**：多级审批流程要显示当前在哪一级、还差几级、预计处理时间，不能只显示一个笼统的「审批中」。
中：「报销单审批中（2/3）：部门主管已通过，等待财务复核，预计 1 个工作日内处理完成。」
EN: "Expense report pending (2 of 3 approvals): Approved by department manager, awaiting finance review. Expect a decision within 1 business day."

## 8. 这个行业的 AI 腔和坏写法

| 坏写法 | 例子 | 改法 |
|---|---|---|
| 卖萌语气配资金操作 | 「马上到账哦～」「钱包充值成功啦！」 | 删掉语气词，只说结果：「已到账」「充值成功」 |
| 用感叹号 / emoji 渲染收益 | 「恭喜您，收益大涨！🎉」 | 「近一年收益率 8.2%（历史数据，不代表未来表现）」 |
| 把「预期」写成听起来像承诺的数字 | 「预计年化收益 6%，稳稳拿到手」 | 「业绩比较基准 6%，不代表实际收益，产品过往业绩不预示未来表现」 |
| 用绝对化用语包装安全性 | 「资金绝对安全，万无一失」 | 删掉绝对化用语，具体说明保障措施：「资金由第三方银行存管」 |
| 用「智能」包装收益承诺 | 「AI 智能优选，稳健跑赢大盘」 | 只说产品实际做了什么，不暗示跑赢基准：「按风险等级配置，历史业绩不代表未来表现」 |
| 模糊到没有下一步的失败原因 | 「因风控原因失败」 | 给能做的下一步：「因安全原因暂时无法完成，请稍后重试或联系客服」 |
| 用电商促销话术卖理财 / 保险 | 「仅剩 3 个名额，立即抢购！」「限时秒杀」 | 删掉倒计时和抢购话术，理财 / 保险类产品不用限时稀缺感制造冲动购买 |
| 验证码短信夹带营销 | 「尊敬的用户，您的专属验证码是 123456，猜猜今天股市行情？」 | 验证码短信只含验证码、有效期、防泄露提示 |

| 用「我们」代替具体机构名做承诺 | 「我们保证您的资金安全」 | 写清楚谁在保障、靠什么机制：「资金由 XX 银行存管，不保本但有存管保障」 |
| 把拒赔 / 拒绝退款说得很模糊 | 「很遗憾，您的申请未通过审核」 | 给依据和申诉路径：「理赔未通过：诊断证明不符合条款约定的责任范围，可在 30 日内申诉」 |
| 用「安心」「放心」代替具体保障说明 | 「放心转，绝对安全」 | 「转账全程加密传输，发起后 X 小时内可撤回」 |
| 把杠杆 / 配资包装成放大收益、不提放大亏损 | 「10 倍杠杆，收益翻倍！」 | 杠杆倍数旁边必须同等醒目地给出对应风险：「10 倍杠杆会同等放大收益和亏损，达到强制平仓线将被强制平仓」 |
| 把强制平仓线做成要点进详情页才能看到的小字 | 下单页只显示「立即下单」，强平线藏在三级页面里 | 强制平仓线和杠杆倍数一样，放在下单按钮附近同等醒目的位置 |
| 把加密资产包装成「理财」「存款」 | 「数字资产理财，年化 20%，随存随取」 | 删掉「理财」「存款」这类暗示保本的词，直接说风险：「质押收益率随市场浮动，本金可能亏损」 |
| 对公审批状态只给笼统进度 | 「审批中…」 | 「报销单审批中（2/3）：部门主管已通过，等待财务复核」 |
| 汇率展示成固定数字，不提示会变 | 「汇率 7.15，到账 $180」 | 「按汇率 7.1523（实时汇率，到账前可能变动）换算，预计到账 USD 180.00」 |
| 把临时退款说成最终退款 | 「交易争议已受理，退款 ¥320.00 已到账」（其实争议还没有结论） | 区分临时退款和最终结果：「已为您做临时退款 ¥320.00，如争议未成立将从账户扣回」 |
| 把单笔金额缩写成「万」 | 「本次转账 12.8 万」 | 单笔金额写全数字：「本次转账 ¥128,000.00」，「万」「亿」缩写只用于汇总统计 |
| 用「很遗憾」代替具体拒赔依据 | 「很遗憾，您的理赔申请未能通过」 | 「理赔未通过：诊断证明不符合条款约定的责任范围（第 4 条「既往症除外」），可在 30 日内申诉」 |
| 投保成功页不提「犹豫期」 | 「投保成功！保单已生效」 | 「投保成功，保单已生效。收到保险合同后 15 日内可退保，退还保费（扣除不超过 10 元工本费）」（天数按合同实际约定写） |
| 出金限制等用户出金被拦下才解释 | 出金按钮点击后弹出「暂不支持出金」 | 入金前就提示：「为符合反洗钱监管要求，首次入金后 1 个工作日内暂不支持出金」 |

「强制平仓线要和杠杆倍数同等醒目」是本文件给出的 UI 文案建议，不是某一条法规的逐字规定——没有查到大陆证监会 / 交易所融资融券或期货风险揭示书、也没有查到 FCA / SEC 对杠杆产品披露专门要求「强平线和杠杆倍数必须同等醒目」这一具体搭配。参照的是几条方向一致、但各自适用范围更窄的既有规则：《银行保险机构消费者权益保护管理办法》第二十二条要求「以显著方式」披露「主要风险」（见第 6 节）；FCA 对 CFD 等杠杆产品要求标准化风险警示必须醒目展示（字体、边框、不能被其他内容盖过，PS19/18、COBS 22.5）；FINRA Rule 2264 要求保证金账户的强制平仓风险披露在网站上「以清楚醒目的方式」（clear and conspicuous manner）展示。把这几条的精神对应到「杠杆倍数」和「强制平仓线」这对具体数字上、要求两者同等醒目，是本文件的推演和建议，上线前仍应以产品所在市场的监管要求和公司合规意见为准。

## 10. 审查时加查的项

- [ ] 资金操作确认页（转账 / 支付 / 跨境汇款）是否同时给出收款人（或汇率、到账币种）、金额、到账时间、手续费（或中间行费用）、能否撤回这几项用户用得上的信息
- [ ] 贷款 / 信用产品是否展示年化利率、且不被日利率 / 月利率 / 分期费率抢视觉焦点；涉及资金的数字（金额、利率、手续费）是否精确到分或小数点，视觉上是否比周围文字更醒目
- [ ] 理财 / 基金 / 保险 / 加密货币类产品页是否有风险提示和「过往业绩不代表未来表现」一类免责声明；长期人身保险新型产品是否提示了「犹豫期」；加密货币是否披露了价格波动风险和是否受存款保险保障而不是包装成「理财」「存款」；一页里多条免责声明中和这笔交易真正相关的那条有没有被通用法律声明稀释
- [ ] 文案中是否出现「保本」「稳赚」「无风险」「保证收益」「万无一失」等禁用或绝对化用语
- [ ] 产品风险等级高于用户测评等级时，是否有明确提示和主动确认，而不是直接放行购买
- [ ] 卡号、身份证号、手机号等敏感信息展示是否已脱敏
- [ ] 验证码短信是否只含验证码本身、有效期和防泄露提示而不夹带营销内容；转账 / 支付失败原因是否给了对症的下一步，而不是泛泛的「请重试」或完全不说原因
- [ ] 账户冻结 / 异常提示、理赔拒赔是否给了解冻 / 申诉路径；新开账户的出金限制（反洗钱观察期）是否在入金前就说明，而不是等用户被拦下才解释
- [ ] 个人信息 / 隐私协议的授权勾选是否默认不勾选；多级审批流程的状态是否显示当前所在层级而不是笼统的「审批中」；划转（同机构内部）、转账（跨机构）、赎回（基金变现）、提现（钱包转出）这几个动作词是否按场景分开使用，没有互换
- [ ] 杠杆 / 融资融券类交易页面的强制平仓线是否和杠杆倍数同等醒目，而不是藏进详情页（本文件的建议做法，非法规逐字规定，见第 8 节说明）

## 11. 台港市场差异

界面是 zh-TW（台湾）或 zh-HK（香港），并且面向当地用户卖存款、贷款、信用卡、基金、保险时，读这一节。第 6 节引的大陆法规（金融监管总局令、「理财非存款」惯例）在台港都不适用，按下面的规则替换。通用换词（帳號、設定、簡訊等）已在 `locale-zh-hant.md`，这里只列金融专有的。

### 台湾

**必须出现的话**：

- 消费性贷款、房贷、信用卡、现金卡的广告和产品介绍页，要揭示「總費用年百分率」，四舍五入到小数点后第二位（《銀行業暨保險業辦理消費者信用交易廣告應揭示總費用範圍及年百分率計算方式標準》第 2 條、第 8 條，依《消費者保護法》第 22-1 條訂定）。只写「利率 2.88% 起」不合规。
- 揭示年百分率时，要配上銀行公會計算範例的说明句（金管會 94.11.30 金管銀（三）字第0940030381號函准予備查），大意为：「本廣告揭露之年百分率係按主管機關備查之標準計算範例予以計算，實際貸款條件仍以本行提供之產品為準，且每一客戶實際之年百分率仍視其個別貸款產品及授信條件而有所不同。」逐字措辞以範例原文为准。
- 信用卡广告（包括网路图像广告和簡訊）：必须有警语「謹慎理財，信用至上」或「謹慎理財，信用無價」，同时写出循環信用利率負擔區間；有分期功能的，还要加分期利率、手續費和總費用年百分率區間（《信用卡業務機構管理辦法》第 20 條第 1 項；金管銀票字第10702102591號函，107.08.08）。
- 現金卡广告：必须有警语「借錢不還，再借困難」或「以債養債，終身受害」，同时写出利率負擔區間和全部费用（同上函）。
- 基金销售页的固定警语：「基金經理公司以往之經理績效不保證基金之最低投資收益；基金經理公司除盡善良管理人之注意義務外，不負責本基金之盈虧，亦不保證最低之收益，投資人申購前應詳閱基金公開說明書。」展示定期定額績效时，再加「投資人因不同時間進場，將有不同之投資績效，過去之績效亦不代表未來績效之保證。」出自中華民國證券投資信託暨顧問商業同業公會《會員及其銷售機構從事廣告及營業活動行為規範》（原分列的《證券投資信託事業從事廣告及營業活動行為規範》已併入此規範，名稱已核实；具体条号因原文需会员登入查阅，仍未核实）。
- 保险广告必须写保险公司名称、地址、电话（《保險業招攬廣告自律規範》第 4 條）。投資型保險要揭示投資風險警語，并写明「本商品所連結之一切投資標的，其發行或管理機構以往之投資績效不保證未來之投資收益」（同規範第 5 條、第 5-2 條）。
- 签约前要了解客户、评估适合度，并充分说明重要内容、揭露风险（《金融消費者保護法》第 9、10 條）。对应第 6 节的适当性拦截，台湾界面的说法是「風險屬性評估」「投資風險屬性」。

**不许出现的话**：

- 广告、招揽、促销不得「虛偽、詐欺、隱匿或其他足致他人誤信」，而且业者对消费者承担的义务不得低于广告内容（《金融消費者保護法》第 8 條）。也就是说，营销页上写的优惠条件就是承诺。
- 保险广告不得让人误信「保證本金安全」「保證獲利」，也不得拿保险和銀行存款或其他金融商品比较（《保險業招攬廣告自律規範》第 4、5 條）。因此「比定存划算」「穩賺不賠」这类话不能写。
- 信用卡网路广告不得推销预借现金功能（金管銀票字第10702102591號函）。

**格式要求**：

- 警语版面：信用卡网路图像广告的警语要占 1/13 版面，或在整个广告期间持续显示，字体不小于 14 号；现金卡占 1/8 版面（同上函）。App 内的 banner 按同样比例做。
- 利率一律以年率表示（《信用卡業務機構管理辦法》第 40 條）。日息可以另外写，但不能替代年率。
- 金额写成「新臺幣 1,280 元」或「NT$1,280」，一般不带小数（惯例）。交易明细如果用民国年（115/10/16），全站统一，不要和西元年混用（惯例）。

### 香港

**必须出现的话**：

- 银行文案提到利率时，同时写「實際年利率」（APR）。可行时附一句说明，例如「實際年利率是參考利率，以年率顯示產品的基本利率及其他費用」（《銀行營運守則》Code of Banking Practice 第 11.6 段）。存款、透支、按揭这类惯用浮动年利率报价的产品可以不报 APR，但要清楚、显眼地列出相关费用（第 12.1 段）。
- 信用卡要分别报「簽賬」和「現金透支」两个 APR，和年費同等醒目（第 32.1 段）。循环贷款的 APR 也要和年费同等醒目（第 24.9 段）。有固定期限的贷款，要列出常用还款期各自的 APR（第 24.8 段）。
- 持牌放債人（财务公司，不包括银行）的所有广告，必须有「忠告：借錢梗要還，咪俾錢中介」（2016 年 12 月 1 日起生效的放債人牌照額外條件）。
- 證監會（SFC）认可基金的广告必须写明：「投資涉及風險」；投资者要阅读销售文件，包括风险因素；展示过往表现时写「過往表現並不代表將來表現」。依据是 SFC 官方中文名《適用於根據產品守則獲認可的集體投資計劃的廣告宣傳指引》（英文 Advertising Guidelines Applicable to Collective Investment Schemes Authorized under the Product Codes，中文译名已核实，见本节末出处链接的中文版）第 23 段。措辞可以改，但意思不能藏（第 24 段）。宣传预期派息率时，要加「派息率為正數並不代表投資回報為正數」一类的警告（第 10 段）。

**不许出现的话**：

- 基金广告不得用让人以为不会亏钱或保证获利的词，除非产品本身有保证机制（指引第 4 段，举例 safe、secure、protected、no risk、guarantee、promise）。对应的中文是「安全」「穩陣」「零風險」「保證」「承諾」。
- 警语的字号、版面和位置都要让人看得清（第 26 段）。不满一年的业绩数字不得比最近一年的数字更醒目（第 13 段）。

**格式要求**：

- 金额写「HK$1,280.00」，保留两位小数（惯例）。
- 涨跌颜色：香港传统是「綠升紅跌」，和台湾、大陆的「紅漲綠跌」相反。按目标市场设默认值，并允许用户切换（行业惯例，港交所或监管层面的统一出处未核实）。注意港股 App 默认并不统一：富途香港帮助中心写明价格「當 價格 > 昨收價，價格顯示紅色」，另设「報價圖表如何設定綠漲紅跌」的切换说明（<https://www.futuhk.com/hant/support/topic1_40>），所以切换开关是必须的，不能假定港股用户都习惯綠升紅跌。

| 大陆 | 台湾 | 香港 |

**个资**：台湾适用《個人資料保護法》。蒐集时要按第 8 條告知六项：机关名称、蒐集目的、个资类别、利用的期间 / 地区 / 对象 / 方式、当事人权利、不提供的影响。首次行销时要提供拒绝行销的方式（第 20 條）。香港适用《個人資料（私隱）條例》（第 486 章）。收集时按附表 1 第 1 原則告知收集目的和资料转移对象，用于直接促销前要先通知并取得同意（第 6A 部）。不要写成大陆的《个人信息保护法》。
