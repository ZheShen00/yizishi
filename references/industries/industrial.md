## 1. 什么时候用这份

信号（命中任意两条就用；只命中一条时，结合用户的话判断）：

- 代码 / 依赖（命中任意一个都算信号）：
  - OPC UA：`node-opcua`、`node-opcua-client`
  - Modbus：`modbus-serial`、`jsmodbus`
  - MQTT / Sparkplug B：`mqtt` 配 `sparkplug-payload` 或 `sparkplug-client`
  - 设计系统：`@siemens/ix`、`@siemens/ix-icons`
  - PLC 专用协议：`nodes7`、`s7-client`（西门子 S7）、`ads-client`（倍福 ADS）
  - 组态/网关平台：`ignition`、`node-red-contrib-s7`
- 目录 / 文件名：`alarms/`、`tags/`、`devices/`、`workorders/`、`interlocks/`、`setpoints/`、`shifts/`、`units/`、`calibration/`、`plc/`、`scada/`、`hmi/`、`telemetry/`、`asset-health/`
- 界面里的词：报警、联锁、急停、复位、下发参数、工单、点位、组态、量程、整定值、工况、停机、待机、故障、维护、巡检、交接班、旁路、信号词、阈值
- 用户的话：「HMI 系统」「SCADA 大屏」「MES 车间看板」「PLC 上位机」「能源管控平台」「产线看板」「设备健康度」「中控室」「组态软件」

和别的行业重叠时：

- **工业 + AI**（设备健康预测、异常检测、数字孪生）：先按本文件的报警结构和确认框硬约束走，再叠 AI 的不确定性表达——「预测」「置信度」这类词必须和已确认的报警/故障状态在视觉和用词上分开，不能让一条模型推断看起来像一条已核实的报警。
- **工业 + 企业软件**（MES/ERP 报表、看板）：状态词、单位、精度按本文件；表格、筛选、分页这些通用控件按 `principles.md`。
- **工业 + 消费端 App**（国网网上国网、光伏业主端）：面向 C 端业主/居民用户的部分语气更服务化，可以用「您」；但故障、停电、计量这些客观状态词仍按本文件，不因为面向 C 端就改成营销语气。
- **工业 + 医疗/安全监管**（如工业场所的安全培训、应急预案系统）：信号词和安全标牌的硬约束优先按本文件的 ISA/ANSI/GB 体系，不要套用医疗行业的免责声明句式。

## 2. 语气和人格

一句话定调：克制、可扫读、按角色分层——操作员只需要知道这一步能不能做，工程师需要数值和趋势，管理者需要汇总和例外。

- **人称**：操作员/工程师界面通常不用「你」或「您」，直接用名词短语或祈使句（「检查传感器」而不是「你检查一下传感器」）；面向业主/居民的能源类 C 端 App（如网上国网）可以用「您」，按消费品习惯走。
- **正式程度**：高，比 `principles.md` 的默认基线更克制。不用感叹号——紧急程度由信号词、颜色、优先级表达，文字本身不用「！」堆叠；安全标牌上的感叹号三角图形是图形符号，不是标点。
- **幽默和 emoji**：不用。设备状态、报警、联锁确认里出现一个 emoji 或语气词，读的人会怀疑这句话是不是认真的。
- **和 principles.md 不同、要覆盖它的地方**：
  - principles 说「危险操作按钮写动作本身，不写确定」——工业场景里涉及联锁/执行机构的操作（启动、复位、旁路）要比这更重一级：确认框必须连带列出联锁状态和后果，不能只给一个动作按钮了事，见第 5、7 节。
  - principles 说空状态是「现状 + 下一步」——工业里很多「空」其实是「零台在线」「当前无报警」这类状态播报，本身就是信息，不必须带一个号召性动作。
  - principles 默认用「你」——工业操作员/工程师界面更常见的做法是干脆不出现人称，直接用祈使句或名词短语。

### 操作员 / 工程师 / 管理者：同一件事，三种详略

三类角色经常看同一个点位、同一条报警，但需要的详略程度不一样；文案要按角色分层，不能用一套话对三类人：

- **操作员**：只要「能不能做这一步」和「现在该做什么」。中：「无法启动：3 号联锁未解除。」不展示点位内部编号、原始寄存器地址这类工程信息。
- **工程师**：需要点位编号、工程单位、历史趋势这些可以用于诊断的信息。中：「TT-301 当前值 86.4 °C（量程 0–150 °C，精度 ±0.5 °C），10 分钟内上升 12 °C。」英：`TT-301: 86.4 °C (range 0–150 °C, ±0.5 °C), +12 °C in 10 min.`
- **管理者**：只要汇总指标和例外，不展示单点位数值。中：「本周 2 号产线停机 3 次，累计 42 分钟，环比上周 -18%。」英：`Line 2 had 3 stoppages this week, 42 min total, -18% vs. last week.`
- 三层共用第 4 节的术语表，不能工程师界面叫「整定值」、管理者报表里又叫「目标值」。

### 短文本的标点

状态标签、按钮、报警横幅这类短文本原则上不加句号，和 `principles.md` 通用规则一致；但有两处是工业场景的例外，要单独记住：

- 英文安全信号词（DANGER / WARNING / CAUTION / NOTICE）后面跟具体危害描述时，信号词本身不加标点，危害描述部分按正常句子加句号：`WARNING: Hot surface. Contact may cause burns.`
- 报警一览里的单条报警描述通常不加句号（它是列表项，不是完整句子）；但报警推送通知、交接班记录这类独立呈现的句子要加句号，因为它们会被单独截图、打印或转发。

### 戴手套操作和远距离可读性

现场 HMI 常常在强光、粉尘、戴手套、和屏幕保持一定距离的条件下使用，文案长度和对比度要为这个场景让步，而不是为了信息完整堆砌长句：

- 报警横幅、状态条这类需要一眼扫到的文字，中文建议单行不超过约 12–16 字，英文单行不超过约 40 字符，避免因为跑马灯滚动或自动换行而把关键词截断。
- 需要戴手套快速确认的操作（如触屏上的「复位」「确认」），按钮文字本身越短越好，解释性内容放在按钮旁边的说明行，不要塞进按钮文字里。
- 全大写只用于英文信号词（DANGER / WARNING / CAUTION / NOTICE）和它们所在的短横幅，正文说明不用全大写——连续大写的长句反而会拖慢阅读速度，这点和 ISA-101「减少不必要装饰、保证可读性」的取向一致。
- 高对比度的红/橙/黄这几种颜色优先留给真正的报警和安全等级用，装饰性图表、品牌色不能抢用这几个颜色，否则操作员会分不清这块红色是警示还是配色。

## 4. 术语和叫法

| 用 | 不用 | 说明 |
|---|---|---|
| 运行 | 开机、工作中 | 「开机」指设备上电这个动作；「运行」是设备状态词，二者不是一回事 |
| 停机 | 关闭、停止运行 | 「关闭」留给窗口/功能这类界面对象；设备状态统一「停机」 |
| 待机 | 空闲、standby | 待机 = 已上电、等待指令，不是「空闲」这种笼统说法；英文夹用会让中文状态标签不统一 |
| 故障 | 异常、error、坏了 | 「故障」是需要维护响应、进工单的设备主状态；「异常」留给数据/趋势层面偏离正常范围的描述，两者分层 |
| 维护 | 保养中、维修中 | 状态标签统一「维护」；「保养」用于计划性维护工单的标题文字，不进状态标签 |
| 联锁 | 互锁、interlock | 全站统一「联锁」；「互锁」是旧译法，两个词并存会让术语表和搜索对不上 |
| 急停 | 紧急停止、E-Stop | 按钮和状态标签统一「急停」；「紧急停止」可以出现在说明性长句里，不进按钮和状态标签 |
| 复位 | reset、恢复 | 「复位」专指清除故障/联锁锁存状态这个动作；「恢复」留给「恢复生产」这类更大范围的业务动作 |
| 下发参数 | 写入参数、推送参数、下装 | 操作员界面统一「下发」；「下装」是工程师口语，不进操作员界面 |
| 确认（报警） | 已读、知道了、ack | 报警确认是有留痕的独立操作，不能用「已读」这种弱化词；「ack」不进中文界面 |
| 消音 | 静音、免打扰 | 「消音」专指报警声音确认这一个动作，不是通用的「静音模式」 |
| 报警 | 告警、预警 | 「报警」= 已越限、需要响应；「预警」= 趋势提示、尚未越限；两者是不同严重度，不能混用。「告警」是通信/IT 行业叫法，工业场景优先「报警」，项目已用「告警」时听项目的 |
| 点位 | 测点、标签、tag | 全站统一「点位」；「标签」容易和「报警标签/状态标签」混淆 |
| 量程 | range、测量范围 | 工程师可见的配置项统一「量程」 |
| 整定值 | 设定值、SP、setpoint | 操作员界面二选一固定用「整定值」或「设定值」，不要「SP」裸露出现；工程师界面可以在后面加注 `(SP)` |
| 阈值 | 门限、limit | 统一「阈值」；「门限」是通信行业叫法 |
| 工单 | 任务单、工作指令、work order | 统一「工单」 |
| 巡检 | 点巡检 | 列表项、按钮用「巡检」；「点巡检」是书面全称，可用于标题或制度文件 |
| 交接班 | 换班、交接 | 「交接班」指记录这个动作；「换班」指人员排班安排，不是同一件事 |
| 量纲 | 单位类型、dimension | 工程设置项统一「量纲」 |
| 工况 | 工作状况 | 「工况」指设备/工艺当前一组运行参数的组合（温度、压力、转速等），不是单一状态标签，不能和「状态」互换使用 |
| 精度 | 分辨率 | 一般界面统一写「精度」；只有需要同时区分测量不确定度和显示小数位时，才分别用「精度」和「分辨率」 |
| 组态 | 配置 | 「组态」专指 HMI/SCADA 工程配置这个动作和对应软件；普通设置项用「设置」 |
| 解除（联锁） | 旁路、bypass、屏蔽 | 「解除联锁」= 条件已满足、联锁自动释放；「旁路联锁」= 人为强制跳过，必须单独授权和留痕；两者不是同义词，不能互换 |
| 示教模式 | 教学模式、teach mode | 机器人操作统一「示教模式」；「教学模式」容易被当成培训/演示功能，混淆实际控制模式 |
| 回零 | 归零、home | 机器人/数控设备坐标系复位统一「回零」；「归零」多用于计数器清零场景，两者含义不同 |
| 末端执行器 | 夹爪（泛指时）、end effector | 泛指机器人末端工具时统一「末端执行器」；「夹爪」只在确实是夹持类工具时使用，不能用来统称吸盘、焊枪等其他末端工具 |
| 诊断故障码 | DTC、error code | 汽车电子/设备诊断场景统一「诊断故障码」，括号内可注 `DTC`；操作员界面不单独出现裸的 "DTC" 缩写 |
| 充电中 | 充电、正在充电 | 电动车/充电桩状态词统一「充电中」，和「运行」区分开，不用「正在充电」这种冗余表达 |
| 已充满 | 充电完成、满电 | 统一「已充满」；「充电完成」容易和「充电已停止（未充满就中断）」混淆 |
| 荷电状态 | SOC、剩余电量 | 面向工程师/专业视图可标注「荷电状态（SOC）」；面向车主/业主的用户视图统一换算成百分比，不单独出现裸的 "SOC" |
| 报警一览 | 报警列表、报警汇总 | DCS/SCADA 场景统一「报警一览」作为查看全部当前报警的入口名；「报警列表」「报警汇总」属于同义词重复，二选一进术语表 |
| 上位机 | 主机、工程师站（泛指时） | 「上位机」指负责监控/操作的计算机层，和「下位机」（PLC/控制器）相对，两者成对使用，不单独替换一边 |
| 下位机 | 控制器（泛指时）、从机 | 和「上位机」成对使用；只有确实需要强调主从通信关系时才用「从机」 |
| 停电 | 断电、拉闸（对外通知场景） | 电网/用户侧通知统一「停电」；「拉闸」是行业操作术语，不进面向用户的通知文案 |
| 复电 | 送电、恢复供电 | 统一「复电」，和「停电」对称；「恢复供电」可用于说明性长句，不进状态标签 |
| 过压 / 欠压 / 过流 | 电压高 / 电压低 / 电流大 | 电气类报警统一用「过压 / 欠压 / 过流」这组工程术语，不用口语化的「高/低/大」去描述同一类越限 |
| 定检 | 定期检查、年检（混用时） | 按计划周期开展的检查统一「定检」；「年检」只在周期确实是一年时使用，不能泛指所有周期性检查 |
| 跳闸 | 断路、trip | 保护动作导致断路器跳开统一「跳闸」；「断路」是现象描述，不能替代「跳闸」这个有明确工程含义的动作词 |
| 泄漏 | 漏点、泄露 | 介质泄漏统一「泄漏」；「泄露」是错别字写法（泄露多用于信息/隐私场景），两个词形近但场景不同，不能混用 |
| 合闸 | 送电（断路器操作场景）、closing | 断路器闭合动作统一「合闸」，和「跳闸」对称；「送电」留给面向用户的复电通知 |

## 5. 按元素写

- **按钮**：执行类动作（启动、停止、急停、复位、下发参数）按钮文字就是动作本身，不加「确定」「执行」；需要二次确认的，确认框里的按钮重复「动作 + 对象」。
  中：「复位 2 号急停」而不是「确定」。
  英：`Reset E-stop 2` not `OK`.
- **表单标签和校验**：数值输入必须带单位和量程提示；校验给出允许范围，不说「格式不对」。
  中：「转速超出量程（0–3000 r/min）。」
  英：`Speed is outside range (0–3000 r/min).`
- **报错**：先分清两类。数据报错（通讯中断、点位无效、服务不可用）按 `principles.md` 的通用报错句式（问题 + 下一步）；工艺报警（超限、设备异常）必须走第 6 节的报警结构，不能用「保存失败，请重试」这类通用句式去套工艺报警。
  中（数据报错）：「3 号线数据中断，重新连接后自动恢复；10 分钟未恢复请联系工程师。」
  英：`Line 3 data lost. Reconnects automatically; contact engineering if not restored in 10 min.`
- **空状态**：「当前无报警」「暂无在线设备」是状态播报，不必须带号召性动作；由筛选条件导致的「无符合条件的报警」要给出具体下一步。
  中：「当前无报警。」/「无符合条件的报警，清除筛选条件后重试。」
  英：`No active alarms.` / `No alarms match this filter. Clear filters and try again.`
- **确认框**：对执行机构的确认必须包含动作对象、当前联锁/安全状态、不可逆后果（如适用），不写「确定要启动吗？」。例句见第 7 节。
- **状态标签**：固定五态「运行 / 停机 / 待机 / 故障 / 维护」。「离线」是通信状态，不是这五态之一，不能和「故障」共用同一视觉样式，否则操作员分不清是设备坏了还是通信丢了。
  中：运行 / 停机 / 待机 / 故障 / 维护 / 离线（单列一类）。
  英：`Running` / `Stopped` / `Standby` / `Fault` / `Maintenance` / `Offline`.
- **通知 / 推送**：报警推送标题必须带位号和优先级，不写「设备异常提醒」这类笼统标题。
  中：「【二级】3 号反应釜温度超限」。
  英：`[Priority 2] Reactor 3 temperature over limit`
- **进度**：下发参数、固件升级类进度显示到具体步骤，不是单纯的百分比空转；中断后必须明确当前状态是否已生效。
  中：「正在校验参数…」「正在写入 PLC-07…」「中断：参数未生效，设备仍使用原参数运行。」
  英：`Validating parameters…` / `Writing to PLC-07…` / `Interrupted: parameters not applied, device still running on previous values.`
- **引导 / 首次使用**：操作员经过培训上岗，HMI/SCADA 主界面不做新手引导浮层；说明内容放进独立的「帮助」入口，不用弹窗打断操作流程。
- **帮助说明**：按 ASD-STE100 的思路写——一步一个动作，祈使句，一个概念只用一个词，不轮换同义词。英文一句不超过约 20 词（操作步骤）或 25 词（说明性文字）；中文建议每句不超过约 20 字，比 `principles.md` 默认的 30 字更短，照顾现场/戴手套场景下的快速阅读。
  中：「1. 按下复位键。2. 确认指示灯变绿。3. 按下启动键。」（一句一个动作，不用「然后」「接着」连接）
  英：`1. Press Reset. 2. Confirm the indicator turns green. 3. Press Start.`
- **操作说明文档结构（IEC 82079-1:2019，使用说明编制要求）**：步骤编号、每步一个动作、动词开头的祈使句、必要的安全提示放在对应步骤前面而不是文档开头统一堆砌。违反这一条最常见的坏写法是把三个动作写进一步：「打开面板，拔下连接器，并检查接触点」要拆成三步分别编号。
- **按受众分层**：具体规则见第 2 节「操作员 / 工程师 / 管理者」。

## 6. 合规和硬约束

- **报警结构（ANSI/ISA-18.2-2016、IEC 62682）**：每条报警的梳理记录最少包含位号、描述、优先级、原因、后果、处理措施、响应时限；界面上至少显示位号、描述、优先级、处理建议，不能只显示一句笼统描述。
- **报警优先级级数**：不超过 3–4 级。常见命名二选一并全站统一，不能混用：
  - 中文化工行业常见三级：一级（紧急）/ 二级（重要）/ 三级（一般），参照团体标准《化工企业工艺报警管理实施指南》T/CCSAS 012—2022 附录 A.4：一级报警设定数量不宜超过报警总数的 5%，二级不宜超过 15%（<https://www.chemicalsafety.org.cn/storage/58/f6ab2aaba483f5629bf2aa9c05a67d.pdf>，该链接为报批稿）。
  - 国际常见四级：Critical / High / Medium / Low。
  - 不能一个界面里「紧急」对应另一处「Critical」却没有固定的中英对照表。
- **信号词（ANSI Z535.4-2011(R2017)、ISO 3864-2:2016）**：DANGER（红底白字）表示不避免会致命或重伤；WARNING（橙底黑字）表示不避免可能致命或重伤；CAUTION（黄底黑字）表示不避免可能造成轻中度伤害；NOTICE（无信号三角、斜体无衬线大写）表示和人身伤害无关的提示。四个词全部大写、无衬线字体，不与正文混排成普通句子。
  - **中文对照是个坑**：GB 2894-2025 的安全色体系是「黄=警告、红=禁止、蓝=指令、绿=提示」，这是标志类型的四分法，和 Z535.4 的「危险/警告/注意/须知」四级伤害严重度不是同一套分类逻辑，不能逐字机械对译。中文信号词的出处是 GB/T 2893.2—2020《图形符号 安全色和安全标志 第2部分：产品安全标签的设计原则》（修改采用 ISO 3864-2:2016），其 3.6 条规定警示语只有「危险」「警告」「注意」三种，分别对应 DANGER / WARNING / CAUTION（3.6 原文："警示语 signal word 用于使产品安全标签吸引注意并标明风险类别的词语。注：警示语包括“危险”“警告”“注意”三种。"见第三方全文转载 <http://www.gongliff.cn/anquanbz/1878.html>，英译本预览 <https://www.chinesestandard.net/PDF.aspx/GBT2893.2-2020> 同条作 "Danger", "Warning", "Caution"；国标全文公开系统为图片阅读器，未直接比对）。「NOTICE」在这套国标里没有对应的警示语，它说的又是和人身伤害无关的事，所以不能借用「注意」，改用「说明」「须知」这类不带危险等级的提示词。
  - **GB/T 15566 不是信号词标准**：GB/T 15566 系列是《公共信息导向系统 设置原则与要求》，管的是公共场所指引标志的设置规则，不是设备安全信号词的出处；危险/警告/注意三级警示语的国标依据是上面的 GB/T 2893.2，写规范文档时不要把 GB/T 15566 或 GB 2894 错引成信号词的依据。
- **设备诊断状态（NAMUR NE 107）**：Failure（故障，测量不可信）、Function Check（功能检查，如强制输出做回路测试时的信号暂时无效）、Out of Specification（超出规范，工艺条件超出设备设计范围）、Maintenance Required（需要维护，设备仍可用但接近寿命终点）。四类用标准化图标和颜色跨厂商保持一致（<https://www.endress.com/en/support-overview/learning-center/namur-ne-107>）；中文译名各家不一（如 Maintenance Required 有「需要维护」「维修请求」等译法，Function Check 也有译作「功能监测」的），项目内部要在术语表里固定一套，不要四个类别各厂商各翻一次。
- **单位和精度（GB 3100-1993、GB 3101-1993、GB 3102 系列）**：数值与单位符号之间按国标规则应留空格，如 `23 °C` 而不是贴在一起；中文工程界面常把「℃」当全角字符处理、不留空格写成 `23℃`，这是工程习惯写法，和正式国标写法不同，项目内二选一，不要在同一界面里空格和不空格混用。小数位数由仪表量程和精度决定，不能因为「好看」统一截断或补零。
- **时间戳和时区**：24 小时制；跨时区装置或云端平台必须显式标注时区或写明「当地时间」，不能让操作员靠猜。
- **交接班记录**：只写可核实条目——在岗人员、未结报警（位号 + 优先级）、遗留操作、设备状态异常项，不写评价性总结句（「一切正常」「比较顺利」这类话不算记录）。
- **操作留痕**：旁路联锁、强制复位、修改整定值这类高风险操作必须记录操作人和时间，界面上长期可见，不能只显示操作结果不显示是谁做的。
- **多厂区本地化**：跨厂区/跨国平台的厂区、产线、设备名用统一的厂区代码体系（如项目约定的厂区简称），不对厂区名做机器翻译式的临时意译；同一台设备在不同语言界面下的位号编号必须一致，不能因为换了语言就换了编号格式。
- **不许出现的话**：不能用「完全安全」「绝对不会」这类绝对化安全承诺；报警文本里不能放猜测性因果（「可能是传感器问题」）去替代报警本身的客观描述，诊断结论是工程师另外做的事。

## 7. 高风险场景

- **急停复位**：要素——动作对象、现场人员是否已确认撤离、急停按钮是否已释放。
  中：「复位 2 号线急停。确认现场人员已撤离，且急停按钮已释放。」按钮：「复位」/「取消」
  英：`Reset E-stop on Line 2. Confirm personnel are clear and the E-stop button is released.` Buttons: `Reset` / `Cancel`
- **启动被联锁阻塞**：不能只把按钮置灰，要列出具体阻塞原因。
  中：「无法启动：安全门未关闭，3 号联锁未解除。」
  英：`Cannot start: safety door open, interlock 3 not cleared.`
- **下发参数会覆盖在用值**：要素——目标设备、是否停产、是否可撤回。
  中：「将下发新参数到 PLC-07，当前生产不会停止。下发后立即生效，无法撤回。」
  英：`Parameters will be sent to PLC-07 now. Production will not stop. Changes take effect immediately and cannot be undone.`
- **报警确认 ≠ 报警消除**：确认只代表操作员已知晓，不代表异常已解决，两个状态分开显示。
  中：「已确认，报警条件仍存在。」
  英：`Acknowledged. Condition still active.`
- **旁路联锁（高风险）**：必须注明操作人、时间、预计恢复时间，并在界面长期可见「旁路中」标签。
  中：「联锁 L-12 旁路中，由 王伟 于 10-16 08:20 设置，预计 12:00 恢复。」
  英：`Interlock L-12 bypassed by Wang Wei at 08:20 on 10-16, scheduled to restore at 12:00.`
- **安全标牌文字**：按 ISO 3864-2 / Z535.4，要素是信号词 + 危害 + 后果 + 规避方法四件齐全，不能只写一个孤立的信号词。
  中：「警告：表面高温，接触可能烫伤。」
  英：`WARNING: Hot surface. Contact may cause burns.`
- **机器人切换为手动/示教模式**：要素——当前自动程序是否已暂停、操作人员是否已进入防护区域内的安全规程。
  中：「切换到示教模式将暂停当前自动程序。确认已按安全规程进入防护区域。」按钮：「切换」/「取消」
  英：`Switching to teach mode pauses the current automatic program. Confirm you have followed the safety procedure to enter the guarded area.` Buttons: `Switch` / `Cancel`
- **清除诊断故障码（DTC）**：要素——清除后原始故障记录是否可追溯、是否会影响保修/质保判定。
  中：「清除故障码 P0301 后将无法查看原始触发记录，仅保留清除时间和操作人。」按钮：「清除」/「取消」
  英：`Clearing DTC P0301 removes the original trigger record. Only the clear time and operator are kept.` Buttons: `Clear` / `Cancel`
- **启动充电（电动车/充电桩）**：要素——枪头是否已确认连接、当前电价/时段（如适用）、预计完成时间。
  中：「开始充电。充电枪已连接，预计 14:30 充满。」
  英：`Start charging. Connector confirmed, estimated full charge at 14:30.`
- **停电计划通知（面向用户）**：要素——停电范围、起止时间、是否可提前恢复。
  中：「10 月 18 日 09:00–12:00 计划停电，影响 3 号片区，提前恢复供电将另行通知。」
  英：`Scheduled power outage 09:00–12:00 on Oct 18, affecting Zone 3. Early restoration will be announced separately.`
- **修改安全相关整定值**：要素——旧值、新值、该整定值关联的保护功能，防止把普通参数修改和安全联锁整定值的修改用同一套轻量确认框处理。
  中：「修改联锁整定值 TSH-301：由 85 °C 改为 90 °C。该整定值关联高温联锁跳车保护，确认前请核实工艺条件。」按钮：「确认修改」/「取消」
  英：`Changing interlock setpoint TSH-301: 85 °C to 90 °C. This setpoint drives the high-temperature trip interlock. Verify process conditions before confirming.` Buttons: `Confirm change` / `Cancel`

## 8. 这个行业的 AI 腔和坏写法

| 坏写法 | 例子 | 改法 |
|---|---|---|
| 把报警写成客服语气 | 「抱歉，检测到设备出现了一些小问题」 | 「3 号电机过载，立即检查负载。」 |
| 用营销词修饰状态 | 「设备正在为您高效运行中」 | 「运行」 |
| 把猜测性因果当报警文本 | 「可能是传感器松动导致的异常」 | 报警只写现象，诊断结论不写进报警文本 |
| 把联锁等待写成哄小孩语气 | 「再等一下下就可以启动啦」 | 「等待联锁条件满足。」 |
| 确认框写成反问、不给依据 | 「确定要急停吗？」 | 给出对象和后果，见第 7 节例句 |
| 用感叹号堆叠渲染紧急感 | 「报警！！！请立即处理！」 | 优先级和颜色已表达紧急程度，文字不堆感叹号 |
| 用 emoji 表示设备状态 | 「✅ 运行中」 | 纯文字状态词，emoji 不进状态标签 |
| 向操作员解释内部实现 | 「系统正在轮询 PLC 获取最新状态」 | 「数据更新中」或直接显示新数值 |
| 用绝对化安全用语担保 | 「该操作完全安全」 | 删除，不做没有依据的担保 |
| 把工程数值写成模糊感受 | 「温度有点高」 | 「温度 86 °C，超过报警阈值 80 °C」 |
| 把安全相关整定值改动写得和普通设置一样轻 | 「设置已更新」 | 「联锁整定值 TSH-301 由 85 °C 改为 90 °C，操作人：王伟，10-16 09:12」 |
| 中英状态词随意夹杂 | 「设备 Standby 中，随时可以 Running」 | 「待机中，可随时启动。」 |
| 把交接班写成叙事体总结 | 「这一班总体比较顺利，没什么大问题」 | 列出未结报警数、遗留操作、异常项清单 |
| 把充电/电量状态写成卖萌提醒 | 「电量要见底啦，记得给我充电哦」 | 「剩余电量 12%，预计可用 18 公里。」 |
| 把示教/手动模式切换写成随意口语 | 「已经切到手动啦，可以自己操作咯」 | 「已切换到示教模式，自动程序已暂停。」 |
| 同一状态在不同屏幕用不同词 | 产线大屏写「运行中」，设备详情页写「正在运行」 | 全站统一成一个固定词（本文件第 4 节建议「运行」），同一状态只有一种写法 |
| 把跳闸/合闸写成「开关坏了」这类口语猜测 | 「2 号开关好像坏了」 | 「2 号断路器已跳闸，保护动作：过流 II 段。」——写实际发生的动作和触发的保护，不猜测设备好坏 |
| 把量纲/单位写错导致数值失真 | 「流量 120」（不写单位） | 「流量 120 m³/h」——数值脱离单位在工业场景是不完整信息，不是风格问题而是读错会出事 |
| 把多语言厂区名随手意译 | 「二号蒸汽车间」在英文版写成 "Steam Workshop No. 2" | 按项目统一的厂区代码体系命名，如 `Plant-02-Steam`，不临时意译，否则两份语言版本对不上同一个物理位置 |
| 把安全提示统一堆在文档开头 | 「注意事项：以下所有步骤都要戴防护手套、远离高压区、确认断电」 | 按 IEC 82079-1 把安全提示拆到对应步骤前面，不整段堆在文档开头让人读到后面就忘了 |

## 9. 改前 → 改后

以下为教学用的构造示例，用来演示第 5–7 节规则，不是逐字引用某家产品的真实文案。

| 改前 | 改后 | 问题 |
|---|---|---|
| 设备出现异常啦，请及时查看哦～ | 3 号搅拌机故障，检查电机过载保护。 | 卖萌语气加波浪号；缺具体对象和处理动作 |
| Oops, something's wrong with the mixer! | Mixer 3 fault. Check motor overload protection. | 同上，工业场景不用感叹号和口语叹词 |
| 确定要启动吗？ | 启动 1 号输送带。联锁已满足，无故障记录。（按钮：启动 / 取消） | 反问式确认不给判断依据，没说清联锁和故障状态 |
| Are you sure you want to start? | Start conveyor 1. Interlocks satisfied, no active faults. | 同上 |
| 参数已下发 | 参数已下发至 PLC-07，10:42:15 生效。 | 缺目标设备和生效时间，无法用于追溯 |
| Parameters sent. | Parameters sent to PLC-07, effective 10:42:15. | 同上 |
| 报警：温度异常 | 【二级】3 号反应釜温度 86 °C，超过上限 80 °C，检查冷却水流量。 | 缺位号、数值、阈值、处理建议，不满足 ISA-18.2 报警结构 |
| Alarm: Temperature abnormal | [Priority 2] Reactor 3 temperature 86 °C exceeds limit 80 °C. Check cooling water flow. | 同上 |
| 操作成功 | 急停已复位。 | 反馈不具体，工业操作必须点名是哪个动作完成 |
| 当前无数据 | 3 号线通信中断，上次更新 08:12。 | 把通信故障和正常空状态混为一谈，操作员会误判为没有异常 |
| 该操作不可逆，请谨慎操作！ | 旁路联锁 L-12 后，安全联锁将不再生效，需人工监控至 12:00 恢复。 | 「请谨慎」是空话，必须写清不可逆的具体内容和需要的后续动作 |
| 维护人员小哥正在处理中～ | 工单 WO-2031 处理中，指派给维修组，预计 14:00 完成。 | 拟人化称呼不合适；必须给工单号和可核实的时间 |
| 42.3℃左右 | 42.3 °C | 工程数值不能加模糊词「左右」，精度由仪表决定，界面如实显示 |
| 注意：设备可能过热 | 警告：表面高温，接触可能烫伤。 | 信号词和风险等级不匹配——烫伤风险应为「警告」级而不是习惯性都写「注意」 |
| 本批次交接一切正常 | 交接时：2 条二级报警未消（位号 T-301、P-205），3 号联锁处于旁路中，无遗留操作。 | 交接班记录必须列可核实条目，不能用「一切正常」做总结 |
| Everything was fine this shift. | At handover: 2 active Priority-2 alarms (T-301, P-205); interlock 3 bypassed; no open actions. | 同上 |
| 电量要见底啦，记得给我充电哦 | 剩余电量 12%，预计可用 18 公里。 | 拟人卖萌语气；必须给具体电量和可用里程这类可核实数值 |
| Battery's getting low, better charge me soon! | Battery 12%, estimated range 18 km. | 同上 |
| 切换到手动模式，可以自己操作啦 | 已切换到示教模式，自动程序已暂停。确认已按安全规程进入防护区域。 | 缺少「自动程序已暂停」「进入防护区域前确认安全规程」这类人身安全相关前置条件 |
| Switched to manual, go ahead and control it yourself! | Switched to teach mode, automatic program paused. Confirm you have followed the safety procedure before entering the guarded area. | 同上 |
| 您所在片区即将进行线路维护，请注意 | 10 月 18 日 09:00–12:00 计划停电，影响 3 号片区，提前恢复供电将另行通知。 | 缺具体时间范围和影响范围，「请注意」不是可操作的信息 |
| Your area will undergo line maintenance soon, please be aware | Scheduled power outage 09:00–12:00 on Oct 18, affecting Zone 3. Early restoration will be announced separately. | 同上 |
| 设置已更新 | 联锁整定值 TSH-301 由 85 °C 改为 90 °C，关联高温联锁跳车保护，操作人：王伟，10-16 09:12。 | 安全相关整定值的改动不能用通用的「设置已更新」一笔带过，要带旧值、新值、关联保护和操作人 |
| Settings updated | Interlock setpoint TSH-301 changed from 85 °C to 90 °C (drives the high-temperature trip interlock). Changed by Wang Wei, 09:12 on 10-16. | 同上 |
| Siemens iX 官方原文："Something happened." / "An error occurred." | "Failed to upload file due to connection error."（原文引用，出处见第 3 节 Siemens Industrial Experience） | 官方写作规范点名反对的正是这类空话；工业报警、报错同样要把对象、原因写进句子里，不能停在"发生了错误" |

## 10. 审查时加查的项

- [ ] 报警文本是否带位号、描述、优先级，处理建议是否存在（界面是否显示按项目约定，但系统内部要有记录）
- [ ] 设备状态标签是否用了固定五态（运行/停机/待机/故障/维护），没有发明新词或中英夹杂
- [ ] 涉及联锁/执行机构的确认框是否列出了对象 + 联锁状态 + 后果，不是裸的「确定吗？」
- [ ] 数值是否都带单位，精度是否和点位定义一致，没有用「左右」「大概」代替具体数值
- [ ] 信号词（危险/警告/注意，或 DANGER/WARNING/CAUTION/NOTICE）是否和实际风险等级匹配，不是习惯性统一用一个词
- [ ] 旁路、强制复位等高风险操作是否留痕（操作人 + 时间）并在界面保持可见，直到状态恢复
- [ ] 交接班/值班日志类文本是否只写可核实条目，没有「一切正常」这类评价性总结句
- [ ] 时间戳是否带时区或明确本地时间，跨时区场景是否说明
- [ ] 中文状态词/术语是否和第 4 节或项目 `docs/copy-glossary.md` 一致，没有新旧词或中英叫法混用
- [ ] 操作员/工程师/管理者三层界面对同一个点位的描述详略是否分层正确，没有把工程师才需要的内部编号塞进操作员界面
- [ ] 报警横幅、状态条这类短文本是否超出现场可读性建议长度（中文约 12–16 字、英文约 40 字符一行），全大写是否只用于英文信号词
- [ ] 操作说明/步骤文字是否一步一个动作、按顺序编号，没有把多个动作压进一步，也没有把安全提示整段堆在文档开头
- [ ] 同一个设备状态或术语在不同屏幕（大屏、详情页、报表、移动端）是否用了完全一致的词，没有「运行中」和「正在运行」这类同义变体并存
- [ ] 安全相关整定值（联锁、跳车保护阈值）的修改记录是否带旧值、新值、关联保护功能和操作人，没有被当成普通参数改动一笔带过
- [ ] 跳闸、过压、过流这类电气类报警是否用了固定的工程术语，没有被改写成「好像坏了」「电压有点不对」这类口语猜测

## 11. 台港市场差异

- 台湾：
  - 危害性化学品标示要以中文为主。警示语按分类用「危險」或「警告」，并附危害图式、危害警告讯息、危害防范措施（《危害性化學品標示及通識規則》第 5 条）。
  - HMI 里显示化学品危害时，用这两个法定警示语，不要另造「高危」「注意危险」。<https://law.moj.gov.tw/LawClass/LawSingle.aspx?pcode=N0060054&flno=5>
- 台湾安全标志：CNS 9328《圖形符號－安全顏色及安全標誌－第1部：安全標誌及安全標示之設計原則》参照 ISO 3864-1:2011 制定，现行版本公告日期 103/12/18（2014 年 12 月 18 日），经经济部标准检验局「国家标准(CNS)网路服务系统」核实。<https://www.cnsonline.com.tw/?node=result&generalno=9328&locale=zh_TW> DANGER／WARNING／CAUTION 三级在台湾通行写「危險／警告／注意」，与第 6 节的说明一致。
- 香港：没有找到专门规定 HMI 或设备标示具体文字/图形的法规。《工廠及工業經營條例》（Cap. 59）及其附属规例对原动机、传动机械的危险部分有「须有效防护」等要求，职业安全一般义务另见《職業安全及健康條例》（Cap. 509），但两者都没有像大陆 GB 2894 那样强制规定标志的具体文字、颜色、形状绑定。<https://www.labour.gov.hk/tc/legislat/content3.htm>、<https://www.elegislation.gov.hk/hk/cap509!zh-Hant-HK>
- 第 6 节引用的 GB 2894、GB 3100 等大陆国标，在台港站换成 CNS 或国际标准（ISO 3864、IEC 62682）。
- 个资：台湾适用《個人資料保護法》（蒐集时依第 8 条告知），香港适用《個人資料（私隱）條例》（Cap. 486），不是大陆《个人信息保护法》。操作留痕记录操作人姓名、工号也算个资。
